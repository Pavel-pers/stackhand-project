# Сценарии плана ↔ тесты (SCENARIOS.md)

Кодовое название сценария связывает e2e-тест с node-isolate тестами, которые в совокупности его образуют: по коду из строки «Сценарий плана:» в readme любого теста здесь находится и e2e, и его разложение по узлам. Файл собирается генератором из `_registry.jsonl` (`scenarios.json` — то же в машинном виде). Один тест может относиться к нескольким кодам.

Коды: `MR-n` — Main-Run, пункт n транскрипта плана 2026-10-27 (буква — подпункт); `IN-n` — Init, пункт n; `X-*` — проверки вне плана (лимиты, несколько серверов, чек-лист, поля записи); `SYS` — системные тесты вне eval-сета.

Порядок звена (`step`) — где тест стоит в цепочке e2e того же кода; по нему node-isolate тесты читаются как разложение e2e:

| Группа | step | Звено |
|---|---|---|
| main | 1 | оркестратор: выбор сервера и запрос агенту (`delegate`) |
| main | 2 | агент: выбор ручки и параметров или эскалация |
| main | 3 | агент: ответ по сводке или обработка ошибки ручки |
| main | 5 | оркестратор: ответ, вопрос или отказ пользователю по ответу агента |
| init | 1 | инспектор: осмотр, вопрос или сдача артефакта |
| init | 2 | куратор: поля, конфликт, обработка ответа, замечания |
| init | 3 | куратор: случай без вопроса (пара к такту «вопрос») |
| любая | 9 | проба после добавления — рабочий запрос по новому серверу |

Без `step` — тест не раскладывает конкретную цепочку (узловой случай, лимиты, чек-лист).

## Чтение таблицы

- e2e-тест кода проверяет цепочку целиком; node-isolate тесты того же кода — её звенья на фикстурах (по `step`). Разрыв e2e локализуется прогоном узловых тестов того же кода.
- Коды «только node-isolate» (MR-2b, MR-4, MR-5c, MR-7a, MR-7b, MR-8a) — по транскрипту плана e2e для них снят или не нужен; столбец e2e пуст намеренно.
- Тесты без кода — узловые случаи вне плана (например, `orchestrator/answered/02`, `curator/consistent/02`): в readme у них нет строки «Сценарий плана:».
- Как механизм можно улучшить — README, раздел «E2E и node-isolate: коды сценариев».
