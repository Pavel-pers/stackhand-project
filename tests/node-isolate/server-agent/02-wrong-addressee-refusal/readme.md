# server-agent/02 — вопрос не по адресу

## Сценарий

Оркестратор ставит агенту srv-1c задачу про задание импорта прайса на сайт. Шаблон «планировщик» в каталоге есть, но такого задания на srv-1c нет: в его планировщике только ночной pg_dump. Агент должен отказать со статусом wrong-addressee — не no-template: шаблон есть, нет объекта на этом хосте.

## Контекст агента srv-1c (backend)

Ubuntu 22.04.4, 8 CPU, 32 ГБ. Диски: / (sda2, 98 ГБ), /var/lib/postgresql (sdb1, 492 ГБ), /backup (sdc1, 980 ГБ).
Службы: srv1cv8-8.3.24.1548 (порты 1540, 1541, 1560–1591), postgresql@16-main (5432), apache2 — публикация 1С для обмена (8080), ssh (22).
Логи: /var/log/auth.log, /var/log/syslog, /var/log/postgresql/postgresql-16-main.log, технологический журнал 1С в /var/log/1c.
Планировщик: pg_dump ночью, `0 2 * * * /usr/local/bin/backup_1c.sh` → /backup/pg. Доступ: evalbot по SSH, ограниченный sudo (df, du, journalctl, systemctl status, cat auth.log).
Чего на хосте нет: wireguard, nginx, docker.

## Каталог шаблонов (выдержка, Linux)

inventory — инвентаризация и паспорт; resources-now — ресурсы сейчас; disk-usage — диски и прогноз заполнения
(df по томам, du топ папок, рост по сборщику, дата заполнения); services-status — статус служб; log-errors — ошибки
журналов (journalctl -p err, grep по пути); auth-events — входы и неудачные входы (auth.log, lastb); accounts-access —
учётки с доступом; backup-freshness — свежесть бэкапов; certs — сертификаты; scheduler — планировщик (задания cron и
systemd-таймеры, последние запуски, код результата, журнал задания). Все — только чтение; шаблон выбирает агент,
параметры проверяются по схеме до запуска.

## Вход

Задача от оркестратора агенту srv-1c: «Проверь, когда последний раз отработало задание импорта прайса на сайт и с каким результатом». Исходный запрос пользователя: «прайс на сайте вчерашний — выгрузка из 1С отработала?».
## Ожидаемое поведение

- Тип ответа `wrong-addressee`, шаблон не выбран.
- Причина: задания импорта прайса на srv-1c нет, в планировщике только `0 2 * * * backup_1c.sh`.
- Задача не выполнена «приблизительно» (отчёт про pg_dump вместо импорта); на другой хост агент не указывает — чужих контекстов у него нет, адресата меняет оркестратор.
- Ошибки: отчёт о ночном бэкапе как об импорте прайса; статус no-template вместо wrong-addressee; «задание отработало» без задания.

## Метрики

- Rule-based: `agent-refusal-correct`.
- LLM-judge: `judge-A-context-answer` — отказ опирается на собственный планировщик агента, без подмены задачи.

## Данные

Контекст агента (как в блоке выше), выдержка каталога шаблонов, задача от оркестратора, рубрика judge.
