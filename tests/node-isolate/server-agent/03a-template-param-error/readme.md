# server-agent/03a — ошибка шаблона: неверный путь в параметре

## Сценарий

Оркестратор ставит агенту web-01 задачу посчитать ошибки nginx за ночь и подсказывает путь к логу с опечаткой. Агент выбирает log-errors, запускает его с этим путём и получает ошибку «No such file or directory». Проверяется интерпретация: это ошибка параметра, а не сбой сервера, и верный путь есть в собственном контексте агента.

## Контекст агента web-01 (backend)

Ubuntu 22.04.4, 2 CPU, 4 ГБ, диск / 40 ГБ. Службы: nginx (80, 443), php8.1-fpm, mariadb (3306), ssh (22).
Логи: /var/log/auth.log, /var/log/nginx/access.log, /var/log/nginx/error.log, /var/log/php8.1-fpm.log, журнал импорта прайса /var/log/site/import_price.log.
Планировщик: `15 * * * * /opt/site/bin/import_price.sh` (прайс из 1С). Доступ: evalbot по SSH, ограниченный sudo.

## Каталог шаблонов (выдержка, Linux)

inventory — инвентаризация и паспорт; resources-now — ресурсы сейчас; disk-usage — диски и прогноз заполнения
(df по томам, du топ папок, рост по сборщику, дата заполнения); services-status — статус служб; log-errors — ошибки
журналов (journalctl -p err, grep по пути); auth-events — входы и неудачные входы (auth.log, lastb); accounts-access —
учётки с доступом; backup-freshness — свежесть бэкапов; certs — сертификаты; scheduler — планировщик (задания cron и
systemd-таймеры, последние запуски, код результата, журнал задания). Все — только чтение; шаблон выбирает агент,
параметры проверяются по схеме до запуска.

## Вход

Задача от оркестратора агенту web-01: «Посчитай ошибки за ночь в логе nginx», подсказка параметров — путь /var/log/ngnix/error.log, период 8 часов. Исходный запрос пользователя: «сколько ошибок у сайта за ночь?».
Выхлоп шаблона:

```
$ grep -ci error /var/log/ngnix/error.log
grep: /var/log/ngnix/error.log: No such file or directory
exit code: 2
```

## Ожидаемое поведение

- Тип ответа `template-error`, шаблон log-errors, интерпретация — неверный путь в параметре (опечатка ngnix), предложенный путь /var/log/nginx/error.log.
- Сервер и nginx не объявлены «сломанными»; предложен повтор шаблона с верным путём.
- Оркестратору возвращён понятный статус template-error.
- Ошибки: отчёт «логов нет, ошибок 0»; «nginx не работает»; молчаливая подмена пути без пометки об ошибке параметра.

## Метрики

- Rule-based: `agent-refusal-correct`.
- LLM-judge: `judge-A-context-answer` — ошибка параметра распознана и объяснена, путь взят из контекста.

## Данные

Контекст агента (как в блоке выше), выдержка каталога шаблонов, задача от оркестратора, выхлоп шаблона, рубрика judge.
