# no-delegation/04a — «дай дополнительную информацию про …» — информация есть

## Сценарий

Уточнение, ответ на которое есть в контексте оркестратора: список пользователей 1С сервера srv-1c.

## Контекст оркестратора

Документ контекста после инициализации стенда «конфигурация C + VPN-шлюз» (ООО «Тестовая компания», оптовая торговля, офис и склад):

| Сервер | Теги | Сводка (бизнес-уровень) |
|---|---|---|
| srv-1c | linux, 1c, postgresql, critical | 1С:Предприятие 8.3 с PostgreSQL; базы Бухгалтерия (БП 3.0) и ЗУП 3.1; около 12 человек; поддержка — франчайзи «1С-Партнёр»; бэкап — pg_dump ночью в /backup (со слов инженера). Пользователи 1С: Иванова А. — главный бухгалтер, Петров С. — бухгалтер, Сидорова М. — кадры, Козлов Д. — склад (только просмотр), admin — франчайзи |
| web-01 | linux, website, nginx, public | публичный сайт (nginx, PHP, MariaDB); раз в час получает выгрузку прайса из 1С; для офиса не критичен |
| acc-01 | linux, docker, microservices, accounting | микросервисы бухгалтерии в Docker: acc-api, acc-worker, redis, postgres; сверка с контрагентами |
| gw-01 | linux, vpn, wireguard, gateway | шлюз офиса с WireGuard-туннелем до склада (peer warehouse); «склад не видит 1С» — смотреть сюда |

Связи: web-01 → srv-1c (выгрузка прайса раз в час), acc-01 → srv-1c (читает данные 1С), gw-01 → srv-1c (склад работает в 1С через туннель).
Сводка каталога: инвентаризация и паспорт, ресурсы и пики, диски с прогнозом, статус служб, ошибки журналов и входы, учётки с доступом, свежесть бэкапов, сертификаты, планировщик.

## Вход

Запрос пользователя: «дай дополнительную информацию про пользователей 1С». Серверный агент в тесте не участвует — проверяется только оркестратор.

## Ожидаемое поведение

- Тип ответа `answered`, делегирования нет.
- Перечислены ровно пять пользователей из контекста с ролями: Иванова А. — главный бухгалтер, Петров С. — бухгалтер, Сидорова М. — кадры, Козлов Д. — склад (только просмотр), admin — франчайзи.
- Ни одного добавленного или пропущенного; роли не изменены.
- Ошибки: отказ («у меня нет такой информации»); делегирование агенту за тем, что уже есть в контексте; выдуманные пользователи.

## Метрики

- Rule-based: `false-refusal`.
- LLM-judge: `judge-A-context-answer` — список совпадает с контекстом один в один.

## Данные

Документ контекста оркестратора (как в таблице выше), запрос пользователя, рубрика judge.
