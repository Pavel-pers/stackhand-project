# response-parse/1b — идеальный ответ агента про импорт прайса на сайт

## Сценарий

Оркестратор получил от агента web-01 эталонный результат шаблона «планировщик» по заданию импорта прайса из 1С. Проверяется перенос: когда импорт отработал последний раз успешно, что происходит с тех пор, и что гипотеза о причине подана как гипотеза.

## Контекст оркестратора

Документ контекста после инициализации стенда «конфигурация C + VPN-шлюз» (ООО «Тестовая компания», оптовая торговля, офис и склад):

| Сервер | Теги | Сводка (бизнес-уровень) |
|---|---|---|
| srv-1c | linux, 1c, postgresql, critical | 1С:Предприятие 8.3 с PostgreSQL; базы Бухгалтерия (БП 3.0) и ЗУП 3.1; около 12 человек; поддержка — франчайзи «1С-Партнёр»; бэкап — pg_dump ночью в /backup (со слов инженера). Пользователи 1С: Иванова А. — главный бухгалтер, Петров С. — бухгалтер, Сидорова М. — кадры, Козлов Д. — склад (только просмотр), admin — франчайзи |
| web-01 | linux, website, nginx, public | публичный сайт (nginx, PHP, MariaDB); раз в час получает выгрузку прайса из 1С; для офиса не критичен |
| acc-01 | linux, docker, microservices, accounting | микросервисы бухгалтерии в Docker: acc-api, acc-worker, redis, postgres; сверка с контрагентами |
| gw-01 | linux, vpn, wireguard, gateway | шлюз офиса с WireGuard-туннелем до склада (peer warehouse); «склад не видит 1С» — смотреть сюда |

Связи: web-01 → srv-1c (выгрузка прайса раз в час), acc-01 → srv-1c (читает данные 1С), gw-01 → srv-1c (склад работает в 1С через туннель).
Сводка каталога: инвентаризация и паспорт, ресурсы и пики, диски с прогнозом, статус служб, ошибки журналов и входы, учётки с доступом, свежесть бэкапов, сертификаты, планировщик.

## Вход

Запрос пользователя: «прайс на сайте вчерашний — выгрузка из 1С отработала?».

Ответ агента web-01 (`executed`, шаблон scheduler, источник — crontab, /var/log/syslog и /var/log/site/import_price.log; проверено 2026-10-05 09:44:30 +03:00):
задание `15 * * * * /opt/site/bin/import_price.sh`; последние пять запусков — 05:15 код 0, 2 с; 06:15 код 0, 2 с; 07:15 код 1, 30 с, «curl: (7) Failed to connect to srv-1c port 8080»; 08:15 код 1, 30 с, та же ошибка; 09:15 код 1, 30 с, та же ошибка. Последний успешный запуск — 2026-10-05 06:15:02.

## Ожидаемое поведение

- Тип ответа `answered`.
- Названы последний успешный запуск (06:15) и три неудачных подряд с 07:15 с кодом 1 и текстом ошибки подключения к srv-1c:8080.
- Вывод «прайс не обновлялся с 06:15» сделан; причина (публикация 1С на srv-1c недоступна) подана как гипотеза, без гарантии; предложен следующий шаг — проверить srv-1c.
- Ошибки: «всё в порядке» при трёх неудачных запусках; причина, поданная как факт («1С упала»); потерянное время последнего успешного запуска; обвинение сайта вместо переноса ошибки.

## Метрики

- Rule-based: `false-refusal`.
- LLM-judge: `judge-B-agent-to-user` — времена и коды точны, факт отделён от гипотезы, есть следующий шаг.

## Данные

Документ контекста оркестратора, запрос пользователя, ответ агента (как в блоке выше), рубрика judge.
