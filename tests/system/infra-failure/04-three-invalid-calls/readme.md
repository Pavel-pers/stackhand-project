# system/infra-failure/04 — три невалидных вызова тулз подряд — системная ошибка

Сценарий плана: **SYS** — Поведение системы, не модели — вне долей eval-сета: удаление сервера [AR-21], закрытие чата (третий ответ, 10 вызовов сверх лимита, третья карточка и deny) [UC-35], «Остановить» [UC-34], системные ошибки [AR-46]. Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Невалидный вызов тулзы — текст в `content` вместо вызова, неизвестная тулза, аргументы не по схеме: система возвращает модели сообщение в формате ошибки аргумента — только первая проблема и, при неверном аргументе, повтор схемы вызова; вызов засчитывается в лимит тулзы; три невалидных вызова подряд — системная ошибка [AR-44], [AR-46] (design doc 4.2 «Невалидный вызов тулзы», 5.4). Модель в тесте — скриптовая заглушка `[предл.]`: по сценарию выдаёт заданную последовательность вызовов тулз, а система — узел исполнения тулз, лимиты, закрытие чата — настоящая. Так проверяются правила системы, которые настоящая модель не воспроизводит надёжно; поведение настоящей модели у тех же лимитов — тесты X-LIM eval-сета (`*/limits/*`, `SCENARIOS.md`).

Варианты: A — оркестратор: текст в `content`, затем `delegate` без `prompt`, затем неизвестная тулза `run_command`; B — два невалидных `delegate` (`server-name` числом; две ошибки сразу — несуществующий сервер и пустой `prompt`), затем валидный `delegate`; C — локальный агент: три вызова ручки с аргументами не по схеме подряд.

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

«Посмотри заполненность дисков на сервере с 1С»; дальше — скрипт по варианту.

## Ожидаемое поведение

- На каждый невалидный вызов модели уходит сообщение об ошибке аргумента: первая проблема (в B при двух ошибках — только первая) и схема вызова; вызов засчитан в лимит своей тулзы (для текста без вызова и неизвестной тулзы — не описано, не проверяется); в журнале — «невалидный вызов» [AR-48].
- A, C: после третьего подряд — «Внутренняя ошибка, попробуйте снова», чат закрыт с пометкой ошибки; SLI — падение.
- B: после валидного `delegate` прогон продолжается штатно до ответа.
- Ошибки: перечень всех ошибок вместо первой; нет схемы при неверном аргументе; невалидный вызов не засчитан в лимит; закрытие не на третьем подряд; в B — закрытие.

## Эталон

- A: невалидных — 3; сессия закрыта, причина — ошибка; счётчик `delegate` = 1 (вызов без `prompt`).
- B: невалидных — 2, затем `delegate` исполнен; счётчик `delegate` = 3; сессия закрывается только штатно.
- C: невалидных — 3; ручек исполнено 0, счётчик ручек = 3; сессия закрыта, причина — ошибка.

## Метрики

- Rule-based `[предл.]`: тексты системных сообщений модели, счётчики, состояние сессии по журналу. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).
