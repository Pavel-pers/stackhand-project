# system/infra-failure/02 — исключение в ручке — системная ошибка; недоступный сервер — нет

Сценарий плана: **SYS** — Поведение системы, не модели — вне долей eval-сета: удаление сервера [AR-21], закрытие чата (третий ответ, 10 вызовов сверх лимита, третья карточка и deny) [UC-35], «Остановить» [UC-34], системные ошибки [AR-46]. Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Граница «падение системы — штатная ошибка ручки» (design doc 2.2, 3.5, 5.4): исключение в коде ручки (дефект реализации, а не ошибка-enum) — системная ошибка: «Внутренняя ошибка», чат закрыт с пометкой [AR-46]; недоступный сервер — обычная ошибка ручки `ssh-refused`: модель эскалирует, пользователь получает ответ о недоступности, и это не падение [AR-25], [AR-42]. Модель — настоящая; оценивается система.

Варианты: A — ручка `host.volumes_usage` подменена версией, бросающей необработанное исключение `[предл.]`; B — srv-1c выключен (как `main/e2e/access-lost/01`).

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — по варианту: подмена ручки (A) или выключенный srv-1c (B); после прогона — сброс.

## Вход

«Посмотри заполненность дисков на сервере с 1С».

## Ожидаемое поведение

- A: после исключения — техническое сообщение «Внутренняя ошибка, попробуйте снова», чат закрыт и в истории с пометкой ошибки; трейс исключения не уходит модели как результат ручки; в журнале — исключение, ручка и шаг; SLI — падение.
- B: 2 попытки подключения с паузой 5 с внутри ручки, ошибка `ssh-refused` агенту, эскалация, ответ оркестратора о недоступности (как `main/e2e/access-lost/01`); чат закрывается только по обычным правилам; SLI — не падение.
- Ошибки: в A модель «объясняет» исключение пользователю или повторяет ручку; в B — «Внутренняя ошибка»; в B больше двух попыток подключения в одной ручке.

## Эталон

- A: сессия закрыта, причина — ошибка; `answer-user` — 0.
- B: `ssh-refused` — 1 (2 попытки); `escalate` → ответ оркестратора по эталону `main/e2e/access-lost/01`; сессия не помечена ошибкой.

## Метрики

- Rule-based `[предл.]`: причина закрытия, число попыток и вызовов по журналу; SLI [D §3.5]: A — падение, B — нет. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).

## Основания
