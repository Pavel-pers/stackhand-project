# system/infra-failure/03 — промпт не помещается в окно: запрос к модели не отправляется

Сценарий плана: **SYS** — Поведение системы, не модели — вне долей eval-сета: удаление сервера [AR-21], закрытие чата (третий ответ, 10 вызовов сверх лимита, третья карточка и deny) [UC-35], «Остановить» [UC-34], системные ошибки [AR-46]. Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Перед каждым вызовом модели система считает токены промпта; если промпт не помещается в окно 64k, запрос не отправляется — системная ошибка, без молчаливой обрезки (design doc 4.2 «Переполнение окна», 4.4; [AR-59], [AR-46]). Чтобы не строить промпт в 64k, окно в конфиге стенда для этого теста уменьшено `[предл.]`: проверяется правило, а не число.

Варианты: A — окно подобрано так, что переполняется первый вызов агента (каталог ручек srv-1c по четырём тегам); B — так, что переполняется вызов агента после результата третьей ручки (рост истории в цикле). Величина окна подбирается по журналу длин промптов.

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Окно контекста в конфиге системы — уменьшенное, по варианту; после прогона — 64k.

## Вход

«Когда за последнюю неделю были пики нагрузки на сервере 1С и что в это время делала 1С?» — запрос, которому нужно несколько ручек.

## Ожидаемое поведение

- На переполняющем вызове запрос к движку не отправлен (в журнале движка вызова нет); пользователь — «Внутренняя ошибка, попробуйте снова»; чат закрыт с пометкой ошибки; в журнале — число токенов, окно и шаг [AR-48]; SLI — падение.
- До переполнения — штатные вызовы (в B — три ручки).
- Ошибки: запрос отправлен с обрезанным промптом; ответ пользователю по неполным данным; чат открыт.

## Эталон

- A: вызовов модели агента — 0; сессия закрыта, причина — ошибка.
- B: вызовов ручек — 3; следующего вызова модели агента нет; сессия закрыта, причина — ошибка.

## Метрики

- Rule-based `[предл.]`: журнал системы и движка. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).

## Основания

[AR-59] — окно 64k, подсчёт токенов, системная ошибка; [AR-46]; [AR-48]; design doc 4.2, 4.4, 5.4. Уменьшенное окно — допущение теста.

## Данные

Стенд M, конфиг с уменьшенным окном по варианту, запрос, эталоны.
