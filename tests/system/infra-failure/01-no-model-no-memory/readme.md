# system/infra-failure/01 — сбой на стороне системы: нет модели, нет памяти о серверах

Сценарий плана: **SYS** — Не метрики модели — вне eval-сета (удаление сервера [AR-21], закрытие чата по лимиту [UC-28], сбой инфраструктуры системы). Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Наследник старого main/e2e/infra-orch/01 (пункт скриншота плана «Infra orch → No memo ← no model»; в транскрипт плана не вошёл). Ломается не сервер, а сама система: недоступна модель или память о серверах. Пользователь должен получить короткий статический ответ без вызова модели [D §5.4], а не зависание, выдуманный ответ или действия на серверах. Модель не оценивается — тест системный.

Варианты: A — недоступно хранилище записей о серверах; B — служба инференса остановлена; C — модель не загружена («model not found»); D — памяти GPU не хватает (видеопамять занята посторонним процессом).

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — по варианту, на хранилище системы (A) или машине инференса (B–D); после прогона — восстановление.

## Вход

Запрос «Посмотри заполненность дисков на сервере с 1С» в состоянии сбоя; тот же запрос после восстановления в новой сессии.

## Ожидаемое поведение

- В сбое: статический ответ за ограниченное время — система временно не может ответить, повторите позже `[предл.]`; `delegate` и ручек — 0; на серверах ничего не происходит; в варианте A система не отвечает «у вас нет серверов»; сбой записан в журнал `[предл.]`.
- После восстановления: штатная цепочка как в `main/e2e/info/05` без ручного перезапуска.
- Ошибки: зависание; трейс исключения пользователю; выдуманные числа; сообщение о пустом списке серверов; после восстановления система не отвечает без перезапуска.

## Эталон

- В сбое: статический ответ ≤ 30 с `[предл.]`; `delegate` — 0; ручек — 0.
- После восстановления: `delegate` → srv-1c; `host.volumes_usage`; `answer-user`.

## Метрики

- Rule-based `[предл.]`: статический ответ получен в пределах времени; запусков агентов нет; после восстановления — `e2e-expected-state`. SLI «прогон до конца без падений» [D §3.5]: прогоны в сбое считаются падениями системы. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).

## Основания

[D §5.4] — статический ответ при инфраструктурном сбое; [D §3.5] — SLI; падение инференса и восстановление не обсуждались (`architecture/overview.md`, `llm-inference.md`). Порог 30 с — по бюджету TTFT P95 [D §3.2], переназначение — [Q22].

## Данные

Стенд M, способ воспроизведения сбоя по варианту, запрос, порог времени, эталон после восстановления.
