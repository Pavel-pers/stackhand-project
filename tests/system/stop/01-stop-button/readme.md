# system/stop/01 — кнопка «Остановить»: прогон прерван, чат закрыт

Сценарий плана: **SYS** — Поведение системы, не модели — вне долей eval-сета: удаление сервера [AR-21], закрытие чата (третий ответ, 10 вызовов сверх лимита, третья карточка и deny) [UC-35], «Остановить» [UC-34], системные ошибки [AR-46]. Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Исключение design doc 2.2 «Пользователь нажал «Остановить»»: прогон прерывается, чат закрывается техническим сообщением и уходит в историю чатов [UC-34]; механизм — отмена asyncio-задачи графа [AR-45]. Модель — настоящая; момент нажатия задаётся по журналу.

Варианты: A — рабочий запрос, «Остановить» во время работы агента; B — добавление сервера, «Остановить» во время осмотра инспектором; C — «Остановить» во время ожидания ответа пользователя на вопрос (граф стоит на `interrupt()`).

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Вариант B — стенд I (добавляется srv-1c).

## Вход

A: «Когда за последнюю неделю были пики нагрузки на сервере 1С и что в это время делала 1С?» → «Остановить» после первого вызова ручки агентом. B: Форма «Добавить сервер»: `conn-ip` 10.0.1.12, `conn-user` `evalbot`, `conn-ssh-key` `eval_ed25519`, `description` «Сервер 1С: Бухгалтерия и ЗУП, PostgreSQL, публикация для обмена с сайтом». → «Остановить» после 3-й ручки осмотра. C: «посмотри диски» (сервер не назван) → вопрос оркестратора с вариантами → «Остановить» вместо ответа.

## Ожидаемое поведение

- Прогон прерван: после нажатия новых вызовов модели и ручек нет (уже идущий вызов может завершиться, его результат в чат не выводится); чат закрыт техническим сообщением; чат — в истории чатов, только для чтения; новый чат открывается штатно.
- A: ответа по теме нет; записи о серверах не изменились.
- B: запись о сервере не создана; куратор не вызывался; что с логгерами, если инспектор успел их поставить, — не описано ([Q49]), не проверяется.
- SLI «прогон до конца» [D §3.5]: остановка — не падение; причина закрытия в журнале — остановка [AR-48].
- Ошибки: ответ модели пришёл после остановки; чат остался открытым; вызовы ручек после остановки; сессия помечена как ошибка.

## Эталон

- Вызовов модели и ручек, начатых после нажатия, — 0; время от нажатия до закрытия чата — не больше длительности текущего вызова `[предл.]`; причина закрытия — остановка; в B записи нет.

## Метрики

- Rule-based `[предл.]`: журнал вызовов и состояние сессии. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).
