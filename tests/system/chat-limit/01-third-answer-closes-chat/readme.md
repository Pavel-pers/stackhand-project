# system/chat-limit/01 — третий ответ или отказ закрывает чат

Сценарий плана: **SYS** — Не метрики модели — вне eval-сета (удаление сервера [AR-21], закрытие чата по лимиту [UC-28], сбой инфраструктуры системы). Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Лимит `answer-user` + `reject` ≤ 3 на сессию: когда ответ или отказ исчерпывает лимит, чат закрывается с техническим сообщением [UC-28], [AR-32]. Проверяется поведение системы — закрытие и сообщение, — а не модели; текст технического сообщения не определён [Q60].

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Одна сессия: 1) «посмотри заполненность дисков на сервере с 1С» → ответ; 2) «а на сервере сайта?» → ответ (продолжение сессии с транскриптом [AR-28]); 3) «а на шлюзе?» → третий ответ.

## Ожидаемое поведение

- После третьего `answer-user` чат закрывается с техническим сообщением (не сгенерированным моделью); новые сообщения в эту сессию не принимаются; новая сессия открывается штатно.
- Ошибки: четвёртый запрос обработан в той же сессии; чат закрыт без сообщения; закрыт раньше третьего ответа.

## Эталон

- После 3-го терминального ответа: сессия закрыта; техническое сообщение показано; счётчик `answer-user` + `reject` = 3.

## Метрики

- Rule-based `[предл.]`: состояние сессии по журналу. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).

## Основания

[UC-28], [AR-32]; текст сообщения и поведение при исчерпании остальных лимитов — [Q60]. Что это значит для пользователя (три вопроса на сессию) — в контракте не описано (файл-обращение).

## Данные

Стенд M, три запроса в одной сессии, эталон состояния сессии.
