# system/chat-limit/01 — третий ответ или отказ закрывает чат

Сценарий плана: **SYS** — Поведение системы, не модели — вне долей eval-сета: удаление сервера [AR-21], закрытие чата (третий ответ, 10 вызовов сверх лимита, третья карточка и deny) [UC-35], «Остановить» [UC-34], системные ошибки [AR-46]. Вид теста: системный, вне eval-сета. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Исключение design doc 2.2 «Исчерпан лимит ответов»: `answer-user` + `reject` ≤ 3 на сессию; когда ответ или отказ исчерпывает лимит, чат закрывается техническим сообщением — модель больше не сможет отвечать [UC-28], [AR-32]; сообщение в духе «Лимит исчерпан, попробуйте снова», чат уходит в историю чатов, продолжить — в новом чате [UC-31], [UC-35]. Проверяется поведение системы — закрытие, сообщение, история, — а не модели. Модель — настоящая; её уточнения (`ask-user`) в счётчик не входят: на них отвечает сценарий пользователя, тест ждёт третий ответ или отказ.

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Одна сессия: 1) «посмотри заполненность дисков на сервере с 1С» → ответ; 2) «а на сервере сайта?» → ответ (продолжение сессии с историей [AR-28]); 3) «а на шлюзе?» → третий ответ; 4) «а на сервере бухгалтерии?» — попытка продолжить.

## Ожидаемое поведение

- Третий ответ показан, затем чат закрывается техническим сообщением, которое пишет система, а не модель; поле ввода закрыто — четвёртый запрос в эту сессию не принимается; чат — в истории чатов, только для чтения; новый чат открывается штатно (окно подтверждения нового чата [UC-31]).
- SLI «прогон до конца» [D §3.5]: закрытие по лимиту — не падение.
- Ошибки: четвёртый запрос обработан в той же сессии; чат закрыт без сообщения или сообщение сгенерировала модель; закрыт раньше третьего ответа; чат не попал в историю.

## Эталон

- После 3-го терминального ответа: сессия закрыта, причина закрытия в журнале — лимит [AR-48]; техническое сообщение показано; счётчик `answer-user` + `reject` = 3; чат в истории.

## Метрики

- Rule-based `[предл.]`: состояние сессии по журналу. Тест системный: оценивается состояние системы и стенда по журналу, модель не оценивается; в доли eval-сета не входит (`SCENARIOS.md`, SYS).

## Основания

[UC-28], [AR-32]; [UC-31], [UC-35] — текст сообщения, история чатов, новый чат; [AR-48] — причина закрытия в журнале; design doc 2.1 «Лимиты реплик», 2.2 «Исчерпан лимит ответов». Тексты технических сообщений предварительные — сверяется суть, не дословно.
