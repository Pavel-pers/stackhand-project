# curator/consistent/01 — первый сервер: сравнивать не с чем

Сценарий плана: **IN-2a** — Серверы 1С и сайт — лишние вопросы не заданы (R&B), качество составленной информации о сервере (LLM). Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

В системе ещё нет серверов. Куратор составляет поля по артефакту инспектора; конфликтов быть не может, вопрос «чем отличается» задавать не нужно — сразу `confirmation`.

## Вход

Артефакт инспектора и пустой список кратких описаний.

## Ожидаемое поведение

- `confirmation(short-desc, server-name)` (`consistent`), `QA` не вызван.
- `short-desc` отражает роль: сервер 1С, Бухгалтерия и ЗУП, PostgreSQL; `tags-short-desc` — по четырём тегам; `server-name` — непустое.
- Ошибки: `QA` «чем этот сервер отличается от других»; факты, которых нет в артефакте; `deny`.

## Эталон

- Тулза: `confirmation`.
- `short-desc`: содержит «1С», «Бухгалтери», «ЗУП», «PostgreSQL»; < 50 слов.
- `server-name`: непустое; `tags-short-desc`: 4 непустых записи.

## Метрики

- Rule-based: `cur-conflict` — класс (тулза) совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- Rule-based: `cur-fields` `[предл.]` (X-FIELDS, [AR-29]) — `server-name` непустое, < 5 слов; `short-desc` < 50 слов; `tags-short-desc` — по каждому тегу из `tags` непустое, ≤ 30 слов; подстроки эталона — без учёта регистра (README, «Метрики»).
- LLM-judge: `judge-cur-summary` `[предл.]` — (1) `short-desc` — общие слова о сервере: роль и отличительные признаки из `full-desc` (описание пользователя и находки инспектора), по которым сервер узнают в запросах; точечные факты (порты, версии, пути) — не здесь; (2) в `short-desc` и `tags-short-desc` нет додуманных фактов — всё есть в артефакте инспектора или в ответах пользователя; (3) `tags-short-desc` по каждому тегу — ситуативное: для 1c — пользователи и ИБ, для db — СУБД и базы, для host — ресурсы и что в процессах; (4) `server-name` узнаваемо — роль или имя хоста из `full-desc`; без разговорных оборотов, личных имён и сведений о доступе. Тест засчитан при всех четырёх. В метриках v0.2 такого judge нет — требуется пунктом плана IN-2a (качество составленной информации) (README, открытые пункты).
