# curator/consistent/01 — первый сервер: сравнивать не с чем

## Сценарий

В системе ещё нет серверов. Куратор заполняет название и краткое описание по описанию из формы; конфликтов быть не может, вопрос «чем отличается» задавать не нужно.

## Контекст куратора

Описание из формы для 10.0.1.12: «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; обслуживает франчайзи «1С-Партнёр»; бэкап — pg_dump каждую ночь в /backup/pg; apache публикует данные 1С для обмена с сайтом». Краткие описания других серверов: нет (система пустая).

## Вход

Описание из формы и пустой список кратких описаний.

## Ожидаемое поведение

- Класс `consistent`, вопросов нет.
- Краткое описание отражает роль и отличительные признаки из формы: сервер 1С, базы Бухгалтерия и ЗУП, PostgreSQL; может включать число пользователей, публикацию для обмена с сайтом и ночной бэкап.
- Название заполнено (имя хоста или роль — как формируется, не обсуждалось).
- Ошибки: вопрос «чем этот сервер отличается от других»; факты в кратком описании, которых нет в форме.

## Эталон

- Класс: `consistent`.
- Краткое описание: содержит «1С», «Бухгалтерия», «ЗУП», «PostgreSQL»; без выдуманного.
- Название: не пустое (строго не оценивается).

## Метрики

- Rule-based: `cur-conflict` — класс совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.

## Основания

[UC-15], [K §2.2]. «Работа куратора при первом сервере — очевидно consistent, явно не обсуждалось» (`architecture/curator-agent.md`) — эталон теста следует этому.

## Данные

Описание из формы, пустой список, эталон.
