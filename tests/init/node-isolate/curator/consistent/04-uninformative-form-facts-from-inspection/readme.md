# curator/consistent/04 — описание из формы ничего не говорит, роль видна по осмотру

## Сценарий

Наследник старого init/ask/01 («второй сервер»). Пользователь в форме написал только «второй сервер», но инспектор осмотрел хост и `full-desc` говорит, что это сайт на nginx с MariaDB и импортом прайса. Куратор составляет `short-desc` по находкам инспектора, а не по словам пользователя, и конфликта не поднимает: роль отличает сервер от добавленных.

## Контекст куратора

Артефакт инспектора (`submit`) для 10.0.1.11 [AR-29]:

- `full-desc`: По описанию пользователя: «второй сервер». Сайт example-trade.ru на nginx с PHP и MariaDB на VPS у хостинг-провайдера; раз в час забирает прайс из 1С с сервера 1С. Ubuntu 22.04.4 LTS, 2 vCPU, 4 ГБ ОЗУ. Осмотрен инспектором 2026-10-08. Имя хоста: web-01.
- `tags`: {host, web/nginx, db/mysql, unsupported:provider-hv}
- `tags-full-desc`:
  - host — Ubuntu 22.04.4 LTS; VPS у хостинг-провайдера (KVM); 2 vCPU, 4 ГБ ОЗУ, GPU нет; диск / 40 ГБ. Планировщик: `15 * * * * /opt/site/bin/import_price.sh` (www-data) — забирает прайс с http://10.0.1.12:8080/buh/hs/price; журнал задания /var/log/site/import_price.log. Бэкапы сайта — у хостера, собственного задания нет.
  - web/nginx — nginx 1.18 (порты 80, 443), сайт example-trade.ru в /var/www/site, TLS-сертификат; php8.1-fpm; журналы /var/log/nginx/access.log, error.log. Подрядчик — веб-студия «Пиксель».
  - db/mysql — MariaDB 10.6 (порт 3306, только localhost); база site.
  - unsupported:provider-hv — гипервизор хостинг-провайдера: виден по виртуализации (QEMU/KVM), системой не обслуживается.

Краткие описания уже добавленных серверов (вход куратора [UC-15]; удалённых серверов и «прошлых описаний» нет [UC-10]):

Тулзы куратора [AR-31]: `QA(question)` ≤ 5; `confirmation(short-desc, server-name)` ≤ 3 — карточка показывает ещё и `tags-short-desc` [UC-32], подтверждаются краткое описание и название [UC-21]; третья карточка — последняя: не подтверждена — добавление прерывается, сервер не добавляется; `deny(reason)` — терминальная: отказ пользователю, чат закрывается, сервер не добавляется; после 5 QA — только confirmation и deny [AR-43], [UC-35]. ## Вход

Артефакт инспектора и краткие описания трёх серверов.

## Ожидаемое поведение

- `confirmation` (`consistent`) `[предл.]`: `short-desc` — сайт компании (example-trade.ru) на nginx, PHP, MariaDB у хостинг-провайдера; забирает прайс из 1С.
- «Второй сервер» в `short-desc` не попадает как роль; `server-name` — «web-01» или «Сайт компании».
- Ошибки: `short-desc` «второй сервер»; `QA` «что это за сервер?» при информативном `full-desc`; `deny`.

## Эталон

- Тулза: `confirmation` `[предл.]`.
- `short-desc`: содержит «сайт»; не равно «второй сервер»; < 50 слов.

## Метрики

- Rule-based: `cur-conflict` — класс (тулза) совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- Rule-based: `cur-fields` `[предл.]` (X-FIELDS, [AR-29]) — `server-name` непустое, < 5 слов; `short-desc` < 50 слов; `tags-short-desc` — по каждому тегу из `tags` непустое, ≤ 30 слов; подстроки эталона — без учёта регистра (README, «Метрики»).
- LLM-judge: `judge-cur-summary` `[предл.]` — (1) `short-desc` — общие слова о сервере: роль и отличительные признаки из `full-desc` (описание пользователя и находки инспектора), по которым сервер узнают в запросах; точечные факты (порты, версии, пути) — не здесь; (2) в `short-desc` и `tags-short-desc` нет додуманных фактов — всё есть в артефакте инспектора или в ответах пользователя; (3) `tags-short-desc` по каждому тегу — ситуативное: для 1c — пользователи и ИБ, для db — СУБД и базы, для host — ресурсы и что в процессах; (4) `server-name` узнаваемо — роль или имя хоста из `full-desc`; без разговорных оборотов, личных имён и сведений о доступе. Тест засчитан при всех четырёх. В метриках v0.2 такого judge нет — требуется пунктом плана IN-2a (качество составленной информации) (README, открытые пункты).

## Основания

[AR-19], [AR-29] — куратор составляет поля по артефакту инспектора; описание из формы приходит уже в составе `full-desc` (`curator-agent.md`). Если `full-desc` тоже неинформативен (осмотр ничего не дал) — это случай для инспектора, не куратора; не обсуждалось.

## Данные

Артефакт инспектора, краткие описания трёх серверов, эталон.
