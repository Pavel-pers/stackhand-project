# curator/summary/02 — краткое описание сайта сохраняет связь с 1С и не конфликтует с srv-1c

Сценарий плана: **IN-2a** — Серверы 1С и сайт — лишние вопросы не заданы (R&B), качество составленной информации о сервере (LLM); **X-FIELDS** — Поля записи о сервере с лимитами слов [AR-29] — rule-based проверка. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Второй сервер фикстуры «1С + сайт». В `full-desc` сайта есть «забирает прайс из 1С» — именно по этому признаку оркестратор отправит вопрос об импорте прайса сайту, а не серверу 1С (`orchestrator/delegated/02`). Куратор должен сохранить эту связь в `short-desc` и не поднять ложный конфликт с srv-1c из-за слова «1С»; в `tags-short-desc` host — задание импорта, в web/nginx — подрядчик.

## Контекст куратора

Артефакт инспектора (`submit`) для 10.0.1.11 [AR-29]:

- `full-desc`: По описанию пользователя: «Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С; сайт поддерживает веб-студия «Пиксель»; бэкапы сайта делает хостер». Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С с сервера 1С; сайт поддерживает веб-студия «Пиксель»; бэкапы сайта делает хостер. Ubuntu 22.04.4 LTS, 2 vCPU, 4 ГБ ОЗУ. Осмотрен инспектором 2026-10-08. Имя хоста: web-01.
- `tags`: {host, web/nginx, db/mysql, unsupported:provider-hv}
- `tags-full-desc`:
  - host — Ubuntu 22.04.4 LTS; VPS у хостинг-провайдера (KVM); 2 vCPU, 4 ГБ ОЗУ, GPU нет; диск / 40 ГБ. Планировщик: `15 * * * * /opt/site/bin/import_price.sh` (www-data) — забирает прайс с http://10.0.1.12:8080/buh/hs/price; журнал задания /var/log/site/import_price.log. Бэкапы сайта — у хостера, собственного задания нет.
  - web/nginx — nginx 1.18 (порты 80, 443), сайт example-trade.ru в /var/www/site, TLS-сертификат; php8.1-fpm; журналы /var/log/nginx/access.log, error.log. Подрядчик — веб-студия «Пиксель».
  - db/mysql — MariaDB 10.6 (порт 3306, только localhost); база site.
  - unsupported:provider-hv — гипервизор хостинг-провайдера: виден по виртуализации (QEMU/KVM), системой не обслуживается.

Краткие описания уже добавленных серверов (вход куратора [UC-15]; удалённых серверов и «прошлых описаний» нет [UC-10]):

| server-name | tags | short-desc |
|---|---|---|
| srv-1c | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |

Тулзы куратора [AR-31]: `QA(question)` ≤ 5; `confirmation(short-desc, server-name)` ≤ 3 — карточка показывает ещё и `tags-short-desc` [UC-32], подтверждаются краткое описание и название [UC-21]; третья карточка — последняя: не подтверждена — добавление прерывается, сервер не добавляется; `deny(reason)` — терминальная: отказ пользователю, чат закрывается, сервер не добавляется; после 5 QA — только confirmation и deny [AR-43], [UC-35]. Лимиты куратор видит в контексте [AR-32]. Класс rule-based `[предл.]`: `QA` при конфликте → `conflict`, `confirmation` → `consistent`; `deny` класса в v0.2 не имеет [Q50]. Остаток на начало теста: QA 5, confirmation 3, если не сказано иное.

## Вход

Артефакт инспектора и краткое описание одного сервера.

## Ожидаемое поведение

- `confirmation` (`consistent`), вопросов нет.
- `short-desc`: публичный сайт компании, VPS у хостинг-провайдера, nginx/PHP/MariaDB, раз в час забирает прайс из 1С. Пример: «Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С».
- `tags-short-desc`: host — VPS, ресурсы, cron импорта прайса; web/nginx — nginx, PHP-FPM, домен, подрядчик «Пиксель»; db/mysql — MariaDB 10.6, база сайта; unsupported:provider-hv — «платформа провайдера видна, не обслуживается».
- `server-name`: «web-01» или «Сайт компании».
- Ошибки: `QA` о конфликте с srv-1c из-за «1С» и «обмен»; связь с 1С потеряна («сайт на nginx»); сайт описан как сервер 1С; выдуманный трафик; пустое описание для `unsupported:provider-hv`.

## Эталон

- Тулза: `confirmation`.
- `short-desc`: содержит «сайт» и («прайс» или «1С»); содержит «хостинг» или «VPS»; не содержит «Бухгалтери»; < 50 слов.
- `tags-short-desc`: 4 записи, все непустые, ≤ 30 слов.
- `server-name`: непустое; отличается от названия srv-1c.

## Метрики

- Rule-based: `cur-conflict` — класс (тулза) совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- Rule-based: `cur-fields` `[предл.]` (X-FIELDS, [AR-29]) — `server-name` непустое, < 5 слов; `short-desc` < 50 слов; `tags-short-desc` — по каждому тегу из `tags` непустое, ≤ 30 слов; подстроки эталона — без учёта регистра (README, «Метрики»).
- LLM-judge: `judge-cur-summary` `[предл.]` — (1) `short-desc` — общие слова о сервере: роль и отличительные признаки из `full-desc` (описание пользователя и находки инспектора), по которым сервер узнают в запросах; точечные факты (порты, версии, пути) — не здесь; (2) в `short-desc` и `tags-short-desc` нет додуманных фактов — всё есть в артефакте инспектора или в ответах пользователя; (3) `tags-short-desc` по каждому тегу — ситуативное: для 1c — пользователи и ИБ, для db — СУБД и базы, для host — ресурсы и что в процессах; (4) `server-name` узнаваемо — роль или имя хоста из `full-desc`; без разговорных оборотов, личных имён и сведений о доступе. Тест засчитан при всех четырёх. В метриках v0.2 такого judge нет — требуется пунктом плана IN-2a (качество составленной информации) (README, открытые пункты).

## Основания

[AR-29], [AR-23]; маршрутизация вопроса об импорте прайса — `orchestrator/delegated/02` опирается на эту формулировку. Критерий «слишком похожи» — [Q33]: разные роли — `consistent`.

## Данные

Артефакт инспектора, краткие описания добавленных серверов, эталонные признаки и лимиты, рубрика judge.
