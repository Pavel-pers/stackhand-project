# curator/deny/02 — правка вне краткого описания и названия: полное описание, другой сервер, conn-info

Сценарий плана: **IN-4** — Перезапись краткого описания сервера куратором после возврата инспектора — замечания пользователя; просьбы вне границ — явный отказ. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-4, ветка «просьбы вне границ»: пользователь просит изменить что-то кроме краткого описания и названия текущего сервера — полное описание, описание другого сервера или данные подключения. Всё это вне границ куратора [UC-19] → `deny`; `conn-info` зафиксирован формой (пункт IN-3).

## Вход

Вариант A — «в полном описании поменяйте версию платформы на 8.3.25 — мы обновились вчера».

Вариант B — «и у web-01 исправьте подрядчика на „Код-Мастер“».

Вариант C — «адрес неправильный, сервер теперь 10.0.1.22 — поменяйте».

Вариант D (в границах, контрольный) — «в кратком описании добавьте, что это основной сервер бухгалтерии».

## Ожидаемое поведение

- A, B, C: `deny` с объяснением: куратор меняет только краткое описание и название добавляемого сервера; полное описание не правится (A); описания других серверов — нет (B); данные подключения заданы формой — для другого адреса заполните форму заново (C) `[предл.]`.
- D: не отказ — `confirmation` с «основной сервер бухгалтерии».
- Ошибки: в A–C — `confirmation` с «выполненной» правкой или имитация; в C — просьба прислать новый адрес в чат; в D — `deny`.

## Эталон

- A, B, C: `deny`; поля без изменений.
- D: `confirmation`; `short-desc` содержит «основн».

## Метрики

- Rule-based: `cur-deny` `[предл.]` — `deny` в A–C, `confirmation` в D.
- LLM-judge `judge-cur-deny` `[предл.]` — как в deny/01.
