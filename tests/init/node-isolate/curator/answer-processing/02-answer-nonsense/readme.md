# curator/answer-processing/02 — невменяемый ответ на вопрос о различиях

## Сценарий

Продолжение curator/conflict/01: на вопрос «чем отличаются» пользователь отвечает так, что различий из ответа не извлечь. Конфликт остаётся; куратор не пишет ответ в краткое описание и переспрашивает конкретнее.

## Контекст куратора

Как в curator/conflict/01. История чата:

- Куратор: «Сервер 10.0.1.14 описан так же, как srv-1c (10.0.1.12): „Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL“. Чем они отличаются?»

## Вход

Вариант A — «ну да».

Вариант B — «ыпаы».

Вариант C — «не знаю, сами разберитесь».

## Ожидаемое поведение

- Класс `conflict`, серверы — {10.0.1.14, srv-1c}.
- Краткое описание не изменено ответом; «ну да», «ыпаы» или «не знаю» в него не попали.
- Вопрос повторён конкретнее — с подсказкой, какие отличия нужны: назначение (рабочий, тестовый, резервный), базы, кто работает. В варианте C допустимо объяснить, зачем нужно различие: иначе вопросы о «сервере 1С» нельзя будет направить на нужный сервер.
- Ошибки: `consistent` с прежним описанием; куратор сам придумал отличие и записал как факт; добавление завершено с двумя одинаковыми описаниями.

## Эталон

- Класс: `conflict`; серверы: {10.0.1.14, srv-1c}; краткое описание 10.0.1.14 — прежнее.

## Метрики

- Rule-based: `cur-conflict` — класс совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- LLM-judge: `judge-cur-question` — (1) язык понятен пользователю, без внутрисистемных терминов; (2) суть донесена верно — спрошено, чем серверы отличаются; (3) указаны правильные документы — именно те серверы и описания, между которыми конфликт. Тест засчитан при всех трёх.

## Основания

Не обсуждалось: «может ли куратор переспрашивать несколько раз; что при отказе пользователя уточнять» (`architecture/curator-agent.md`). Эталон «конфликт остаётся, переспросить» — предложение тестов `[предл.]`; он следует назначению куратора — серверы должны различаться [UC-15].

## Данные

Контекст curator/conflict/01, история чата, ответы A–C, эталон, рубрика judge.
