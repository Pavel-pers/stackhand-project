# curator/answer-processing/01 — уточнение попало в краткое описание

## Сценарий

Продолжение curator/conflict/01: куратор спросил, чем 10.0.1.14 отличается от srv-1c, пользователь ответил. Уточнение должно попасть в краткое описание нового сервера так, чтобы серверы различались; описание srv-1c и другие поля не меняются.

## Контекст куратора

Как в curator/conflict/01. История чата:

- Куратор: «Сервер 10.0.1.14 описан так же, как srv-1c (10.0.1.12): „Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL“. Чем они отличаются?»

## Вход

Ответ пользователя: «Это тестовый сервер франчайзи: копии Бухгалтерии и ЗУП для доработок, бухгалтеры там не работают».

## Ожидаемое поведение

- Класс `consistent`.
- Краткое описание 10.0.1.14 различимо с srv-1c: тестовый сервер франчайзи, копии баз для доработок, бухгалтеры не работают. Пример: «Тестовый сервер 1С франчайзи: копии Бухгалтерии и ЗУП на PostgreSQL для доработок; бухгалтеры не работают».
- Краткое описание srv-1c не изменилось.
- Ошибки: ответ вставлен дословно с разговорными оборотами; в описании потеряно «1С» или «PostgreSQL»; изменено описание srv-1c; повторный вопрос.

## Эталон

- Класс: `consistent`.
- Краткое описание 10.0.1.14 содержит «тест» (тестовый) и «франчайзи» или «доработ»; содержит «1С»; описание srv-1c — без изменений.

## Метрики

- Rule-based: `cur-conflict` — класс совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.

## Основания

«Уточнение попадает в краткое описание» — текст K, не оспорен [UC-15].

## Данные

Контекст curator/conflict/01, история чата, ответ, эталон.
