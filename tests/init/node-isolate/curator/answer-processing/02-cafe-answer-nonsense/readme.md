# curator/answer-processing/02 — ответ, из которого адреса не извлечь

Сценарий плана: **IN-1b** — N серверов кафе + ещё один — такт 2: обработка ответа, корректный результат. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Продолжение curator/conflict/01 (вариант A): на вопрос «где это кафе» пользователь отвечает так, что адреса из ответа не получить. Конфликт остаётся; куратор не пишет ответ в `short-desc` и переспрашивает конкретнее (QA ≤ 5 [AR-32]).

Серверы кафе собраны из одного образа: теги и роль одинаковые, различает их только адрес в кратком описании. Удалённых серверов нет.

Тулзы куратора [AR-31]: `QA(question)` ≤ 5, `confirmation(short-desc, server-name)` ≤ 3, `deny(reason)` — терминальная; лимиты видит в контексте [AR-32]. Класс rule-based `[предл.]`: `QA` при конфликте → `conflict`, `confirmation` → `consistent`; `deny` класса в v0.2 не имеет [Q50]. Остаток на начало теста: QA 5, confirmation 3, если не сказано иное.

История чата:

- Куратор (`QA`): «Новый сервер 10.30.5.10 описан так же, как серверы кафе на Тверской, на Арбате, на Покровке и у «Сокола», только без адреса. В каком кафе он стоит — какой у него адрес?»

Остаток: QA 4, confirmation 3.

## Вход

Вариант A — «ну да».

Вариант B — «ыпаы».

Вариант C — «не знаю, сами разберитесь».

Вариант D — «такой же, как все остальные» (по смыслу ответ, но различия в нём нет).

Буквы вариантов совпадают с init/e2e/n-server-cafe/04; рабочий запрос внутри чата добавления (там вариант E) на уровне узла не проверяется — это поведение системы, а не куратора.

## Ожидаемое поведение

- `QA` (`conflict`), серверы — {10.30.5.10, cafe-01…cafe-04}.
- `short-desc` не изменён ответом; «ну да», «ыпаы», «не знаю» и «такой же» в него не попали.
- Вопрос повторён конкретнее: нужен адрес или ориентир кафе. В вариантах C и D допустимо объяснить, зачем: иначе вопрос о «кафе на …» нельзя будет направить на нужный сервер.
- Ошибки: `confirmation` с прежним описанием; куратор сам придумал адрес; `deny` (ответ не требует смены тегов — повода для отказа нет).

## Эталон

- Тулза: `QA`; серверы: {10.30.5.10, cafe-01…cafe-04}; `short-desc` 10.30.5.10 — прежний.

## Метрики

- Rule-based: `cur-conflict` — класс (тулза) совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- LLM-judge: `judge-cur-question` — (1) язык понятен пользователю, без имён ручек, классов и тегов как идентификаторов; (2) суть донесена верно — спрошено, чем новый сервер отличается от серверов кафе: адрес или место кафе; (3) указаны правильные документы — серверы кафе, с которыми совпало описание; сервер офиса не упомянут как похожий. Тест засчитан при всех трёх.
