# curator/conflict/02 — описание из формы ничего не говорит о сервере

## Сценарий

Наследник старого init/ask/01 («не сказали, что на первом сервере»). Пользователь в поле description написал только «второй сервер». По такому краткому описанию оркестратор не отличит сервер ни от одного другого; куратор спрашивает, что это за сервер и для чего он, а не присваивает роль сам.

## Контекст куратора

Описание из формы для 10.0.1.11: «второй сервер». Добавлены srv-1c, acc-01, gw-01 (краткие описания — как в таблице ниже, без web-01).

Краткие описания уже добавленных серверов (стенд M) — вход куратора [UC-15]:

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Удалённых серверов и «прошлых описаний» нет — с ними куратор не сверяет [UC-10]. Видит ли куратор полное описание, собранное инспектором, — не обсуждалось; в node-isolate тестах куратора его нет.

## Вход

Описание из формы и краткие описания трёх серверов.

## Ожидаемое поведение

- Класс `conflict` `[предл.]`: краткое описание не отличает сервер от добавленных.
- Вопрос конкретный: что это за сервер и для чего он, чтобы его можно было отличать от остальных.
- Роль не присвоена молча, краткое описание не выдумано.
- Ошибки: краткое описание «второй сервер» принято как есть (`consistent`); роль «сайт» или «1С» присвоена без ответа.

## Эталон

- Класс: `conflict` `[предл.]`; набор серверов: содержит 10.0.1.11; остальные члены набора не проверяются.
- Суть вопроса: назначение сервера.

## Метрики

- Rule-based: `cur-conflict` — класс совпадает с эталоном; при `conflict` — набор содержит новый сервер.
- LLM-judge: `judge-cur-question` — критерии (1) и (2); критерий (3) «указаны правильные документы» здесь не применим.

## Основания

Не обсуждалось: что делает куратор с неинформативным описанием из формы; валидация формы; критерий конфликта [Q33]. Класс `conflict` и набор «новый сервер» — предложение тестов, чтобы сохранить покрытие старого init/ask/01. Если решат, что такой случай закрывает инспектор (по осмотру) — тест переедет в inspector/clarify.

## Данные

Описание из формы, краткие описания трёх серверов, эталон.
