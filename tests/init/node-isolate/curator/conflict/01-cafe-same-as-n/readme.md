# curator/conflict/01 — сеть кафе: новое кафе описано так же, как остальные

Сценарий плана: **IN-1a** — N серверов кафе + ещё один — такт 1: серверы получились неразличимы, R&B — вопрос задан, LLM — корректность вопроса. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана IN-1a на уровне узла (такт «вопрос»). Сеть кафе: в каждом кафе одинаковый мини-сервер, серверы различаются только адресом кафе. Добавляется сервер нового кафе, но адрес в описание не попал, а осмотр инспектора адреса дать не может — `full-desc` совпадает с остальными кафе. Куратор должен поднять конфликт и спросить адрес тулзой `QA`.

Вариант A — общее описание без адреса: «Сервер кафе: меню, заказы и экран кухни; PostgreSQL и сервисы в Docker». Совпадает с общей частью описаний всех четырёх кафе.

Вариант B — описание скопировано из формы кафе на Тверской слово в слово: «Сервер кафе на Тверской, 12: меню, заказы и экран кухни; PostgreSQL и сервисы в Docker». Это одинаковые описания из примера пользователя [UC-15].

## Контекст куратора

Серверы кафе собраны из одного образа: теги и роль одинаковые, различает их только адрес в кратком описании. Удалённых серверов нет.

Тулзы куратора [AR-31]: `QA(question)` ≤ 5; `confirmation(short-desc, server-name)` ≤ 3 — карточка показывает ещё и `tags-short-desc` [UC-32], подтверждаются краткое описание и название [UC-21]; третья карточка — последняя: не подтверждена — добавление прерывается, сервер не добавляется; `deny(reason)` — терминальная: отказ пользователю, чат закрывается, сервер не добавляется; после 5 QA — только confirmation и deny [AR-43], [UC-35]. Лимиты куратор видит в контексте [AR-32]. Класс rule-based `[предл.]`: `QA` при конфликте → `conflict`, `confirmation` → `consistent`; `deny` класса в v0.2 не имеет [Q50]. Остаток на начало теста: QA 5, confirmation 3, если не сказано иное.

Вариант B — тот же артефакт, но описание пользователя в `full-desc`: «Сервер кафе на Тверской, 12: меню, заказы и экран кухни; PostgreSQL и сервисы в Docker».

## Вход

Артефакт инспектора и краткие описания пяти серверов.

## Ожидаемое поведение

- `QA` (`conflict`); `confirmation` до ответа не вызван.
- Серверы: вариант A — {10.30.5.10, cafe-01, cafe-02, cafe-03, cafe-04}; вариант B — {10.30.5.10, cafe-01}.
- office-01 в конфликт не входит, хотя у него тоже db/pg и PostgreSQL.
- Вопрос: вариант A — где это кафе, какой адрес; пример: «Новый сервер 10.30.5.10 описан так же, как серверы кафе на Тверской, на Арбате, на Покровке и у «Сокола», только без адреса. В каком кафе он стоит — какой у него адрес?» Вариант B — описание совпадает с кафе на Тверской: это то же кафе или новое, и какой у него адрес.
- Краткие описания существующих кафе не меняются; адрес не выдумывается.
- Серверы кафе в вопросе можно перечислить или назвать обобщённо («как серверы остальных кафе») — критерий (3) читается так `[предл.]`; сервер офиса назван быть не должен.
- Ошибки: `confirmation` с описанием без адреса; в конфликт включён office-01; в варианте A вопрос не про адрес; в варианте B конфликт со всеми кафе, а не с cafe-01; `deny`.

## Эталон

- Тулза: `QA` (`conflict`).
- Серверы: вариант A — {10.30.5.10, cafe-01…cafe-04}; вариант B — {10.30.5.10, cafe-01}.
- Суть вопроса: адрес или место нового кафе.

## Метрики

- Rule-based: `cur-conflict` — класс (тулза) совпадает с эталоном; при `conflict` — набор серверов совпадает с эталонным.
- LLM-judge: `judge-cur-question` — (1) язык понятен пользователю, без имён ручек, классов и тегов как идентификаторов; (2) суть донесена верно — спрошено, чем новый сервер отличается от серверов кафе: адрес или место кафе; (3) указаны правильные документы — серверы кафе, с которыми совпало описание; сервер офиса не упомянут как похожий. Тест засчитан при всех трёх.

## Основания

Транскрипт плана, Init-1: «сервера получились различными [по смыслу — неразличимыми]: R&B — вопрос задан, LLM — корректность вопроса»; пример пользователя — одинаковые краткие описания [UC-15]; формулировка — [K §2.2]; [UC-17]. Вариант A: критерий «слишком похожи» не определён [Q33]; эталон `conflict` задан планом.
