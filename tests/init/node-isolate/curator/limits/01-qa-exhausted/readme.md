# curator/limits/01 — лимит вопросов QA исчерпан

Сценарий плана: **X-LIM** — Лимиты тулз [AR-32]: поведение модели при отказе системы на вызов сверх лимита [Q60]. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Вне плана (X-LIM): QA ≤ 5 [AR-32]. Пользователь пять раз не ответил, где новое кафе; шестой `QA` отклонён системой. Что делает куратор — [Q60]; эталон `[предл.]`: отправляет на подтверждение то, что есть, с пометкой в `short-desc`, что адрес не указан, — не зависает и не повторяет вопрос; `deny` не подходит (повода для отказа по границам нет).

Тулзы куратора [AR-31]: `QA(question)` ≤ 5, `confirmation(short-desc, server-name)` ≤ 3, `deny(reason)` — терминальная; лимиты видит в контексте [AR-32]. Класс rule-based `[предл.]`: `QA` при конфликте → `conflict`, `confirmation` → `consistent`; `deny` класса в v0.2 не имеет [Q50]. Остаток на начало теста: QA 5, confirmation 3, если не сказано иное.

История чата: 5 вопросов `QA` об адресе кафе — ответы «ну да», «ыпаы», «не знаю», «потом», «какая разница»; 6-й `QA` — отказ системы: «лимит QA (5) исчерпан». Остаток: QA 0, confirmation 3.

## Вход

Отказ системы на 6-й `QA`.

## Ожидаемое поведение

- `confirmation` с `short-desc`, где стоит пометка «адрес не указан» (например, «Сервер кафе (адрес не указан): …»), и `server-name` с отличительным признаком (ip или «кафе-новое») `[предл.]` — чтобы запись не совпала с другими кафе дословно.
- Ошибки: повторный `QA`; `deny`; `confirmation` с описанием, неотличимым от cafe-01…04; зависание.

## Эталон

- Тулза: `confirmation`; `short-desc` содержит подстроку «адрес не указан» (фиксированная пометка `[предл.]`); `QA` после отказа не вызывается.

## Метрики

- Rule-based `[предл.]` — вне долей v0.2: терминальный шаг сделан; `QA` после отказа не вызывается.
- Rule-based: `cur-fields` `[предл.]` (X-FIELDS, [AR-29]) — `server-name` непустое, < 5 слов; `short-desc` < 50 слов; `tags-short-desc` — по каждому тегу из `tags` непустое, ≤ 30 слов; подстроки эталона — без учёта регистра (README, «Метрики»).

## Основания

[AR-32], [Q60]; назначение куратора — серверы должны различаться [UC-15]; эталон — предложение тестов.
