# inspector/filled/01 — сервер 1С: всё есть в осмотре и описании, вопросов нет

## Сценарий

Пользователь добавил srv-1c через форму. Всё, что нужно для полей описания, есть в инвентаре или в описании из формы. Инспектор должен предложить теги, заполнить полное описание и поля паспорта и не задавать вопросов — ложное уточнение здесь такая же ошибка, как пропущенное.

## Контекст инспектора

Форма: ip 10.0.1.12, ssh_key `eval_ed25519`, description «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; обслуживает франчайзи «1С-Партнёр»; бэкап — pg_dump каждую ночь в /backup/pg; apache публикует данные 1С для обмена с сайтом».

Инвентарь srv-1c 10.0.1.12 (фикстура осмотра 2026-10-08 14:00):

- Ubuntu 22.04.4 LTS, ядро 5.15; виртуализация kvm; 8 vCPU, 32 ГБ ОЗУ; GPU не обнаружено.
- Тома: /dev/sda2 → / 98 ГБ (занято 41 ГБ); /dev/sdb1 → /var/lib/postgresql 492 ГБ (занято 350 ГБ); /dev/sdc1 → /backup 980 ГБ (занято 193 ГБ).
- Активные юниты: srv1cv8-8.3.24.1548@default, postgresql@16-main, apache2, ssh, cron. Бинарь ras есть, служба RAS не запущена.
- Процессы: ragent, rmngr, rphost ×2, postgres (≈ 30), apache2.
- Слушающие порты: 22, 1540, 1541, 1560–1591, 5432, 8080.
- Кластер 1С: реестр кластера содержит ИБ Buh и ZUP; СУБД — PostgreSQL на localhost.
- PostgreSQL 16: базы buh, zup; data_directory /var/lib/postgresql/16/main.
- apache2: конфигурация публикации 1С, Listen 8080, веб-сервис обмена /buh/hs/price.
- cron (root): `0 2 * * * /usr/local/bin/backup_1c.sh` — pg_dump баз buh и zup в /backup/pg; последние файлы buh_2026-10-08.dump (02:14), zup_2026-10-08.dump (02:09).
- Учётка подключения evalbot: sudo на установку тулкитов и выполнение предусловий.

Правила detect первой волны (выдержка, [T §3.1, §5], `architecture/tags.md`), которые инспектор применяет к инвентарю:

| Тег | Детект |
|---|---|
| host | всегда |
| db | служба MSSQL*; юнит postgresql* или процесс postgres; mysqld / mariadbd |
| 1c | служба или процесс ragent, юнит srv1cv8*; файлы 1Cv8.1CD без сервера |
| web | nginx / apache / W3SVC с сайтом |
| docker | dockerd или сокет |
| backup | службы Veeam, Кибер Бэкапа, PBS, WSB; репозитории из паспорта |

Уверенность: служба или роль найдена — высокая; только файлы или процесс — средняя; неподдерживаемое — `unsupported:<имя>` без тулкита [T §3.1, §3.4]. Перенос этих правил на инспектора детально не обсуждался (`architecture/inspector-agent.md`).

## Вход

Результат осмотра (фикстура выше) и описание из формы; истории чата нет.

## Ожидаемое поведение

- Класс `filled`, вопросов пользователю нет.
- Теги — ровно {host, 1c/cluster, db/pg, web/apache}: юниты srv1cv8, postgresql@16-main и apache2 с публикацией дают высокую уверенность.
- Полное описание содержит факты чек-листа (эталон) и не содержит фактов, которых нет ни в осмотре, ни в описании.
- Расхождений «сказано — по факту» нет: бэкап по описанию в /backup/pg, cron складывает туда же.
- Предусловия для тегов (по манифестам: включение RAS для чтения сеансов и кластера, учётка мониторинга PostgreSQL, права чтения журналов) перечислены для карточки подтверждения, а не заданы вопросом — они подтверждаются вместе с JSON [UC-07].
- Ошибки: вопрос «подтвердите теги» при высокой уверенности; вопрос о пути бэкапа, который совпал с осмотром; тег `files` или `backup` без детекта; выдуманные версии и пути.

## Эталон

- Класс: `filled`.
- `tags`: {host, 1c/cluster, db/pg, web/apache}.
- Чек-лист полного описания: Ubuntu 22.04.4; 8 vCPU, 32 ГБ, GPU нет; тома / 98 ГБ, /var/lib/postgresql 492 ГБ, /backup 980 ГБ; 1С 8.3.24.1548, кластер: 1540, 1541, 1560–1591; ИБ Buh и ZUP в PostgreSQL; PostgreSQL 16, порт 5432; apache2 — публикация 1С для обмена с сайтом, порт 8080; cron `0 2 * * *` — pg_dump в /backup/pg; около 12 пользователей (из описания).
- Поля паспорта (перечень — по контракту [K §2.1 Вход 1]; точный набор — по манифестам [Q04]): пути бэкапов — /backup/pg; ИБ — Buh, ZUP; подрядчик по 1С — «1С-Партнёр».
- Правило сравнения полей полного описания: факт присутствует и совпадает (числа — точно, формулировки — по смыслу); формат полного описания не обсуждался.

## Метрики

- Rule-based: `insp-fields` — по каждому полю: теги — совпадение множеств; полное описание — каждый факт из чек-листа присутствует и верен, выдуманных фактов нет; поля паспорта — значение по эталону. `insp-clarify` — вопрос не задан (ложное уточнение — тест не засчитан).

[K §2.1 Вход 1, §2.2], [UC-04], [UC-07], [T §3.1], метрики инспектора [M]. Не обсуждалось: формат полного описания; связь полного описания с паспортом [Q07]; эталон — вручную по фикстуре [Q19].
