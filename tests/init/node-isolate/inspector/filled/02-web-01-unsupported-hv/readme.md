# inspector/filled/02 — сайт на VPS у хостера: теги, неподдерживаемая платформа провайдера

## Сценарий

Пользователь добавил web-01 — VPS у хостинг-провайдера. Инспектор должен предложить теги сайта и СУБД и отметить платформу провайдера как неподдерживаемую: она видна, но не обслуживается и тулкита не получает. Вопросов не нужно.

## Контекст инспектора

Форма: ip 10.0.1.11, ssh_key `eval_ed25519`, description «Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С; сайт поддерживает веб-студия «Пиксель»; бэкапы сайта делает хостер».

Инвентарь web-01 10.0.1.11 (фикстура осмотра):

- Ubuntu 22.04.4 LTS; виртуализация kvm, оборудование — стандартная виртуальная машина провайдера (DMI: QEMU); 2 vCPU, 4 ГБ ОЗУ; GPU не обнаружено; / 40 ГБ (занято 17 ГБ).
- Активные юниты: nginx, php8.1-fpm, mariadb, ssh, cron. Docker не установлен.
- Слушающие порты: 22, 80, 443, 3306 (только 127.0.0.1).
- nginx: сайт example-trade.ru, корень /var/www/site, TLS-сертификат.
- MariaDB 10.6: база site.
- cron (www-data): `15 * * * * /opt/site/bin/import_price.sh` — скрипт забирает прайс с http://10.0.1.12:8080/buh/hs/price; журнал задания /var/log/site/import_price.log.
- Учётка подключения evalbot: sudo на установку тулкитов и выполнение предусловий.

Правила detect первой волны (выдержка, [T §3.1, §5], `architecture/tags.md`), которые инспектор применяет к инвентарю:

| Тег | Детект |
|---|---|
| host | всегда |
| db | служба MSSQL*; юнит postgresql* или процесс postgres; mysqld / mariadbd |
| 1c | служба или процесс ragent, юнит srv1cv8*; файлы 1Cv8.1CD без сервера |
| web | nginx / apache / W3SVC с сайтом |
| docker | dockerd или сокет |
| backup | службы Veeam, Кибер Бэкапа, PBS, WSB; репозитории из паспорта |

Уверенность: служба или роль найдена — высокая; только файлы или процесс — средняя; неподдерживаемое — `unsupported:<имя>` без тулкита [T §3.1, §3.4]. Перенос этих правил на инспектора детально не обсуждался (`architecture/inspector-agent.md`).

## Вход

Результат осмотра и описание из формы; истории чата нет.

## Ожидаемое поведение

- Класс `filled`, вопросов нет.
- Теги — ровно {host, web/nginx, db/mysql, unsupported:provider-hv}: nginx с сайтом и служба mariadb — высокая уверенность; гипервизор провайдера — по виртуализации и описанию «VPS у хостинг-провайдера» [T §6, §7].
- Для `unsupported:provider-hv` тулкит не ставится и предусловий нет [T §3.4].
- Полное описание: факты чек-листа; задание импорта прайса с адресом публикации 1С; подрядчик и бэкапы у хостера — из описания.
- Ошибки: тег `1c` из-за упоминания 1С в задании импорта; тег `docker`; попытка поставить тулкит гипервизора; вопрос о хостере, когда всё сказано в описании.

## Эталон

- Класс: `filled`.
- `tags`: {host, web/nginx, db/mysql, unsupported:provider-hv}.
- Чек-лист полного описания: Ubuntu 22.04.4; VPS у хостинг-провайдера (KVM), платформа провайдера не обслуживается; 2 vCPU, 4 ГБ, GPU нет, / 40 ГБ; nginx (80, 443), сайт в /var/www/site; php8.1-fpm; MariaDB 10.6, порт 3306 только локально; cron `15 * * * *` — импорт прайса из публикации 1С на 10.0.1.12:8080, журнал задания /var/log/site/import_price.log.
- Поля паспорта: подрядчик — веб-студия «Пиксель»; бэкапы — делает хостер (собственного задания бэкапа на сервере нет).

## Метрики

- Rule-based: `insp-fields` — по каждому полю: теги — совпадение множеств; полное описание — каждый факт из чек-листа присутствует и верен, выдуманных фактов нет; поля паспорта — значение по эталону. `insp-clarify` — вопрос не задан (ложное уточнение — тест не засчитан).

## Основания

[T §3.4, §6, §7] — `unsupported:provider-hv`; [UC-16] — имя тега пользователю в ответах не называется (в JSON при добавлении теги видны [UC-08]). Не обсуждалось: как именно инспектор опознаёт платформу провайдера — эталон предполагает виртуализацию + описание `[предл.]`.

## Данные

Форма, фикстура инвентаря web-01, правила detect, эталон.
