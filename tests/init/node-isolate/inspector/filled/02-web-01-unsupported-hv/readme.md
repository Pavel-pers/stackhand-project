# inspector/filled/02 — сайт на VPS у хостера: теги, неподдерживаемая платформа провайдера

Сценарий плана: **IN-2a** — Серверы 1С и сайт — лишние вопросы не заданы (R&B), качество составленной информации о сервере (LLM). Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-2a, сторона сайта. Инспектор должен выбрать теги сайта и СУБД и отметить платформу провайдера как неподдерживаемую: она видна, но не обслуживается. Вопросов не нужно. Ручки «просмотр доменов на сайте» и «поиск nginx-логов» — примеры из постановки [AR-30].

## Контекст инспектора

Форма «Добавить сервер»: `conn-ip` 10.0.1.11, `conn-ssh-key` `eval_ed25519`, `description` «Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С; сайт поддерживает веб-студия «Пиксель»; бэкапы сайта делает хостер».

Ручки инспектора — one-shot осмотра [AR-30]; каталог — предложение тестов до [Q58]:

| Ручка | Что возвращает |
|---|---|
| `insp.hardware` | CPU, память, GPU, диски, виртуализация (DMI) |
| `insp.os_packages` | ОС, ядро, установленные пакеты по категориям |
| `insp.services_processes` | активные юниты и процессы |
| `insp.ports` | слушающие порты |
| `insp.volumes` | тома и точки монтирования, сетевые тома |
| `insp.scheduler` | задания cron и systemd-таймеры с командами |
| `insp.path_check(path)` | существует ли путь, что в нём (размер, свежие файлы) |
| `insp.1c_structure` | кластер 1С: версия платформы, порты, реестр ИБ, СУБД каждой ИБ |
| `insp.1c_users` | «сканер пользователей»: учётки и роли в ИБ, активные сеансы на момент осмотра |
| `insp.db_instances` | СУБД: версия, порт, базы, доступ учётки мониторинга |
| `insp.web_sites` | веб-сервер: сайты, домены, корни, сертификаты |
| `insp.web_logs` | пути журналов веб-сервера и их свежесть |
| `insp.docker_containers` | контейнеры, образы, тома, доступ к GPU |
| `insp.backup_jobs` | задания и репозитории резервного копирования (restic, pg_dump, vzdump…) |
| `insp.account_rights` | права учётки подключения: sudo, доступ к СУБД — только чтением |
| `ask-user(question)` | вопрос пользователю (≤ 10 на сессию) |
| `submit(full-desc, tags, tags-full-desc)` | терминальная сдача артефакта куратору |

Лимит — 40 вызовов ручек осмотра на сессию [AR-32]; инспектор видит остаток.

Чек-лист инспектора (в промпте; предложение тестов до [Q58]) — какие ручки попробовать для составления информации по тегу; `host` — всегда:

| Тег | Обязательные ручки | Что должно попасть в `tags-full-desc` |
|---|---|---|
| host (всегда) | `insp.hardware`, `insp.os_packages`, `insp.services_processes`, `insp.ports`, `insp.volumes`, `insp.scheduler`, `insp.backup_jobs` | ОС и ресурсы; тома; службы и порты; задания планировщика; где лежат бэкапы (пути — по описанию пользователя и `insp.path_check`) |
| 1c | `insp.1c_structure`, `insp.1c_users` | версия платформы, порты кластера, ИБ и их СУБД; пользователи и роли ИБ, сеансы на момент осмотра; подрядчик — из описания пользователя |
| db | `insp.db_instances` | СУБД, версия, порт, базы; учётка мониторинга и её права (`insp.account_rights`) |
| web | `insp.web_sites`, `insp.web_logs` | сайты и домены, сертификаты; пути журналов; подрядчик — из описания пользователя |
| docker | `insp.docker_containers` | контейнеры, образы, тома; что внутри (СУБД только в контейнере — кандидат `db` со средней уверенностью: вопрос пользователю, следить ли за ней как за СУБД [K §2.2], [T §3.1]) |
| backup | `insp.backup_jobs` | драйвер, репозиторий, расписание, последние запуски |
| unsupported:* | `insp.hardware` (виртуализация) | что видно и не обслуживается |

Правило проверки описания пользователя: каждое утверждение описания, которое можно проверить ручкой (путь, служба, СУБД, число пользователей), проверяется; расхождение «сказано — по факту» — повод для вопроса пользователю (поведение при расхождении в документах не описано — `[предл.]`).

Результаты ручек осмотра web-01 10.0.1.11 (фикстуры):

- `insp.hardware` → Ubuntu 22.04.4 LTS; виртуализация kvm (DMI: QEMU Standard PC); 2 vCPU, 4 ГБ ОЗУ; GPU не обнаружено; диск vda 40 ГБ.
- `insp.os_packages` → nginx 1.18, php8.1-fpm, mariadb-server 10.6, openssh-server, cron; docker не установлен.
- `insp.services_processes` → активные юниты: nginx, php8.1-fpm, mariadb, ssh, cron.
- `insp.ports` → 22, 80, 443, 3306 (только 127.0.0.1).
- `insp.volumes` → / 40 ГБ (занято 17); сетевых томов нет.
- `insp.scheduler` → cron www-data: `15 * * * * /opt/site/bin/import_price.sh` — забирает прайс с http://10.0.1.12:8080/buh/hs/price; журнал задания /var/log/site/import_price.log.
- `insp.web_sites` («просмотр доменов на сайте») → nginx: сайт example-trade.ru (80, 443), корень /var/www/site, TLS-сертификат до 2027-01-15; php8.1-fpm.
- `insp.web_logs` («поиск nginx-логов») → /var/log/nginx/access.log, error.log — свежие.
- `insp.db_instances` → MariaDB 10.6, порт 3306 (localhost); база site; учётка мониторинга — есть.
- `insp.backup_jobs` → собственных заданий бэкапа нет; restic/PBS/Veeam не найдены.
- `insp.account_rights` → evalbot: sudo на чтение журналов и установку пакетов; доступ к MariaDB — учётка мониторинга.
- `insp.docker_containers` → Docker не установлен.

Остаток лимитов на начало теста: ручки осмотра — 40 из 40, `ask-user` — 10 из 10 [AR-32].

## Вход

Поля формы и результаты ручек; истории чата нет.

## Ожидаемое поведение

- `submit` (`filled`), вопросов нет.
- `tags` — ровно {host, web/nginx, db/mysql, unsupported:provider-hv}: nginx с сайтом и служба mariadb — высокая уверенность; платформа провайдера — по виртуализации и описанию «VPS у хостинг-провайдера» [T §6, §7].
- `full-desc`: публичный сайт компании на VPS у хостинг-провайдера; nginx, PHP, MariaDB; импорт прайса из 1С раз в час; подрядчик «Пиксель» и бэкапы у хостера — из описания; ресурсы.
- `tags-full-desc`: web/nginx — домен example-trade.ru, порты, корень, сертификат, журналы; db/mysql — MariaDB 10.6, 3306 локально, база site; host — ресурсы, диск, задание импорта с адресом публикации 1С и журналом задания; unsupported:provider-hv — «гипервизор провайдера виден, не обслуживается».
- Ошибки: тег `1c` из-за упоминания 1С в задании импорта; тег `docker`; вопрос о хостере, когда всё сказано в описании; домен и пути журналов не из ручек.

## Эталон

- Тулза: `submit`; `tags`: {host, web/nginx, db/mysql, unsupported:provider-hv}.
- Чек-лист `full-desc`: сайт компании на VPS у хостинг-провайдера; nginx, PHP, MariaDB; импорт прайса из 1С раз в час; подрядчик «Пиксель»; бэкапы у хостера; Ubuntu 22.04.4; 2 vCPU, 4 ГБ.
- Чек-лист `tags-full-desc`: web/nginx — example-trade.ru, 80/443, /var/www/site, сертификат, /var/log/nginx/; db/mysql — 10.6, 3306 localhost, site; host — диск 40 ГБ, cron `15 * * * *` import_price.sh → 10.0.1.12:8080/buh/hs/price, журнал /var/log/site/import_price.log; unsupported:provider-hv — виден, не обслуживается.

## Метрики

- Rule-based: `insp-fields` — `tags`: совпадение множеств; `full-desc`: каждый факт чек-листа эталона присутствует и верен (числа — точно, формулировки — по смыслу), выдуманных фактов нет; `tags-full-desc`: по каждому тегу из `tags` описание непустое и содержит факты эталона для тега. `insp-clarify` — вопрос не задан (ложное уточнение — тест не засчитан). Терминальная тулза — `submit`.

## Основания

[T §3.4, §6, §7] — `unsupported:provider-hv`; [UC-16]; [AR-30] — ручки «домены на сайте», «поиск nginx-логов». Признаки виртуализации у web-01 и srv-1c одинаковые (kvm), поэтому эталон опирается на описание из формы `[предл.]`.

Эталон «вопрос не задан» `[предл.]`: по метрике инспектора вопрос не задаётся там, где поле заполняется из осмотра [M]; теги и полные поля пользователь не подтверждает [UC-21], поэтому «подтвердите теги» — ложное уточнение. Предусловия тегов (RAS, учётка мониторинга) после UC-21 отдельным вопросом не подтверждаются; кто и когда ставит тулкиты и предусловия — [Q49].
