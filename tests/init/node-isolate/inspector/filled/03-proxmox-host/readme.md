# inspector/filled/03 — гипервизор Proxmox по SSH

## Сценарий

Наследник Linux-части старого init/success/02: гипервизор Proxmox осматривается по SSH, тег hv входит в каталог первой волны [T §5]. Windows-ВМ на нём как отдельные серверы не добавляются — их статус при подключении только по SSH не решён [Q09]. Инспектор выбирает теги и заполняет поля без вопросов; ручки для hv в каталоге `[предл.]` не выделены — факты о ВМ приходят через ручки служб и планировщика.

## Контекст инспектора

Форма «Добавить сервер»: `conn-ip` 10.0.1.30, `conn-user` `evalbot`, `conn-ssh-key` `eval_ed25519`, `description` «Гипервизор Proxmox pve-01: на нём ВМ vm-1c (1С с MS SQL) и vm-rds (терминальный сервер); бэкапы ВМ делает сам Proxmox по субботам».

Ручки инспектора — one-shot осмотра [AR-30]; каталог — предложение тестов до [Q58]:

| Ручка | Что возвращает |
|---|---|
| `insp.hardware` | CPU, память, GPU, диски, виртуализация (DMI) |
| `insp.os_packages` | ОС, ядро, установленные пакеты по категориям |
| `insp.services_processes` | активные юниты и процессы |
| `insp.ports` | слушающие порты |
| `insp.volumes` | тома и точки монтирования, сетевые тома |
| `insp.scheduler` | задания cron и systemd-таймеры с командами |
| `insp.path_check(path)` | существует ли путь, что в нём (размер, свежие файлы) |
| `insp.1c_structure` | кластер 1С: версия платформы, порты, реестр ИБ, СУБД каждой ИБ |
| `insp.1c_users` | «сканер пользователей»: учётки и роли в ИБ, активные сеансы на момент осмотра |
| `insp.db_instances` | СУБД: версия, порт, базы, доступ учётки мониторинга |
| `insp.web_sites` | веб-сервер: сайты, домены, корни, сертификаты |
| `insp.web_logs` | пути журналов веб-сервера и их свежесть |
| `insp.docker_containers` | контейнеры, образы, тома, доступ к GPU |
| `insp.backup_jobs` | задания и репозитории резервного копирования (restic, pg_dump, vzdump…) |
| `insp.account_rights` | права учётки подключения: sudo, доступ к СУБД — только чтением |
| `ask-user(question)` | вопрос пользователю (≤ 10 на сессию) |
| `submit(full-desc, tags, tags-full-desc)` | терминальная сдача артефакта куратору |

Лимит — 40 вызовов ручек осмотра и 10 вопросов на сессию [AR-32]; инспектор видит остаток; вызов сверх лимита отклоняется с комментарием, 10 таких подряд — закрытие сессии [AR-43].

Чек-лист инспектора (в промпте; предложение тестов до [Q58]) — какие ручки попробовать для составления информации по тегу; `host` — всегда:

| Тег | Обязательные ручки | Что должно попасть в `tags-full-desc` |
|---|---|---|
| host (всегда) | `insp.hardware`, `insp.os_packages`, `insp.services_processes`, `insp.ports`, `insp.volumes`, `insp.scheduler`, `insp.backup_jobs` | ОС и ресурсы; тома; службы и порты; задания планировщика; где лежат бэкапы (пути — по описанию пользователя и `insp.path_check`) |
| 1c | `insp.1c_structure`, `insp.1c_users` | версия платформы, порты кластера, ИБ и их СУБД; пользователи и роли ИБ, сеансы на момент осмотра; подрядчик — из описания пользователя |
| db | `insp.db_instances` | СУБД, версия, порт, базы; учётка мониторинга и её права (`insp.account_rights`) |
| web | `insp.web_sites`, `insp.web_logs` | сайты и домены, сертификаты; пути журналов; подрядчик — из описания пользователя |
| docker | `insp.docker_containers` | контейнеры, образы, тома; что внутри (СУБД только в контейнере — кандидат `db` со средней уверенностью: вопрос пользователю, следить ли за ней как за СУБД [K §2.2], [T §3.1]) |
| backup | `insp.backup_jobs` | драйвер, репозиторий, расписание, последние запуски |
| unsupported:* | `insp.hardware` (виртуализация) | что видно и не обслуживается |

Правило проверки описания пользователя: каждое утверждение описания, которое можно проверить ручкой (путь, служба, СУБД, число пользователей), проверяется; расхождение «сказано — по факту» — повод для вопроса пользователю (поведение при расхождении в документах не описано — `[предл.]`).

Результаты ручек осмотра pve-01 10.0.1.30 (фикстуры; хоста нет на стендах — тест только node-isolate):

- `insp.hardware` → Debian 12 (Proxmox VE 8.2); 16 CPU, 64 ГБ ОЗУ; GPU не обнаружено; виртуализация — хост (DMI: Supermicro).
- `insp.os_packages` → pve-manager 8.2, qemu-server, openssh-server; docker нет.
- `insp.services_processes` → pvedaemon, pveproxy, pvestatd, ssh; процессы kvm ×2.
- `insp.ports` → 22, 8006.
- `insp.volumes` → local-lvm 1800 ГБ (занято 940); / 100 ГБ.
- `insp.scheduler` → vzdump: суббота 02:00, ВМ 101 и 102, хранилище local; последний запуск 2026-10-24 02:00 — успешно.
- `insp.backup_jobs` → vzdump (встроенный бэкап Proxmox), суббота 02:00; restic/PBS не найдены.
- ВМ (из `insp.services_processes` и конфигураций qemu-server): 101 vm-1c — 8 ядер, 32 ГБ, работает; 102 vm-rds — 8 ядер, 24 ГБ, работает; узел не в кластере.
- `insp.account_rights` → evalbot: sudo на чтение журналов и установку пакетов.
- `insp.1c_structure`, `insp.db_instances`, `insp.web_sites`, `insp.docker_containers` → не найдено.

Дополнительно к чек-листу: hv — пакет pve-manager или роль Hyper-V [T §5]; кластер PVE — `unsupported:<имя>` [T §3.4].

Остаток лимитов на начало теста: ручки осмотра — 40 из 40, `ask-user` — 10 из 10 [AR-32].

## Вход

Поля формы и результаты ручек; истории чата нет.

## Ожидаемое поведение

- `submit` (`filled`), вопросов нет.
- `tags` — ровно {host, hv/proxmox}: пакет pve-manager и службы найдены; кластера нет — `unsupported:*` не нужен.
- `full-desc`: гипервизор Proxmox VE 8.2 с двумя ВМ (1С с MS SQL, терминальный сервер — роли из описания), бэкап ВМ встроенным vzdump по субботам; ресурсы узла.
- `tags-full-desc`: host — ОС, ресурсы, хранилище; hv/proxmox — ВМ с ресурсами и состоянием, local-lvm, vzdump суббота 02:00 для 101 и 102, последний запуск 2026-10-24 успешно.
- Описание проверено: «бэкапы по субботам» — задание vzdump на субботу, расхождений нет.
- Ошибки: теги `1c`, `db/mssql`, `rds` у гипервизора по словам о ВМ; тег `backup` для встроенного vzdump без детекта; вопрос про ВМ, когда всё видно в осмотре.

## Эталон

- Тулза: `submit`; `tags`: {host, hv/proxmox}.
- Чек-лист `full-desc`: Proxmox VE 8.2; ВМ vm-1c (1С с MS SQL) и vm-rds (терминальный сервер); бэкап ВМ по субботам; 16 CPU, 64 ГБ.
- Чек-лист `tags-full-desc`: hv/proxmox — 101 vm-1c 8 ядер 32 ГБ, 102 vm-rds 8 ядер 24 ГБ; local-lvm 1800 ГБ, занято 940; vzdump сб 02:00, последний 2026-10-24 успешно; host — Debian 12, порты 22, 8006.

## Метрики

- Rule-based: `insp-fields` — `tags`: совпадение множеств; `full-desc`: каждый факт чек-листа эталона присутствует и верен (числа — точно, формулировки — по смыслу), выдуманных фактов нет; `tags-full-desc`: по каждому тегу из `tags` описание непустое и содержит факты эталона для тега. `insp-clarify` — вопрос не задан (ложное уточнение — тест не засчитан). Терминальная тулза — `submit`.

## Основания

[T §5] — тег hv с драйвером proxmox; [AR-13] — только SSH; [Q09] — Windows-ВМ. Не обсуждалось: ручки инспектора для hv [Q58]; как сочетаются hv и кластер PVE на одном узле.

Эталон «вопрос не задан» `[предл.]`: по метрике инспектора вопрос не задаётся там, где поле заполняется из осмотра [M]; теги и полные поля пользователь не подтверждает [UC-21], поэтому «подтвердите теги» — ложное уточнение. Предусловия тегов (RAS, учётка мониторинга) после UC-21 отдельным вопросом не подтверждаются; кто и когда ставит тулкиты и предусловия — [Q49].
