# inspector/clarify/03 — учётке не хватает прав: доступ к статистике PostgreSQL

## Сценарий

Для тега db/pg нужна учётка СУБД с правами чтения статистики — предусловие тега. Выполнить его инспектор не может: у учётки подключения нет прав администратора PostgreSQL. Инспектор сообщает, чего не хватает и зачем, и спрашивает, как предоставить доступ.

## Контекст инспектора

Форма: ip 10.0.1.12, ssh_key `eval_ed25519`, description «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; обслуживает франчайзи «1С-Партнёр»; бэкап — pg_dump каждую ночь в /backup/pg; apache публикует данные 1С для обмена с сайтом».

Инвентарь srv-1c 10.0.1.12 (фикстура осмотра 2026-10-08 14:00):

- Ubuntu 22.04.4 LTS, ядро 5.15; виртуализация kvm; 8 vCPU, 32 ГБ ОЗУ; GPU не обнаружено.
- Тома: /dev/sda2 → / 98 ГБ (занято 41 ГБ); /dev/sdb1 → /var/lib/postgresql 492 ГБ (занято 350 ГБ); /dev/sdc1 → /backup 980 ГБ (занято 193 ГБ).
- Активные юниты: srv1cv8-8.3.24.1548@default, postgresql@16-main, apache2, ssh, cron. Бинарь ras есть, служба RAS не запущена.
- Процессы: ragent, rmngr, rphost ×2, postgres (≈ 30), apache2.
- Слушающие порты: 22, 1540, 1541, 1560–1591, 5432, 8080.
- Кластер 1С: реестр кластера содержит ИБ Buh и ZUP; СУБД — PostgreSQL на localhost.
- PostgreSQL 16: базы buh, zup; data_directory /var/lib/postgresql/16/main.
- apache2: конфигурация публикации 1С, Listen 8080, веб-сервис обмена /buh/hs/price.
- cron (root): `0 2 * * * /usr/local/bin/backup_1c.sh` — pg_dump баз buh и zup в /backup/pg; последние файлы buh_2026-10-08.dump (02:14), zup_2026-10-08.dump (02:09).
- Учётка подключения evalbot: sudo только на установку пакетов тулкитов и управление их службами; запуск команд от имени postgres не разрешён. PostgreSQL: локальные подключения — по паролю (scram-sha-256), учётки для мониторинга нет; создать её не удалось: «permission denied» на запуск psql от имени postgres.

Правила detect первой волны (выдержка, [T §3.1, §5], `architecture/tags.md`), которые инспектор применяет к инвентарю:

| Тег | Детект |
|---|---|
| host | всегда |
| db | служба MSSQL*; юнит postgresql* или процесс postgres; mysqld / mariadbd |
| 1c | служба или процесс ragent, юнит srv1cv8*; файлы 1Cv8.1CD без сервера |
| web | nginx / apache / W3SVC с сайтом |
| docker | dockerd или сокет |
| backup | службы Veeam, Кибер Бэкапа, PBS, WSB; репозитории из паспорта |

Уверенность: служба или роль найдена — высокая; только файлы или процесс — средняя; неподдерживаемое — `unsupported:<имя>` без тулкита [T §3.1, §3.4]. Перенос этих правил на инспектора детально не обсуждался (`architecture/inspector-agent.md`).

## Вход

Результат осмотра и ошибка выполнения предусловия для db/pg; истории чата нет.

## Ожидаемое поведение

- Класс `clarify`, поле — учётки и предусловия тега db/pg.
- Сказано: для сбора данных о PostgreSQL нужна учётка с правами только на чтение статистики; создать её не получилось — у учётки подключения нет прав администратора PostgreSQL. Спрошено, как предоставить доступ (например, пользователь создаёт учётку сам или временно расширяет права).
- Без команд и SQL в тексте [UC-03]; без предложения хранить пароль администратора СУБД — секреты не хранятся [K §2.2].
- Остальные теги и поля заполнены без вопросов.
- Ошибки: тег db/pg молча снят; db/pg оставлен без предусловия и без вопроса; текст с `CREATE ROLE` или `pg_hba.conf`; просьба прислать пароль.

## Эталон

- Класс: `clarify`; поле: учётки/предусловия db/pg; ожидаемая суть: не хватает прав для учётки мониторинга PostgreSQL — как её предоставить.

## Метрики

- Rule-based: `insp-clarify` — класс `clarify`, вопрос по ожидаемому полю; вопросов по полям, которые заполняются из осмотра, нет.
- LLM-judge: `judge-insp-question` — (1) язык понятен пользователю: нет имён источников, ручек, шаблонов, классов, `unsupported:*`; имя тега допустимо, если вопрос понятен и без знания модели тегов [UC-08]; (2) суть донесена верно — спрошено именно то, чего не хватает для поля. Тест засчитан при обоих.

## Основания

Исключение «учётка агента без нужных прав» [K §2.2], [UC-17]; предусловия тегов (pg_monitor для PG) — [T §5], в контракт не выносятся [UC-16]; «справочные пояснения не содержат команд» [UC-03]. Не обсуждалось: как пользователь передаёт учётку и где она хранится — [Q10].

## Данные

Форма, фикстура инвентаря с ограниченной учёткой, ошибка предусловия, эталон.
