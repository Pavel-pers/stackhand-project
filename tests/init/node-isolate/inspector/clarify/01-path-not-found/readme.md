# inspector/clarify/01 — путь бэкапа из описания не найден

## Сценарий

В описании из формы бэкап лежит в /backup, а на сервере такого каталога нет: ночное задание складывает дампы на сетевой том /mnt/nas/pg. Инспектор не должен молча заменить слова пользователя фактом или наоборот — он задаёт вопрос по полю «пути бэкапов» и опирается на то, что нашёл.

## Контекст инспектора

Форма: ip 10.0.1.12, ssh_key `eval_ed25519`, description «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; обслуживает франчайзи «1С-Партнёр»; бэкап — pg_dump каждую ночь в /backup; apache публикует данные 1С для обмена с сайтом».

Инвентарь srv-1c 10.0.1.12 (фикстура осмотра 2026-10-08 14:00):

- Ubuntu 22.04.4 LTS, ядро 5.15; виртуализация kvm; 8 vCPU, 32 ГБ ОЗУ; GPU не обнаружено.
- Тома: /dev/sda2 → / 98 ГБ (занято 41 ГБ); /dev/sdb1 → /var/lib/postgresql 492 ГБ (занято 350 ГБ); сетевой том nas-01:/pg → /mnt/nas/pg (NFS, 2 ТБ, занято 640 ГБ). Каталога /backup нет.
- Активные юниты: srv1cv8-8.3.24.1548@default, postgresql@16-main, apache2, ssh, cron. Бинарь ras есть, служба RAS не запущена.
- Процессы: ragent, rmngr, rphost ×2, postgres (≈ 30), apache2.
- Слушающие порты: 22, 1540, 1541, 1560–1591, 5432, 8080.
- Кластер 1С: реестр кластера содержит ИБ Buh и ZUP; СУБД — PostgreSQL на localhost.
- PostgreSQL 16: базы buh, zup; data_directory /var/lib/postgresql/16/main.
- apache2: конфигурация публикации 1С, Listen 8080, веб-сервис обмена /buh/hs/price.
- cron (root): `0 2 * * * /usr/local/bin/backup_1c.sh` — pg_dump баз buh и zup в /mnt/nas/pg; последние файлы /mnt/nas/pg/buh_2026-10-08.dump (02:14), zup_2026-10-08.dump (02:09).
- Учётка подключения evalbot: sudo на установку тулкитов и выполнение предусловий.

Правила detect первой волны (выдержка, [T §3.1, §5], `architecture/tags.md`), которые инспектор применяет к инвентарю:

| Тег | Детект |
|---|---|
| host | всегда |
| db | служба MSSQL*; юнит postgresql* или процесс postgres; mysqld / mariadbd |
| 1c | служба или процесс ragent, юнит srv1cv8*; файлы 1Cv8.1CD без сервера |
| web | nginx / apache / W3SVC с сайтом |
| docker | dockerd или сокет |
| backup | службы Veeam, Кибер Бэкапа, PBS, WSB; репозитории из паспорта |

Уверенность: служба или роль найдена — высокая; только файлы или процесс — средняя; неподдерживаемое — `unsupported:<имя>` без тулкита [T §3.1, §3.4]. Перенос этих правил на инспектора детально не обсуждался (`architecture/inspector-agent.md`).

## Вход

Результат осмотра и описание из формы; истории чата нет.

## Ожидаемое поведение

- Класс `clarify`, поле — пути бэкапов.
- В вопросе: в описании указан /backup, такого каталога нет; задание планировщика пишет дампы в /mnt/nas/pg; вопрос — считать ли местом бэкапов /mnt/nas/pg. Пример: «В описании бэкап хранится в /backup, но такого каталога на сервере нет; ночное задание сохраняет дампы в /mnt/nas/pg. Это и есть место бэкапов?»
- Остальные поля не вызывают вопросов: теги {host, 1c/cluster, db/pg, web/apache} с высокой уверенностью, ИБ и порты — из осмотра.
- Ошибки: путь /backup записан в описание как факт; /mnt/nas/pg записан молча без отметки расхождения; вопрос без найденного варианта («где лежат бэкапы?»); вопросы о тегах.

## Эталон

- Класс: `clarify`; поле: пути бэкапов; ожидаемая суть: расхождение /backup (сказано) и /mnt/nas/pg (найдено), просьба подтвердить путь.
- Других вопросов нет.

## Метрики

- Rule-based: `insp-clarify` — класс `clarify`, вопрос по ожидаемому полю; вопросов по полям, которые заполняются из осмотра, нет.
- LLM-judge: `judge-insp-question` — (1) язык понятен пользователю: нет имён источников, ручек, шаблонов, классов, `unsupported:*`; имя тега допустимо, если вопрос понятен и без знания модели тегов [UC-08]; (2) суть донесена верно — спрошено именно то, чего не хватает для поля. Тест засчитан при обоих.

## Основания

Исключение «Инспектору не хватает данных: путь из описания не найден» [K §2.2], [UC-17]; пример вопроса с найденными вариантами — [K §2.2] («найдены D:\1C\bases и E:\bases — какой верный?»); расхождения «сказано — по факту» — [D §1.1], [T §9.1 X19].

## Данные

Форма, фикстура инвентаря (вариант с NAS), правила detect, эталон поля и сути вопроса.
