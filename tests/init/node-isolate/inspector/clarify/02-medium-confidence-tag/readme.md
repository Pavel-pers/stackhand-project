# inspector/clarify/02 — тег-кандидат со средней уверенностью: postgres в контейнере

## Сценарий

На acc-01 процессы postgres видны в списке процессов хоста, но принадлежат контейнеру микросервисов; службы СУБД на хосте нет. Кандидат `db/pg` со средней уверенностью — инспектор спрашивает пользователя, а не решает сам (уверенность после перехода на ручки инспектора — [Q46]).

## Контекст инспектора

Форма «Добавить сервер»: `conn-ip` 10.0.1.13, `conn-ssh-key` `eval_ed25519`, `description` «Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU».

Ручки инспектора — one-shot осмотра [AR-30]; каталог — предложение тестов до [Q58]:

| Ручка | Что возвращает |
|---|---|
| `insp.hardware` | CPU, память, GPU, диски, виртуализация (DMI) |
| `insp.os_packages` | ОС, ядро, установленные пакеты по категориям |
| `insp.services_processes` | активные юниты и процессы |
| `insp.ports` | слушающие порты |
| `insp.volumes` | тома и точки монтирования, сетевые тома |
| `insp.scheduler` | задания cron и systemd-таймеры с командами |
| `insp.path_check(path)` | существует ли путь, что в нём (размер, свежие файлы) |
| `insp.1c_structure` | кластер 1С: версия платформы, порты, реестр ИБ, СУБД каждой ИБ |
| `insp.1c_users` | «сканер пользователей»: учётки и роли в ИБ, активные сеансы на момент осмотра |
| `insp.db_instances` | СУБД: версия, порт, базы, доступ учётки мониторинга |
| `insp.web_sites` | веб-сервер: сайты, домены, корни, сертификаты |
| `insp.web_logs` | пути журналов веб-сервера и их свежесть |
| `insp.docker_containers` | контейнеры, образы, тома, доступ к GPU |
| `insp.backup_jobs` | задания и репозитории резервного копирования (restic, pg_dump, vzdump…) |
| `insp.account_rights` | права учётки подключения: sudo, доступ к СУБД — только чтением |
| `ask-user(question)` | вопрос пользователю (≤ 10 на сессию) |
| `submit(full-desc, tags, tags-full-desc)` | терминальная сдача артефакта куратору |

Лимит — 40 вызовов ручек осмотра на сессию [AR-32]; инспектор видит остаток.

Чек-лист инспектора (в промпте; предложение тестов до [Q58]) — какие ручки попробовать для составления информации по тегу; `host` — всегда:

| Тег | Обязательные ручки | Что должно попасть в `tags-full-desc` |
|---|---|---|
| host (всегда) | `insp.hardware`, `insp.os_packages`, `insp.services_processes`, `insp.ports`, `insp.volumes`, `insp.scheduler`, `insp.backup_jobs` | ОС и ресурсы; тома; службы и порты; задания планировщика; где лежат бэкапы (пути — по описанию пользователя и `insp.path_check`) |
| 1c | `insp.1c_structure`, `insp.1c_users` | версия платформы, порты кластера, ИБ и их СУБД; пользователи и роли ИБ, сеансы на момент осмотра; подрядчик — из описания пользователя |
| db | `insp.db_instances` | СУБД, версия, порт, базы; учётка мониторинга и её права (`insp.account_rights`) |
| web | `insp.web_sites`, `insp.web_logs` | сайты и домены, сертификаты; пути журналов; подрядчик — из описания пользователя |
| docker | `insp.docker_containers` | контейнеры, образы, тома; что внутри (СУБД только в контейнере — кандидат `db` со средней уверенностью: вопрос пользователю, следить ли за ней как за СУБД [K §2.2], [T §3.1]) |
| backup | `insp.backup_jobs` | драйвер, репозиторий, расписание, последние запуски |
| unsupported:* | `insp.hardware` (виртуализация) | что видно и не обслуживается |

Правило проверки описания пользователя: каждое утверждение описания, которое можно проверить ручкой (путь, служба, СУБД, число пользователей), проверяется; расхождение «сказано — по факту» — повод для вопроса пользователю (поведение при расхождении в документах не описано — `[предл.]`).

Результаты ручек осмотра acc-01 10.0.1.13 (фикстуры):

- `insp.hardware` → Ubuntu 22.04.4 LTS; 8 vCPU, 32 ГБ ОЗУ; GPU NVIDIA T4 16 ГБ (драйвер 535); диск 200 ГБ.
- `insp.os_packages` → docker-ce 24, containerd, nvidia-driver-535, openssh-server, cron; пакетов СУБД на хосте нет.
- `insp.services_processes` → активные юниты: docker, containerd, ssh, cron; процессы dockerd, containerd-shim ×5, python (acc-api, acc-worker), acc-ocr, redis-server, postgres ×9 — redis и postgres принадлежат контрольной группе контейнеров docker.
- `insp.ports` → 22, 8080 (docker-proxy).
- `insp.volumes` → / 200 ГБ (занято 74); сетевых томов нет.
- `insp.scheduler` → таймеры системы; собственных заданий нет.
- `insp.docker_containers` → acc-api (порт 8080), acc-worker, acc-ocr (доступ к GPU), redis, postgres (том /srv/acc/pgdata); образы из частного реестра.
- `insp.db_instances` → служб СУБД на хосте не найдено; процессы postgres принадлежат контейнеру postgres.
- `insp.backup_jobs` → заданий бэкапа нет.
- `insp.account_rights` → evalbot: sudo на чтение журналов и установку пакетов; доступ к docker — группа docker.

Остаток лимитов на начало теста: ручки осмотра — 40 из 40, `ask-user` — 10 из 10 [AR-32].

## Вход

Поля формы и результаты ручек; истории чата нет.

## Ожидаемое поведение

- `ask-user` (`clarify`), поле — теги (кандидат db/pg).
- Кандидаты с высокой уверенностью — host и docker — вопросов не вызывают.
- Вопрос объясняет находку человеческими словами: база PostgreSQL работает внутри контейнера микросервисов, отдельной службы СУБД нет; нужно ли следить за ней как за отдельной СУБД.
- GPU и контейнер распознавания отражены в `tags-full-desc` без вопросов.
- Ошибки: `submit` с `db/pg` молча; `db/pg` отброшен молча; вопрос «подтвердите теги host, docker, db»; формулировка вида «кандидат db/pg, confidence medium».

## Эталон

- Тулза: `ask-user`; поле: теги; ожидаемая суть: PostgreSQL найден только внутри контейнера — следить ли за ним как за СУБД.
- Предварительный набор тегов без ответа: {host, docker} + открытый кандидат db/pg.

## Метрики

- Rule-based: `insp-clarify` — тулза `ask-user` (класс `clarify`), вопрос по ожидаемому полю; вопросов по полям, которые заполняются из осмотра, нет; `submit` до ответа не вызван.
- LLM-judge: `judge-insp-question` — (1) язык понятен пользователю: нет имён ручек, классов, `unsupported:*`; имя тега допустимо, если вопрос понятен и без знания модели тегов [UC-08]; (2) суть донесена верно — спрошено именно то, чего не хватает для поля. Тест засчитан при обоих.

## Основания

Средняя уверенность — «только файлы или процесс» [T §3.1]; «тег-кандидат со средней уверенностью → вопрос» [K §2.2]; [Q46].
