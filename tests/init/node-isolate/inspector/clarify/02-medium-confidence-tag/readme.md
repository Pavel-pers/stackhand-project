# inspector/clarify/02 — тег-кандидат со средней уверенностью: postgres в контейнере

## Сценарий

На acc-01 процессы postgres видны в списке процессов хоста, но принадлежат контейнеру микросервисов; юнита PostgreSQL нет. По правилам detect это кандидат `db/pg` со средней уверенностью — инспектор спрашивает пользователя, а не решает сам.

## Контекст инспектора

Форма: ip 10.0.1.13, ssh_key `eval_ed25519`, description «Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU».

Инвентарь acc-01 10.0.1.13 (фикстура осмотра):

- Ubuntu 22.04.4 LTS; 8 vCPU, 32 ГБ ОЗУ; GPU NVIDIA T4 16 ГБ (драйвер 535); / 200 ГБ (занято 74 ГБ).
- Активные юниты: docker, containerd, ssh, cron. Юнита postgresql нет.
- Контейнеры: acc-api (порт 8080), acc-worker, acc-ocr (с доступом к GPU), redis, postgres (том /srv/acc/pgdata).
- Процессы: dockerd, containerd-shim ×5, python (acc-api, acc-worker), acc-ocr, redis-server, postgres ×9 — процессы redis и postgres принадлежат контрольной группе контейнеров docker.
- Учётка подключения evalbot: sudo на установку тулкитов и выполнение предусловий.

Правила detect первой волны (выдержка, [T §3.1, §5], `architecture/tags.md`), которые инспектор применяет к инвентарю:

| Тег | Детект |
|---|---|
| host | всегда |
| db | служба MSSQL*; юнит postgresql* или процесс postgres; mysqld / mariadbd |
| 1c | служба или процесс ragent, юнит srv1cv8*; файлы 1Cv8.1CD без сервера |
| web | nginx / apache / W3SVC с сайтом |
| docker | dockerd или сокет |
| backup | службы Veeam, Кибер Бэкапа, PBS, WSB; репозитории из паспорта |

Уверенность: служба или роль найдена — высокая; только файлы или процесс — средняя; неподдерживаемое — `unsupported:<имя>` без тулкита [T §3.1, §3.4]. Перенос этих правил на инспектора детально не обсуждался (`architecture/inspector-agent.md`).

## Вход

Результат осмотра и описание из формы; истории чата нет.

## Ожидаемое поведение

- Класс `clarify`, поле — теги (кандидат db/pg).
- Кандидаты с высокой уверенностью — host и docker — вопросов не вызывают.
- Вопрос объясняет находку человеческими словами: база PostgreSQL работает внутри контейнера микросервисов, отдельной службы СУБД нет; нужно ли следить за ней как за отдельной СУБД.
- GPU и контейнер распознавания документов отражены в описании без вопросов.
- Ошибки: `db/pg` добавлен молча; `db/pg` отброшен молча; вопрос «подтвердите теги host, docker, db»; формулировка вида «кандидат db/pg, confidence medium».

## Эталон

- Класс: `clarify`; поле: теги; ожидаемая суть: PostgreSQL найден только как процесс внутри контейнера — следить ли за ним как за СУБД.
- Предварительный набор тегов без ответа: {host, docker} + открытый кандидат db/pg.

## Метрики

- Rule-based: `insp-clarify` — класс `clarify`, вопрос по ожидаемому полю; вопросов по полям, которые заполняются из осмотра, нет.
- LLM-judge: `judge-insp-question` — (1) язык понятен пользователю: нет имён источников, ручек, шаблонов, классов, `unsupported:*`; имя тега допустимо, если вопрос понятен и без знания модели тегов [UC-08]; (2) суть донесена верно — спрошено именно то, чего не хватает для поля. Тест засчитан при обоих.

## Основания

Средняя уверенность — «только файлы или процесс» [T §3.1]; «тег-кандидат со средней уверенностью → вопрос» [K §2.2]. Видна ли пользователю сама уверенность — [Q46]: эталон не требует слова «уверенность», требует объяснения находки.

## Данные

Форма, фикстура инвентаря acc-01, правила detect, эталон.
