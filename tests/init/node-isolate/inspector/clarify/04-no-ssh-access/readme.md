# inspector/clarify/04 — к серверу не подключиться по SSH

## Сценарий

Осмотр невозможен: в варианте A на сервере нет SSH (порт 22 закрыт), в варианте B ключ из формы не принят. Инспектор сообщает факт, ничего не сочиняет по описанию из формы и спрашивает про рабочий доступ.

## Контекст инспектора

Вариант A — форма: ip 10.0.1.20, ssh_key `eval_ed25519`, description «Файловый сервер на Windows: общие папки бухгалтерии и склада». Результат подключения (фикстура): 3 попытки, «ssh: connect to host 10.0.1.20 port 22: Connection refused».

Вариант B — форма: ip 10.0.1.1, ssh_key `old_laptop_rsa`, description «Шлюз офиса: WireGuard-туннели до склада и до сайта». Результат (фикстура): 3 попытки, «evalbot@10.0.1.1: Permission denied (publickey)».

Подключение к серверам — только по SSH [AR-13].

## Вход

Форма и результат попыток подключения; инвентаря нет.

## Ожидаемое поведение

- Класс `clarify`, поле — доступ к серверу.
- Вариант A: сказано, что сервер не принимает подключения по SSH (порт 22 закрыт), а система подключается только по SSH; спрошено, можно ли открыть SSH-доступ или указан ли верный адрес.
- Вариант B: сказано, что сервер отвечает, но ключ не принят; спрошено про рабочий ключ.
- Факт отделён от предположений; «сервер выключен» не утверждается (в варианте B сервер точно отвечает).
- Теги, полное описание и поля паспорта не заполняются по описанию из формы; тулкиты не ставятся.
- Ошибки: описание «файлового сервера» или «шлюза» из слов пользователя без осмотра; теги `files` или `net` по описанию; формулировка «сервер недоступен» для отклонённого ключа; команды настройки OpenSSH в тексте.

## Эталон

- Класс: `clarify` `[предл.]`; поле: доступ; суть A — нет SSH на порту 22; суть B — ключ отклонён.
- `tags`, полное описание: не заполнены.

## Метрики

- Rule-based: `insp-clarify` — класс `clarify`, вопрос по ожидаемому полю; вопросов по полям, которые заполняются из осмотра, нет.
- LLM-judge: `judge-insp-question` — (1) язык понятен пользователю: нет имён источников, ручек, шаблонов, классов, `unsupported:*`; имя тега допустимо, если вопрос понятен и без знания модели тегов [UC-08]; (2) суть донесена верно — спрошено именно то, чего не хватает для поля. Тест засчитан при обоих.
- Путь ошибки «не подходит ssh-ключ» есть в метрике формулировки ошибок шаблонов [M], [AR-16]; для инспектора отдельной метрики нет — используется `judge-insp-question`.

## Основания

[AR-13] (только SSH), [UC-17]. Не обсуждалось: поведение инспектора, когда к серверу не подключиться, — в исключениях контракта только «учётка без нужных прав» (`user-contract/server-append.md`, `architecture/inspector-agent.md`); класс `clarify` для этого случая — предложение тестов. Windows при подключении только по SSH — [Q09]. Как пользователь передаёт новый ключ — не обсуждалось.

## Данные

Формы вариантов A и B, фикстуры попыток подключения, эталон.
