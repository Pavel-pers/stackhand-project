# inspector/answer-processing/01 — ответ пользователя учтён, остальное не изменилось

## Сценарий

Продолжение inspector/clarify/01: инспектор спросил про место бэкапов, пользователь ответил. Проверяется обработка ответа: поле заполнено по ответу, остальные поля остались как были, вопрос не повторяется.

## Контекст инспектора

Как в inspector/clarify/01 (форма с /backup, инвентарь с сетевым томом /mnt/nas/pg). История чата:

- Инспектор: «В описании бэкап хранится в /backup, но такого каталога на сервере нет; ночное задание сохраняет дампы в /mnt/nas/pg. Это и есть место бэкапов?»

## Вход

Ответ пользователя: «Да, /mnt/nas/pg — это смонтированный NAS, туда и складываем».

## Ожидаемое поведение

- Класс `filled`.
- Поле «пути бэкапов» — /mnt/nas/pg (сетевое хранилище nas-01); в полном описании задание бэкапа указано с этим путём.
- Остальные поля совпадают с эталоном inspector/filled/01, кроме тома /backup (его нет) и сетевого тома /mnt/nas/pg (он есть): теги, ИБ, порты, версии не изменились.
- Повторного вопроса о пути нет; новых вопросов нет.
- Ошибки: в описании остался /backup; ответ записан дословно вместо пути; изменены поля, которых ответ не касался.

## Эталон

- Класс: `filled`; поле «пути бэкапов» = /mnt/nas/pg; `tags` = {host, 1c/cluster, db/pg, web/apache}; прочие поля — по чек-листу inspector/filled/01 с заменой тома /backup на сетевой том /mnt/nas/pg.

## Метрики

- Rule-based: `insp-fields` (поле по ответу, остальные без изменений), `insp-clarify` (повторного вопроса нет).

## Основания

«Описание заполняется после ответа» [K §2.2]. Повторный осмотр хоста внутри сессии после ответа — [Q43]: тест его не требует.

## Данные

Контекст inspector/clarify/01, история чата, ответ пользователя, эталон полей.
