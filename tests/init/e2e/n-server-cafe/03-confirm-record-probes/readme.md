# init/e2e/n-server-cafe/03 — такт 3: подтверждение — запись о сервере и маршрутизация по адресу

Сценарий плана: **IN-1b** — N серверов кафе + ещё один — такт 2: обработка ответа, корректный результат. Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана IN-1b, итог: пользователь подтверждает карточку; запись о сервере расходится по памяти системы, после чего оркестратор должен различать пять одинаковых серверов по адресу, и агент нового кафе — отвечать на запросы; ради этого куратор и нужен [UC-15].

1. Состояние после такта 2: карточка с `short-desc` «Сервер кафе в ТЦ «Авиапарк» (Ходынский бульвар, 4): меню, заказы и экран кухни; PostgreSQL и сервисы в Docker» и `server-name` в транскрипте зафиксирована тестом.
2. Пользователь подтверждает.
3. Пробы — две новые сессии (каждая — свой такт):
   - «Сколько места осталось на сервере кафе в Авиапарке?»
   - «Сколько места осталось на сервере кафе на Покровке?»

## Стенд

Стенд K — сеть кафе (подробно — `init/README.md`, раздел «Стенд K»): в каждом кафе свой мини-сервер, собранный из одного образа, — одинаковые ОС, службы, теги и структура; кафе различаются только адресом. Серверы кафе cafe-01…cafe-04 (10.30.1.10…10.30.4.10) и сервер офиса office-01 (10.30.0.10) уже добавлены засевом — записи о серверах в памяти системы, логгеры на них не установлены (искусственное состояние: сама система до него не доходит); новый сервер cafe-05 (10.30.5.10) — такой же мини-сервер, добавляется в тесте, логгеры ставятся при подтверждении. Подключение — по SSH через VPN сети; ключ системы `eval_ed25519` принят на всех хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — снапшот после такта 2 с зафиксированной карточкой.

## Вход

Подтверждение (шаг 2); две пробы (шаг 3) в новых сессиях.

## Цепочка

- Подтверждение → память: запись cafe-05 [AR-29]; `conn-ip`, название, теги, `short-desc` с адресом — в контекст оркестратора; `full-desc`, `tags-full-desc` — агенту cafe-05; логгеры на cafe-05 ([Q49]).
- Пробы: оркестратор по адресу в кратком описании выбирает cafe-05 и cafe-03 без уточнений; запрос агенту cafe-05 выполняется по его полям и ручкам; для cafe-03 проверяется только маршрут — логгеров на засеянных серверах нет, агент вернёт ошибку ручки, итоговый текст этой пробы не оценивается.
- Признаки разрыва: записи нет или в ней поля не те; в контексте оркестратора нет адреса; проба уходит не туда или требует уточнения; агент cafe-05 эскалировал `wrong_addressee` или `no_template`.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Запись cafe-05: `tags` {host, db/pg, docker}; `short-desc` с адресом; `tags-short-desc` по трём тегам; `full-desc`, `tags-full-desc` — как у остальных кафе.
- Пробы: первый запрос — `delegate` cafe-05 (10.30.5.10) без уточнений, агент вызвал `host.volumes_usage` (ответ по числам не оценивается — данные только начали копиться); второй — `delegate` cafe-03: проверяется только `delegate_to`.
- Ошибки: после добавления вопрос о «кафе в Авиапарке» уходит не туда или требует уточнения; cafe-05 нет в контексте; описания других кафе изменены.

## Эталон

- Память: запись cafe-05 по эталону `init/README.md`, «Стенд K»; контекст оркестратора — шесть серверов.
- Пробы: `delegate_to` = cafe-05 и cafe-03; для пробы cafe-05 — вопросов 0, агент `answer`; для пробы cafe-03 класс оркестратора после ответа агента не оценивается.

## Метрики

- Rule-based: `e2e-expected-state` (rule-based по журналу и состоянию системы): цепочка — инспектор (ручки ≤ 40, вопросы ≤ 10), затем куратор (QA ≤ 5, confirmation ≤ 3), затем карточка подтверждения с `short-desc` и `server-name` [UC-21]; вопросов пользователю ровно столько, сколько в эталоне; после подтверждения запись о сервере сохранена и совпадает с эталоном по полям (`insp-fields` для полей инспектора, `cur-fields` для полей куратора [AR-29]); в контексте оркестратора появились `conn-ip`, `server-name`, `tags`, `short-desc` [AR-22] (`tags-short-desc` — [Q56]), `full-desc` и `tags-full-desc` — только у агента сервера [UC-04]; логгеры стоят ровно для тегов записи (для `unsupported:*` — нет) — [Q49] `[предл.]`; других изменений на хосте нет [UC-06], [UC-07]; пользователю не показаны разделение записи и заключение куратора [UC-14]. На стенде K `insp-fields` — теги и `tags-full-desc` cafe-05 (эталон — `init/README.md`, «Стенд K»).
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: `orch-agent-choice` (пробы). Узлы — `orchestrator/delegated/11`.
