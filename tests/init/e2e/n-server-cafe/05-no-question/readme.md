# init/e2e/n-server-cafe/05 — такт 1: сервер кафе без вопроса о различиях

Сценарий плана: **IN-1a** — N серверов кафе + ещё один — такт 1: серверы получились неразличимы, R&B — вопрос задан, LLM — корректность вопроса. Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Обратная сторона проверки «R&B: вопрос задан?» (пункт IN-1a): там, где новое кафе уже отличается от остальных, вопрос о различиях — ложное уточнение, и такт должен дойти до карточки подтверждения без вопросов.

Вариант A — N = 4, пользователь сразу указал адрес: description «Сервер кафе в ТЦ «Авиапарк», Ходынский бульвар, 4: меню, заказы и экран кухни; PostgreSQL и сервисы в Docker».

Вариант B — первое кафе: в системе только office-01; description «Сервер кафе: меню, заказы и экран кухни; PostgreSQL и сервисы в Docker» — сравнивать не с чем, кроме сервера офиса, а он описан иначе.

Такт: форма → инспектор → куратор → `confirmation`. Подтверждение и проба — `n-server-cafe/06`.

## Стенд

Стенд K — сеть кафе (подробно — `init/README.md`, раздел «Стенд K»): в каждом кафе свой мини-сервер, собранный из одного образа, — одинаковые ОС, службы, теги и структура; кафе различаются только адресом. Серверы кафе cafe-01…cafe-04 (10.30.1.10…10.30.4.10) и сервер офиса office-01 (10.30.0.10) уже добавлены засевом — записи о серверах в памяти системы, логгеры на них не установлены (искусственное состояние: сама система до него не доходит); новый сервер cafe-05 (10.30.5.10) — такой же мини-сервер, добавляется в тесте; логгеры на нём ставит инспектор в ходе добавления (design doc 2.2). Подключение — по SSH через VPN сети; ключ системы `eval_ed25519` принят на всех хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Вариант A — засеяны office-01 и cafe-01…cafe-04; вариант B — засеян только office-01.

## Вход

Форма по варианту. Такт заканчивается карточкой подтверждения.

## Цепочка

- Форма → инспектор: осмотр ручками; `submit` без вопросов.
- Артефакт и память → куратор: `short-desc` по `full-desc`; сравнение с памятью не даёт конфликта — адрес различает (A) или сравнивать не с чем, кроме сервера офиса с другой ролью (B); `confirmation`.
- Признаки разрыва: любой вопрос пользователю; `QA` с office-01 из-за общего тега db/pg; адрес из формы потерян в `short-desc`; `deny`.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Вопросов пользователю — 0; куратор `confirmation` (`consistent`); вариант A — `short-desc` сохраняет адрес из формы; вариант B — `short-desc` по `full-desc`; office-01 не мешает (другая роль).
- Инспектор: теги и `tags-full-desc` — как у остальных кафе.
- Ошибки: вопрос «чем отличается» при указанном адресе; в варианте B — конфликт с office-01.

## Эталон

- Цепочка: инспектор `submit`, куратор `confirmation`; вопросов — 0; память до подтверждения не изменена.
- Вариант A: `short-desc` содержит («Авиапарк» или «Ходынск») и «кафе».

## Метрики

- Rule-based: `cur-conflict` («вопрос задан?» = нет — R&B из плана), `insp-clarify`, `cur-fields` `[предл.]`, `e2e-expected-state` (карточка показана, память не изменена). На стенде K `insp-fields` — теги и `tags-full-desc` cafe-05.
- LLM-judge: `judge-cur-summary` `[предл.]` — `server-name`, `short-desc`, `tags-short-desc`, составленные куратором (критерии — README, «Метрики»; узловые тесты — `curator/summary/*`).
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: узлы — `curator/consistent/03`, `curator/consistent/01`.
