# init/e2e/difference/03 — обработка ответа: невменяемый ответ

## Сценарий

Пункт плана «Обработка ответа → невменяемый». Продолжение difference/02 (вариант A): куратор спросил, чем 10.0.1.14 отличается от srv-1c. Пользователь отвечает так, что различий не извлечь, или уводит разговор в сторону.

Вариант A — «ну да».

Вариант B — «ыпаы».

Вариант C — «а сколько места осталось на srv-1c?» (рабочий запрос внутри чата добавления).

Вариант D — «не знаю, сами разберитесь».

После ответа куратор реагирует; затем пользователь даёт нормальный ответ из difference/04, и добавление завершается.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс srv-1c-2 10.0.1.14 и win-01 10.0.1.20; тулкиты не установлены; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — как после шага 3 difference/02, вариант A.

## Вход

Ответ пользователя по варианту; затем нормальный ответ из difference/04.

## Ожидаемое поведение

- Конфликт остаётся: класс куратора `conflict`, серверы {10.0.1.14, srv-1c}; краткое описание не изменено ответом.
- Куратор переспрашивает конкретнее, с подсказкой, какие отличия нужны (назначение: рабочий, тестовый, резервный; базы; кто работает).
- Вариант C: рабочий запрос в чате добавления не выполняется — одна сессия, одно добавление [K §2.3]; куратор говорит, что сначала нужно закончить добавление, и повторяет вопрос.
- Вариант D: допустимо объяснить, зачем нужно различие, и предложить вариант по осмотру как вопрос («по данным осмотра на сервере базы buh_dev и zup_dev — это тестовый сервер?»), но не записывать его как факт без подтверждения.
- После нормального ответа — как в difference/04.
- Ошибки: «ну да» или «ыпаы» в кратком описании; `consistent` с двумя одинаковыми описаниями; куратор записал придуманное отличие; в чате добавления выполнен запрос о дисках srv-1c.

## Эталон

- После ответа A–D: `conflict`, {10.0.1.14, srv-1c}, краткое описание прежнее, карточка не показана.
- После нормального ответа: `consistent` (эталон difference/04).

## Метрики

- Rule-based: `cur-conflict` после каждого ответа; `e2e-expected-state` (в варианте C делегаций агентам нет).
- LLM-judge: `judge-cur-question` для повторного вопроса — три критерия, как в difference/02.

## Основания

Не обсуждалось: может ли куратор переспрашивать, что при отказе пользователя уточнять (`architecture/curator-agent.md`). Эталон «конфликт остаётся, переспросить» — предложение тестов `[предл.]`, следует назначению куратора [UC-15]. Одна сессия — одно добавление [K §2.3].

## Данные

Состояние после difference/02, ответы A–D, нормальный ответ, эталон, рубрика judge.
