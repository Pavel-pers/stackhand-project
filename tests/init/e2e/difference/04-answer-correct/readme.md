# init/e2e/difference/04 — обработка ответа: верный итог

## Сценарий

Пункт плана «Обработка ответа → correct result». Продолжение difference/02 (вариант A): пользователь объясняет, чем серверы отличаются. Уточнение должно попасть в краткое описание, после подтверждения JSON оркестратор должен различать два сервера 1С — ради этого куратор и нужен [UC-15].

1. Ответ пользователя: «Это тестовый сервер франчайзи: копии Бухгалтерии и ЗУП для доработок, бухгалтеры там не работают».
2. Куратор обновляет краткое описание; пользователь видит карточку JSON и подтверждает.
3. Проверка различимости — две новые сессии:
   - «Сколько места осталось на рабочем сервере 1С, где сидит бухгалтерия?»
   - «Сколько места на тестовом сервере 1С франчайзи?»

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс srv-1c-2 10.0.1.14 и win-01 10.0.1.20; тулкиты не установлены; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — как после шага 3 difference/02, вариант A.

## Вход

Ответ пользователя (шаг 1), подтверждение карточки (шаг 2), два запроса (шаг 3).

## Ожидаемое поведение

- Куратор: класс `consistent` после ответа.
- Краткое описание 10.0.1.14 различимо с srv-1c: тестовый сервер франчайзи, копии Бухгалтерии и ЗУП для доработок, бухгалтеры не работают.
- Не изменилось: краткое описание srv-1c; теги и полное описание srv-1c-2, собранные инспектором до вопроса куратора.
- Карточка: `tags` {host, 1c/cluster, db/pg}; полное описание — ИБ buh_dev и zup_dev, бэкапов нет (по ответу пользователя инспектору); подрядчик «1С-Партнёр».
- Шаг 3: первый запрос делегирован srv-1c, второй — srv-1c-2 (10.0.1.14); уточнений не требуется.
- Ошибки: ответ вставлен дословно с разговорными оборотами; изменено описание srv-1c; после добавления вопрос о «рабочем сервере 1С» уходит на 10.0.1.14 или требует уточнения.

## Эталон

- Куратор: `consistent`; краткое описание 10.0.1.14 содержит «тест» и «франчайзи» или «доработ», содержит «1С».
- Шаг 3: `delegate_to` = srv-1c и 10.0.1.14 соответственно.

## Метрики

- Rule-based: `cur-conflict` (`consistent`), `orch-agent-choice` (шаг 3), `e2e-expected-state` (rule-based по журналу и состоянию системы): JSON сохранён после подтверждения и совпадает с эталоном по полям (`insp-fields` для полей инспектора, правило краткого описания для куратора); в документе контекста оркестратора появились ip, теги и краткое описание, полное описание — только у агента сервера [UC-04]; тулкиты стоят ровно для подтверждённых тегов (для `unsupported:*` — нет); других изменений на хосте, кроме тулкитов и предусловий, нет [UC-06], [UC-07]; пользователю не показаны smoke-проверка, заключение куратора и разделение JSON [UC-14].

## Основания

[UC-15] — уточнение, чтобы в дальнейшем различать серверы; «уточнение попадает в краткое описание» — текст K, не оспорен; маршрутизация по тегам и краткому описанию [UC-04].

## Данные

Состояние после difference/02, ответ, запросы шага 3, эталон.
