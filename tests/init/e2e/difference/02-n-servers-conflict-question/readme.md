# init/e2e/difference/02 — случай N серверов: куратор спрашивает, чем отличается

## Сценарий

Пункт плана «Difference? — LLM: correct question; R&B: question asked?», сторона «N servers». В системе уже есть серверы; добавляется srv-1c-2 — копия баз для франчайзи, описанная теми же словами, что рабочий srv-1c. Куратор должен задать вопрос о различиях (rule-based: вопрос задан) и задать его правильно (judge).

Вариант A — N = 4: в системе web-01, srv-1c, acc-01, gw-01 (подтверждённые JSON стенда M).

Вариант B — N = 1: в системе только srv-1c.

1. Форма: ip 10.0.1.14, ssh_key `eval_ed25519`, description «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL».
2. Инспектор осматривает srv-1c-2. На его вопросы пользователь отвечает по сценарию: о бэкапах — «бэкапов на нём нет»; о подрядчике — «тот же, „1С-Партнёр“».
3. Куратор сравнивает краткое описание с уже добавленными и задаёт вопрос.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс srv-1c-2 10.0.1.14 и win-01 10.0.1.20; тулкиты не установлены; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

srv-1c-2 10.0.1.14: Ubuntu 22.04.4, 4 vCPU, 16 ГБ; srv1cv8-8.3.24.1548 (кластер), postgresql@16-main; в реестре кластера ИБ buh_dev и zup_dev; apache и заданий бэкапа нет.

Состояние системы засеяно подтверждёнными JSON: вариант A — четыре сервера стенда M, вариант B — только srv-1c (способ засева — по реализации).

## Вход

Форма (шаг 1); ответы пользователя инспектору (шаг 2).

## Ожидаемое поведение

- Куратор: класс `conflict`, серверы — {10.0.1.14, srv-1c} в обоих вариантах.
- Вопрос пользователю: новый сервер описан так же, как srv-1c, — чем они отличаются. Пример: «Сервер 10.0.1.14 описан так же, как srv-1c (10.0.1.12): „Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL“. Чем они отличаются?»
- В варианте A в конфликт не попал acc-01, хотя у него тоже postgres, и не попал web-01.
- Карточка JSON до ответа пользователя не предлагается.
- Вопросы инспектора в этом тесте не оцениваются (фокус — куратор).
- Ошибки: `consistent` (вопрос не задан); вопрос без указания сервера, с которым совпадение; куратор сам дописал отличие; описание srv-1c изменено.

## Эталон

- Куратор: `conflict`; серверы {10.0.1.14, srv-1c}; суть вопроса — чем отличаются; вопросов куратора до ответа — ровно один.

## Метрики

- Rule-based: `cur-conflict` («вопрос задан?» = да, набор серверов верный), `e2e-expected-state` (карточка не показана до ответа, srv-1c не изменён).
- LLM-judge: `judge-cur-question` — (1) язык без внутрисистемных терминов; (2) спрошено, чем серверы отличаются; (3) указан именно srv-1c и его описание. Засчитан при всех трёх.

## Основания

[UC-15] — одинаковые краткие описания как пример конфликта; [K §2.2] — формулировка вопроса; [AR-11] — куратор после инспектора; [UC-17] — исключение «конфликт описаний».

## Данные

Стенд I (srv-1c-2), засев системы для вариантов A и B, форма, сценарные ответы инспектору, эталон, рубрика judge.
