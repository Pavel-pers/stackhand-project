# init/e2e/difference/01 — случай одного сервера: вопроса «чем отличается» нет

## Сценарий

Пункт плана «N-server case + 1 server case → Difference? R&B: question asked?», сторона «1 server». Система пустая, добавляется первый сервер. Сравнивать куратору не с чем — вопрос о различиях задан быть не должен.

1. Кнопка «Добавить сервер» → форма: ip 10.0.1.12, ssh_key `eval_ed25519`, description «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; обслуживает франчайзи «1С-Партнёр»; бэкап — pg_dump каждую ночь в /backup/pg; apache публикует данные 1С для обмена с сайтом».
2. Открывается чат добавления; инспектор осматривает srv-1c (базовое состояние стенда I), заполняет теги и полное описание.
3. Куратор заполняет название и краткое описание.
4. Пользователь видит карточку с JSON и подтверждает; система сообщает, что сервер добавлен и данные начали копиться.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс srv-1c-2 10.0.1.14 и win-01 10.0.1.20; тулкиты не установлены; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

srv-1c — базовое состояние: бэкап pg_dump в /backup/pg по cron 02:00.

## Вход

Форма (шаг 1) и подтверждение карточки (шаг 4). На вопросы, если они всё же будут заданы, пользователь отвечает фразой «всё как в описании».

## Ожидаемое поведение

- Куратор: класс `consistent`, вопроса о различиях нет.
- Инспектор: класс `filled`, вопросов нет — всё есть в осмотре и в описании (см. init/node-isolate/inspector/filled/01).
- Единственное действие пользователя после формы — подтверждение карточки JSON.
- Эталон JSON srv-1c (полный чек-лист — `init/README.md`, «Эталонные описания»): `server_ip` 10.0.1.12; `tags` {host, 1c/cluster, db/pg, web/apache}; краткое описание — сервер 1С, Бухгалтерия и ЗУП, PostgreSQL; полное описание — ОС, ресурсы, тома, версия и порты кластера 1С, ИБ Buh и ZUP, PostgreSQL 16, публикация на 8080, задание бэкапа 02:00 → /backup/pg; поля паспорта — пути бэкапов /backup/pg, ИБ Buh и ZUP, подрядчик «1С-Партнёр».
- Ошибки: вопрос «чем этот сервер отличается от других»; любой вопрос инспектора; карточка без тегов или полного описания.

## Эталон

- Куратор: `consistent`; вопросов куратора — 0.
- Инспектор: `filled`; вопросов инспектора — 0.
- JSON — эталон srv-1c.

## Метрики

- Rule-based: `cur-conflict` (ожидается `consistent` — «вопрос задан?» = нет), `insp-clarify` (вопросов нет), `insp-fields`.
- `e2e-expected-state` (rule-based по журналу и состоянию системы): JSON сохранён после подтверждения и совпадает с эталоном по полям (`insp-fields` для полей инспектора, правило краткого описания для куратора); в документе контекста оркестратора появились ip, теги и краткое описание, полное описание — только у агента сервера [UC-04]; тулкиты стоят ровно для подтверждённых тегов (для `unsupported:*` — нет); других изменений на хосте, кроме тулкитов и предусловий, нет [UC-06], [UC-07]; пользователю не показаны smoke-проверка, заключение куратора и разделение JSON [UC-14].

## Основания

## Данные

Стенд I (srv-1c, базовое состояние), форма, эталон JSON srv-1c.
