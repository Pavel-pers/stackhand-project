# init/e2e/1c-site/02 — такт 2: подтверждение — запись о сервере и рабочие пробы

Сценарий плана: **IN-2a** — Серверы 1С и сайт — лишние вопросы не заданы (R&B), качество составленной информации о сервере (LLM). Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-2a, итог: пользователь подтверждает карточки; записи расходятся по памяти; пробы проверяют, пригодно ли то, что собрали инспектор и куратор, для рабочих запросов — оркестратору хватает краткого описания для маршрутизации и ответа, агенту — полей инспектора и его ручек.

1. Такт 2 сессии 1: подтверждение карточки srv-1c (зафиксирована из 1c-site/01) → запись.
2. Такт 2 сессии 2: подтверждение карточки web-01 → запись.
3. Пробы (новые сессии, по одному такту): «Расскажи про сервер сайта»; «Что сейчас грузит сервер 1С?»; «Прайс на сайте вчерашний — выгрузка из 1С отработала?».

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — снапшоты после такта 1 каждой сессии 1c-site/01 с зафиксированными карточками.

## Вход

Два подтверждения; три пробы.

## Цепочка

- Подтверждение → память: записи srv-1c и web-01 [AR-29]; контекст оркестратора — `conn-ip`, название, теги, `short-desc`; `full-desc`, `tags-full-desc` — агентам; логгеры под теги ([Q49]).
- Пробы: «Расскажи про сервер сайта» — `answer-user` из краткого описания web-01 (его достаточно для ответа); «Что сейчас грузит сервер 1С?» — `delegate` srv-1c, агент по своим полям и ручкам вызывает `host.now_resources`, ответ доходит до пользователя; «прайс…» — `delegate` web-01 по краткому описанию («забирает прайс из 1С»), агент — `host.sched_jobs`.
- Признаки разрыва: записи нет или поля не те; логгеры не под теги; на пробах — уточняющий вопрос, неверный адресат, `wrong_addressee` или `no_template` у агента.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Записи srv-1c и web-01 — по эталонам `init/README.md`; в контексте оркестратора — оба сервера.
- Пробы: первая — ответ из краткого описания web-01 без запуска агента, факты совпадают с кратким описанием (сайт, VPS у хостера, прайс из 1С); вторая — `delegate` srv-1c, агент `host.now_resources`, ответ с процессами и моментом; третья — `delegate` web-01; уточнений нет.
- Ошибки: на пробах — вопрос или не тот сервер; `delegate` srv-1c по слову «1С» в третьей пробе.

## Эталон

- Память: записи по эталонам; контекст оркестратора — srv-1c, web-01.
- Пробы: `answer-user` без `delegate`; `delegate` → srv-1c, агент `host.now_resources`; `delegate` → web-01; вопросов — 0.

## Метрики

- Rule-based: `e2e-expected-state` (rule-based по журналу и состоянию системы): цепочка — инспектор (ручки ≤ 40, вопросы ≤ 10), затем куратор (QA ≤ 5, confirmation ≤ 3), затем карточка подтверждения с `short-desc` и `server-name` [UC-21]; вопросов пользователю ровно столько, сколько в эталоне; после подтверждения запись о сервере сохранена и совпадает с эталоном по полям (`insp-fields` для полей инспектора, `cur-fields` для полей куратора [AR-29]); в контексте оркестратора появились `conn-ip`, `server-name`, `tags`, `short-desc` [AR-22] (`tags-short-desc` — [Q56]), `full-desc` и `tags-full-desc` — только у агента сервера [UC-04]; логгеры стоят ровно для тегов записи (для `unsupported:*` — нет) — [Q49] `[предл.]`; других изменений на хосте нет [UC-06], [UC-07]; пользователю не показаны разделение записи и заключение куратора [UC-14].
- LLM-judge: `judge-orch-arch` для первой пробы — только факты из краткого описания web-01; `judge-orch-report` для второй и третьей.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: `orch-no-delegation`, `orch-agent-choice`, `local-handle-choice` (пробы). Узлы — `orchestrator/answered/03`, `orchestrator/delegated/02`, `/05`, `local/handle-choice/03`.
