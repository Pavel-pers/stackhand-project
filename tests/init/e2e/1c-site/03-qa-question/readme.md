# init/e2e/1c-site/03 — такт 1: 1С + сайт — вопрос инспектора нужен

Сценарий плана: **IN-2b** — Серверы 1С и сайт — вопрос задать нужно: такты «вопрос» и «обработка ответа». Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана IN-2b, такт «вопрос». «1С + сайт» — фикстура стенда: пара серверов «сервер 1С + сайт» (пояснение автора плана, 2026-10-27). Что проверяется: у инспектора — правильно ли расставлены теги и заполнены полное описание и описания по тегам; у куратора — правильно ли сформированы название, краткое описание и описания по тегам (LLM-judge). Две составляющие: IN-2a — лишние вопросы не задаём (R&B: вопрос задан — заведомо провал; LLM — качество составленной информации о сервере); IN-2b — вопрос задать всё-таки нужно, такты «вопрос» и «обработка ответа». Похожие серверы в этом пункте не проверяются — это IN-1.

Та же пара серверов, но на стенде засеяны два пробела, по которым инспектор обязан спросить: у srv-1c путь бэкапа из описания не существует, на web-01 остатки Docker дают тег-кандидат со средней уверенностью. Проверяются сами вопросы и их формулировка; такт каждой сессии заканчивается вопросом инспектора. Вопрос куратора в этой фикстуре не ожидается: описания серверов разные.

1. Сессия 1, такт 1: форма srv-1c — description как в 1c-site/01, но «бэкап — pg_dump каждую ночь в /backup» (без /pg) → инспектор → `ask-user` о пути.
2. Сессия 2, такт 1: форма web-01 — description как в 1c-site/01 → инспектор → `ask-user` о Docker.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Засев: на srv-1c каталога /backup нет, задание cron 02:00 пишет дампы в /mnt/nas/pg (NFS с nas-01), там лежат дампы за последние ночи; на web-01 установлен пакет Docker, служба остановлена и отключена, контейнеров нет, файл сокета остался.

## Вход

Две формы — два такта; каждый заканчивается вопросом инспектора.

## Цепочка

- Форма → инспектор: ручки по чек-листу; расхождение «сказано — по факту» (srv-1c: `insp.path_check(/backup)` — нет, задание пишет в /mnt/nas/pg) и неуверенный тег (web-01: Docker установлен, но не работает) → по одному `ask-user`; остальные поля — без вопросов; `submit` до ответа не вызван.
- Признаки разрыва: вопрос не задан (расхождение не замечено; `insp.path_check` не вызван); задан не по тому полю; два вопроса там, где нужен один; `submit` с /backup; вопрос куратора (его ход ещё не настал).

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Сессия 1: вопрос инспектора по полю «пути бэкапов» (суть: /backup не найден, задание пишет в /mnt/nas/pg — подтвердить).
- Сессия 2: вопрос инспектора по тегу docker (суть: Docker установлен, но не работает и контейнеров нет — следить ли).
- Других вопросов нет; язык без имён ручек и классов.
- Ошибки: `submit` без вопроса; вопрос «где лежат бэкапы?» без найденного варианта; «кандидат docker, confidence medium»; отдельный вопрос о тегах с высокой уверенностью `[предл.]`.

## Эталон

- Цепочка: вопросов пользователю — ровно по одному в каждой сессии, оба от инспектора: (srv-1c, пути бэкапов), (web-01, тег docker); `submit` — 0; куратор не запущен.

## Метрики

- Rule-based: `insp-clarify` (вопросы там и только там, где ожидаются), `insp-checklist` `[предл.]` (`insp.path_check(/backup)` вызван), `e2e-expected-state` (такт закончился вопросом; память не изменена).
- LLM-judge: `judge-insp-question` для обоих вопросов — (1) язык без имён ручек и классов; (2) спрошено именно то, чего не хватает для поля.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: узлы — `inspector/clarify/01`, `/05`.

## Основания

Транскрипт плана, Init-2 («случай, когда вопрос задать всё-таки нужно — разделяется на несколько тактов»); исключение «инспектору не хватает данных: путь из описания не найден, тег-кандидат со средней уверенностью» [K §2.2], [UC-17]; [T §3.1]; [Q46].
