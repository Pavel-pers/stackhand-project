# init/e2e/1c-site/05 — такт 3: подтверждение — ответы дошли до записи и до агента

Сценарий плана: **IN-2b** — Серверы 1С и сайт — вопрос задать нужно: такты «вопрос» и «обработка ответа». Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-2b, итог: после подтверждения ответы пользователя живут в записи о сервере и доходят до агента и его ручек — путь к бэкапам агент берёт из `tags-full-desc` (из ответа пользователя), логгер docker на web-01 не установлен.

1. Подтверждение карточек (зафиксированы из 1c-site/04) → записи.
2. Пробы (новые сессии): «Есть ли свежий бэкап баз 1С?» — путь /mnt/nas/pg; «Какие контейнеры перезапускались на сайте за сутки?» — у web-01 нет docker.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — снапшоты после такта 2 каждой сессии 1c-site/04.

## Вход

Два подтверждения; две пробы.

## Цепочка

- Подтверждение → память: записи с учтёнными ответами; логгер docker на web-01 не ставится (ответ «не нужен» дошёл до установки — [Q49]); путь /mnt/nas/pg — в `tags-full-desc` host srv-1c.
- Проба 1: оркестратор → агент srv-1c → `host.backup_files` по пути из записи — /mnt/nas/pg; в ответе — дампы с NAS и их время.
- Проба 2: оркестратор → агент web-01 (сервер назван) → `escalate(wrong_addressee)` — у web-01 нет тега docker и контейнеров в описании (как `local/refusal/04`); оркестратор, не найдя другого сервера с Docker по этому запросу, сообщает пользователю, что контейнеров на сайте нет / Docker там не обслуживается; без выдуманных контейнеров.
- Признаки разрыва: на пробе 1 агент ищет бэкапы в /backup или эскалирует `no_template`; на пробе 2 — перезапуски служб выданы за контейнеры; логгер docker установлен.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Записи: srv-1c — пути бэкапов /mnt/nas/pg; web-01 — без docker; логгера docker на web-01 нет.
- Проба 1: `delegate` srv-1c; агент `host.backup_files(path = /mnt/nas/pg)` (или без path — по записи); ответ называет последние дампы и их время; без уточнений.
- Проба 2: `delegate` web-01; агент `escalate(wrong_addressee)`, не выдаёт перезапуски служб за контейнеры; ответ пользователю — контейнеров/Docker на сайте нет (не обслуживается).
- Ошибки: «бэкапов нет» из-за поиска в /backup; выдуманные контейнеры на web-01.

## Эталон

- Память: записи с ответами; логгеры srv-1c — host, 1c, db, web; web-01 — host, web, db.
- Проба 1: `delegate` → srv-1c; `host.backup_files` с путём /mnt/nas/pg; вопросов — 0.
- Проба 2: `delegate` → web-01; эскалация `wrong_addressee`; `answer-user`/`reject` без выдуманных данных.

## Метрики

- Rule-based: `e2e-expected-state` (rule-based по журналу и состоянию системы): цепочка — инспектор (ручки ≤ 40, вопросы ≤ 10), затем куратор (QA ≤ 5, confirmation ≤ 3), затем карточка подтверждения с `short-desc` и `server-name` [UC-21]; вопросов пользователю ровно столько, сколько в эталоне; после подтверждения запись о сервере сохранена и совпадает с эталоном по полям (`insp-fields` для полей инспектора, `cur-fields` для полей куратора [AR-29]); в контексте оркестратора появились `conn-ip`, `server-name`, `tags`, `short-desc` [AR-22] (`tags-short-desc` — [Q56]), `full-desc` и `tags-full-desc` — только у агента сервера [UC-04]; логгеры стоят ровно для тегов записи (для `unsupported:*` — нет) — [Q49] `[предл.]`; других изменений на хосте нет [UC-06], [UC-07]; пользователю не показаны разделение записи и заключение куратора [UC-14].
- LLM-judge: `judge-orch-report` для проб.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: `orch-agent-choice`, `local-handle-choice` и `local-handle-args` (путь). Узлы — `local/handle-choice/11`, `local/refusal/04`.
