# init/e2e/rewrite-short-desc/01 — такт 2: замечания пользователя на карточке — куратор переписывает краткое описание и название

Сценарий плана: **IN-4** — Перезапись краткого описания сервера куратором после возврата инспектора — замечания пользователя; просьбы вне границ — явный отказ. Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана IN-4: перезапись краткого описания сервера куратором — уже после возврата из инспектора и построения куратором краткого описания. По сути тест на куратора, но e2e важен для прогона на реальном возврате инспектора: куратор переписывает поля по замечаниям на живом артефакте. Такт 1 (форма → карточка) — это `1c-site/01`, сессия srv-1c; здесь — такт 2: карточка зафиксирована в транскрипте, пользователь пишет замечание → новая карточка.

Замечание: «назови его „1С бухгалтерии“; в описании напиши, что это основной сервер бухгалтерии и кадров, про бэкап не надо».

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

Состояние — снапшот после такта 1 `1c-site/01` (сессия srv-1c): живой артефакт инспектора; в транскрипте карточка зафиксирована тестом: `short-desc` — «Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз»; `server-name` — «srv-1c».

## Вход

Замечание пользователя на карточке. Такт — до новой карточки.

## Цепочка

- Замечание → куратор [UC-24]: переписывает только `short-desc` и `server-name`; `tags`, `full-desc`, `tags-short-desc` не трогает; `confirmation` повторно (2-я из 3); `deny` и `QA` не нужны.
- Признаки разрыва: карточка без изменений; изменены теги или `tags-short-desc`; `deny` на замечание в границах; `QA` «что именно поменять?»; название > 4 слов.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Новая карточка — `server-name` «1С бухгалтерии»; `short-desc` — сервер 1С, основной сервер бухгалтерии и кадров, Бухгалтерия и ЗУП на PostgreSQL; без «ночной бэкап»; < 50 слов.
- Теги, `full-desc`, `tags-short-desc` — как в такте 1.
- Ошибки: повторная отправка без изменений; изменение тегов; `deny`; название > 4 слов; «бэкап» в описании.

## Эталон

- `confirmation` (2-я); `server-name` = «1С бухгалтерии»; `short-desc` содержит «бухгалтер» и «кадр», не содержит «бэкап»; `tags` без изменений; память не изменена.

## Метрики

- Rule-based: `cur-fields` `[предл.]`, `e2e-expected-state` (2-я карточка; теги без изменений; память не изменена).
- LLM-judge: `judge-cur-summary` `[предл.]` — `server-name`, `short-desc`, `tags-short-desc`, после правки — ровно по замечаниям, ничего не додумано и не потеряно сверх них (критерии — README, «Метрики»; узловые тесты — `curator/summary/*`).
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: узел — `curator/rewrite/01`.

Транскрипт плана, Init-4; [UC-24] — замечания по краткому описанию и названию на шаге подтверждения; [UC-21]; [AR-32] — confirmation ≤ 3.
