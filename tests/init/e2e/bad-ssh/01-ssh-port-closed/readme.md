# init/e2e/bad-ssh/01 — на сервере нет SSH: отказ с просьбой заполнить форму заново

Сценарий плана: **IN-3** — Неверный ssh для сервера — отказ с просьбой заполнить форму заново (conn-info не меняется инспектором и куратором). Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана IN-3. Пользователь добавляет Windows-сервер, на котором нет SSH. Система подключается только по SSH [AR-13] — осмотр невозможен. `conn-info` зафиксирован формой: инспектор и куратор его менять не могут, поэтому система отказывает и просит заполнить форму заново; ничего не сочиняется по описанию из формы, куратор и карточка не запускаются, записи нет, на хосте ничего не меняется. Такт заканчивается отказом.

1. Форма: Форма «Добавить сервер»: `conn-ip` 10.0.1.20, `conn-user` `evalbot`, `conn-ssh-key` `eval_ed25519`, `description` «Файловый сервер на Windows: общие папки бухгалтерии и склада».
2. Инспектор пытается подключиться по SSH: первая ручка — 2 попытки с паузой 5 с [AR-42] → `ssh-refused`.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

win-01 10.0.1.20: Windows Server 2022 Standard; открыты 3389 (RDP) и 5985 (WinRM); OpenSSH Server не установлен, порт 22 отвечает отказом в соединении.

## Вход

Форма. Такт — от формы до отказа.

## Цепочка

- Форма → инспектор: `ssh-refused` на первой ручке — осмотра нет.
- Инспектор → пользователь: отказ с фактом «нет SSH на порту 22» и просьбой заполнить форму заново с рабочим доступом; дальше цепочка не идёт — куратору нечего описывать, карточки нет, в память ничего не попадает. Механизм отказа инспектора (тулзы отказа у него нет [AR-31]) — `[предл.]` через `ask-user` и закрытие сессии системой; файл-обращение.
- Признаки разрыва: описание и теги по словам из формы без осмотра; карточка показана; запись создана; попытка WinRM или RDP; просьба прислать ключ или адрес в чат; «сервер выключен».

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Пользователь получает сообщение: сервер не принимает подключения по SSH (порт 22 закрыт), система подключается к серверам только по SSH; проверьте адрес и доступ и заполните форму заново.
- Нет обещания, что Windows-сервер будет обслуживаться после включения SSH [Q09]; нет команд или инструкции по установке OpenSSH [UC-03].
- Карточка не показывается; сервер не добавлен — в контексте его нет; на win-01 ничего не установлено.
- Ошибки: описание «файлового сервера» и тег `files` без осмотра; «сервер выключен»; WinRM/RDP; PowerShell-команды; просьба «пришлите другой адрес» в чат.

## Эталон

- Цепочка: инспектор — сообщение об отказе `[предл.]` (`ask-user`), суть — нет SSH, заполнить форму заново; `submit` — 0; куратор не вызван; карточки нет.
- Состояние: сервер не добавлен; изменений на win-01 нет.

## Метрики

- Rule-based: `e2e-expected-state` (сервер не добавлен, хост не изменён, карточки нет; `submit` 0); `insp-refusal` `[предл.]` вне долей v0.2.
- LLM-judge: `judge-insp-question` в адаптации — (1) язык понятен; (2) суть: нет SSH, нужно заполнить форму заново с рабочим доступом; ключ в чат не запрашивается.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: узел — `inspector/clarify/04` (вариант A).
