Сценарий плана: **IN-3** — Неверный ssh для сервера — отказ с просьбой заполнить форму заново (conn-info не меняется инспектором и куратором). Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-3, продолжение: после отказа пользователь заполняет форму заново с рабочим ключом (новая сессия — отдельный такт). Цепочка проходит до карточки без вопросов; от прежней попытки в системе ничего не остаётся.

Форма: Форма «Добавить сервер»: `conn-ip` 10.0.1.1, `conn-user` `evalbot`, `conn-ssh-key` `eval_ed25519`, `description` «Шлюз офиса: WireGuard-туннели до склада и до сайта». → инспектор → куратор → `confirmation`. Подтверждение и проба по образцу `1c-site/02` здесь не повторяются.

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах.
