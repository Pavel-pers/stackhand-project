# init/e2e/bad-ssh/02 — ключ из формы не подходит: отказ с просьбой заполнить форму заново

Сценарий плана: **IN-3** — Неверный ssh для сервера — отказ с просьбой заполнить форму заново (conn-info не меняется инспектором и куратором). Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт IN-3, наследник старого init/ask/02. Сервер отвечает по SSH, но ключ из формы не принят. Инспектор сообщает факт — сервер на связи, ключ отклонён — и просит заполнить форму заново: сменить `conn-ssh-key` в чате нельзя. Такт заканчивается отказом; повторная форма с верным ключом — `bad-ssh/03`.

1. Форма: Форма «Добавить сервер»: `conn-ip` 10.0.1.1, `conn-user` `evalbot`, `conn-ssh-key` `old_laptop_rsa`, `description` «Шлюз офиса: WireGuard-туннели до склада и до сайта».
2. Первая ручка инспектора — 2 попытки с паузой 5 с [AR-42], обе с «evalbot@10.0.1.1: Permission denied (publickey)» → `ssh-refused` → отказ.

## Стенд

Стенд I (подробно — `init/README.md`, раздел «Стенд I»): чистые хосты стенда M до добавления (web-01, srv-1c, acc-01, gw-01), плюс win-01 10.0.1.20 и NAS-заглушка nas-01 10.0.1.40 (в систему не добавляется, нужна засевам); логгеры не установлены, если засев не говорит иное; у системы есть ключ `eval_ed25519`, принятый на Linux-хостах. Перед тестом — снапшот хостов и состояния системы; после — сброс.

gw-01 10.0.1.1: ключа `old_laptop_rsa` нет в authorized_keys; `eval_ed25519` — есть.

## Вход

Форма с неверным ключом. Такт — от формы до отказа.

## Цепочка

- Форма → инспектор: `ssh-refused` (ключ отклонён, сервер отвечает), осмотра нет → отказ с просьбой заполнить форму заново; куратор и карточка не запускаются; в память ничего не попадает.
- Признаки разрыва: артефакт или теги по описанию из формы без осмотра; карточка; «сервер недоступен»; просьба прислать ключ в чат; повторные подключения сверх двух попыток ручки.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Сказано, что сервер отвечает, но ключ не принят и осмотр не выполнен; просьба заполнить форму заново с рабочим ключом. Не утверждается, что сервер недоступен или выключен; гипотезы (ключ удалён, другая учётка) — допустимы. Описание шлюза не сочинено, тегов нет, на хосте ничего не установлено; ключ в чат не запрашивается.
- Ошибки: «шлюз недоступен»; артефакт по описанию без осмотра; тег `net` без осмотра; просьба прислать ключ.

## Эталон

- Цепочка: инспектор — отказ `[предл.]` (`ask-user`), суть — ключ отклонён, заполнить форму заново; `submit` 0; куратор не вызван; сервер не добавлен; хост не изменён.

- LLM-judge: `judge-insp-question` в адаптации — суть: ключ отклонён, заполнить форму заново.
