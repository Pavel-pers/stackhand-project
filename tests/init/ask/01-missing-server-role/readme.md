# init/ask/01 — не сказали, что на первом сервере

## Сценарий

1. Пользователь описывает конфигурацию C, но первый сервер назван только адресом: «Три сервера: 10.0.1.11, srv-1c — 1С с PostgreSQL, acc-01 — микросервисы бухгалтерии в Docker. Бэкап баз 1С — pg_dump ночью на srv-1c в /backup».
2. Инспекторы отрабатывают на всех трёх хостах; на 10.0.1.11 видны nginx, php8.1-fpm, mariadb, порты 80 и 443, cron с импортом прайса.
3. Оркестратор обнаруживает, что роль первого сервера не описана, и вместо того чтобы присвоить её молча, задаёт уточняющий вопрос.

## Ожидаемое поведение

- Тип ответа `clarify`, предмет уточнения — 10.0.1.11.
- Вопрос конкретный: что это за сервер и для чего он. Допустимо опереться на инспекцию: «на 10.0.1.11 работает nginx с сайтом — это публичный сайт компании?» — но роль не присваивается без ответа.
- Документ по srv-1c и acc-01 этим вопросом не заблокирован.
- Ошибки: молчаливое назначение роли «website» и выдача документа как при полном описании; отказ.

## Метрики

- Rule-based: `orchestrator-refusal-correct` (`clarify` там, где ожидается).
- LLM-judge: `judge-A-context-answer` — вопрос про нужный сервер, роль не выдумана, остальная работа не остановлена.

## Данные

Неполное описание пользователя, конфиг стенда C, эталон инспекции (как в init/success/03), рубрика judge.
