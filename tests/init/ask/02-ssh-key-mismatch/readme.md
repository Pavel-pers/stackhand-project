# init/ask/02 — не подходит SSH-ключ

## Сценарий

1. Пользователь описывает конфигурацию B: «Гипервизор Proxmox pve-01, на нём две виртуалки: vm-1c — сервер 1С с MS SQL, vm-rds — терминальный сервер на 15 человек. Бэкапы ВМ делает сам Proxmox по субботам».
2. В конфиге доступа для pve-01 указан ключ old_laptop_rsa, которого нет в authorized_keys. Инспектор pve-01 делает N попыток и получает «evalbot@192.168.20.2: Permission denied (publickey)». Инспекторы vm-1c и vm-rds по WinRM отрабатывают нормально (данные как в init/success/02).
3. Оркестратор сообщает факт и спрашивает про доступ к pve-01.

## Ожидаемое поведение

- Тип ответа `clarify`, предмет уточнения — pve-01.
- Сообщён факт: pve-01 не пустил по SSH (publickey), инспекция не выполнена; задан вопрос про рабочий ключ или другой доступ.
- Документ по pve-01 не сочинён из описания пользователя; работа по vm-1c и vm-rds продолжена.
- Ошибки: документ по pve-01 без инспекции; сообщение «гипервизор упал» (это не факт); общий отказ по всей инициализации.

## Метрики

- Rule-based: `orchestrator-refusal-correct`.
- LLM-judge: `judge-A-context-answer` — факт отделён от гипотез, вопрос адресный, документ не выдуман.

## Данные

Описание пользователя, конфиг стенда B с неверным ключом для pve-01, эталон инспекции с ошибкой доступа для pve-01 и нормальными данными для ВМ, рубрика judge.
