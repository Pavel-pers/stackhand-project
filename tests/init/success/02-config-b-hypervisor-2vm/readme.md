# init/success/02 — конфигурация B: гипервизор и две ВМ

## Сценарий

1. Пользователь описывает инфраструктуру: «Гипервизор Proxmox pve-01, на нём две виртуалки: vm-1c — сервер 1С с MS SQL (базы Бухгалтерия и ЗУП), vm-rds — терминальный сервер, на нём работают 15 человек. Бэкапы ВМ делает сам Proxmox по субботам».
2. Оркестратор запускает инспекторов на три хоста: pve-01 по SSH, vm-1c и vm-rds по WinRM. Инспекция: pve-01 — Proxmox VE 8.2, 16 CPU, 64 ГБ, ВМ 101 vm-1c (8 ядер, 32 ГБ) и 102 vm-rds (8 ядер, 24 ГБ), хранилище local-lvm 1800 ГБ (940 занято), задание бэкапа «сб 02:00» для обеих ВМ, последний запуск 2026-10-04 02:00 — ok; vm-1c — Windows Server 2022, служба «1C:Enterprise 8.3 Server Agent (1540)», MSSQLSERVER (1433), базы Buh и ZUP, диски C: 120 ГБ (55 занято), D: 500 ГБ (310 занято); vm-rds — Windows Server 2022, роль RDS Session Host, 15 пользователей, C: 200 ГБ (140 занято).
3. Q&A, сверка, формирование документов: сводка оркестратора с тегами и связями, документы трёх агентов.

## Ожидаемое поведение

- Тип ответа `answered`.
- Теги: pve-01 — обязательные `linux, hypervisor, proxmox, backup-vzdump`, запрещённые `windows, 1c`; vm-1c — `windows, 1c, mssql, vm`, запрещённые `hypervisor, rds`; vm-rds — `windows, rds, vm`, запрещённые `hypervisor, 1c`.
- Связи: vm-1c и vm-rds работают на pve-01 (runs-on).
- Сводка оркестратора: три сущности, обе ВМ зависят от одного гипервизора — это названо риском; бэкапы ВМ еженедельно по субботам; 15 пользователей терминала; базы 1С названы; ничего не выдумано.
- Документы агентов: pve-01 — версия PVE, список ВМ с ресурсами, хранилище и его заполненность, задание бэкапа; vm-1c — службы 1С и MSSQL, базы, диски; vm-rds — роль RDS, число пользователей, диск.
