# main/e2e/routing/02 — несколько серверов-кандидатов: вопрос с вариантами

## Сценарий

Пункт плана «Multiple servers candidate → 100% question, with candidates». Под запрос подходят два сервера; система всегда спрашивает с вариантами и после ответа работает с выбранным.

1. «Сколько места осталось на сервере с PostgreSQL?»
2. Ответ пользователя на уточнение: «на сервере 1С».

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Запрос и ответ на уточнение в одной сессии.

## Ожидаемое поведение

- Шаг 1: `clarify` A, варианты — ровно {srv-1c, acc-01} с краткими описаниями; делегаций нет.
- Шаг 2: делегирование srv-1c; агент — `executed`, ручка `host.volumes`; отчёт по томам — как в журнале.
- Требование «100 %»: на всех ~5 прогонах шаг 1 — вопрос, а не угаданная делегация.
- Ошибки: делегирование без вопроса хотя бы в одном прогоне; web-01 в вариантах; вопрос без вариантов; после ответа — снова вопрос.

## Эталон

- Шаг 1: `clarify` A, {srv-1c, acc-01}; шаг 2: `delegated` → srv-1c, `executed`, `host.volumes`.

## Метрики

- Rule-based: `orch-clarify-A` (доля должна быть 100 % по прогонам — порог из плана), `orch-agent-choice`, `local-template-choice`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-question` — (1) язык без внутрисистемных терминов; (2) суть донесена верно.; `judge-orch-report` — числа и факты в ответе пользователю совпадают с возвратом шаблона в журнале прогона; причины не выдуманы; период или момент назван; внутренние имена не упомянуты.

## Основания

[K §2.2] «Не понял, к какому агенту», [UC-17]. Порог «100 %» — из плана тестов; целевые значения метрик v0.2 не назначены [Q22].

## Данные

Живой стенд M, запрос, эталонные классы, адресат и шаблон, рубрика judge. Фактические числа берутся из журнала прогона (возврат шаблона), не из этого описания.
