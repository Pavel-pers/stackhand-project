# main/e2e/routing/03 — «что с сервером?»: подходят все агенты

## Сценарий

Пункт плана «Multiple local agent → What with server». Запрос, под который подходят все четыре агента. Система не опрашивает всех агентов сразу и не выбирает наугад — спрашивает; после ответа работает с одним сервером.

1. «Что с сервером?»
2. Ответ пользователя: «С сайтом — страницы долго открываются».

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Запрос и ответ на уточнение в одной сессии.

## Ожидаемое поведение

- Шаг 1: `clarify` A, варианты — все четыре сервера; делегаций нет (в журнале нет обращений к агентам).
- Шаг 2: делегирование web-01; задача — о текущей нагрузке или доступности сайта; выбор шаблона в этом тесте не оценивается.
- Ошибки: четыре делегации на шаге 1; одна делегация наугад; ответ «всё в порядке».

## Эталон

- Шаг 1: `clarify` A, {web-01, srv-1c, acc-01, gw-01}, делегаций — 0; шаг 2: `delegated` → web-01.

## Метрики

- Rule-based: `orch-clarify-A`, `orch-agent-choice` (шаг 2), `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-question` — (1) язык без внутрисистемных терминов; (2) суть донесена верно.

## Основания

[UC-11] — запрос уходит агенту одного сервера; [K §2.1 Поведение при неуверенности]. Прочтение пункта плана — README, «Соответствие плану».

## Данные

Живой стенд M, запрос, эталонные классы, адресат и шаблон, рубрика judge. Фактические числа берутся из журнала прогона (возврат шаблона), не из этого описания.
