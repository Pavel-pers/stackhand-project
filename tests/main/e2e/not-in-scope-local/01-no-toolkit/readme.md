# main/e2e/not-in-scope-local/01 — у агента нет тулкита под вопрос

Сценарий плана: **MR-3** — Не в скоупе локального агента — нет тулкита под запрос: агент формирует отказ, оркестратор получает и формулирует пользователю. Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана MR-3: e2e нужен — тестирует, как локальный агент формирует отказ, как оркестратор его получает и формулирует пользователю. Оркестратор верно отправляет вопрос о туннеле шлюзу gw-01, но у шлюза нет тулкита для WireGuard: ни ручки A, ни ручки B под вопрос. Агент эскалирует `no_template` с перечнем того, что умеет; оркестратор доносит отказ и перечень до пользователя на языке действий — не переделегирует молча и не придумывает ответ. Симметричные node-isolate тесты — по компонентам (`SCENARIOS.md`, MR-3).

Запрос: «Склад не видит 1С — когда склад последний раз выходил на связь через туннель?»

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Запрос. Такт один: запрос пользователя → … → терминальная тулза оркестратора; действий пользователя внутри нет.

## Цепочка

- Пользователь → оркестратор: вопрос о туннеле до склада → `delegate` gw-01 по краткому описанию («туннели до склада»), хотя в запросе есть «1С».
- Агент gw-01: тема в его описании есть (не `wrong_addressee`), но ни ручки A, ни B под неё нет → `escalate(no_template)` с перечнем того, что он умеет по gw-01 (пробный `host.log_excerpt` допустим, `answer` по нему — нет).
- Оркестратор → пользователь: `reject` по образцу контракта с перечнем — действиями, без имён ручек и без «можно добавить» [UC-25]; без `delegate` srv-1c и без `ask-user` «какой сервер?» (политика — [Q38]).
- Признаки разрыва: `delegate` srv-1c первым; агент эскалировал `wrong_addressee` (тема в описании есть) или ответил `answer` по `host.log_excerpt` с выводом «склад не подключался»; перечень агента не дошёл до пользователя или дополнен; имена ручек в отказе; выдуманное время подключения.

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Пользователь получает отказ по образцу контракта: «Такой вопрос по gw-01 пока не поддерживается. Могу ответить про: …» — перечень действиями.
- Не утверждается, что туннель упал или склад не подключался; на gw-01 ничего не изменено.
- Ошибки: `delegate` srv-1c; выдуманное время подключения; выборка журнала как ответ о рукопожатиях; `wrong_addressee`; имена ручек; «можно добавить в перечень».

## Эталон

- Цепочка: `delegate` → gw-01; агент — `escalate(no_template)` (ручек A/B с ответом — 0; пробная `host.log_excerpt` допустима); один запуск; `ask-user` — 0; `reject`.
- Итог: перечень в отказе = перечень из эскалации агента, на языке действий.

## Метрики

- Rule-based: `e2e-expected-state` (rule-based по журналу прогона и состоянию стенда): цепочка — тулзы оркестратора и ручки агентов вызваны в ожидаемом порядке и числе, `delegate_to` и обязательные ручки как в эталоне, вопросов пользователю ровно столько, сколько в эталоне, лимиты не превышены [AR-32]; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-report` по тексту отказа (без критерия периода) — перечень совпадает с ответом агента, ничего не добавлено, имён ручек нет; доп. рубрика `judge-orch-refusal` `[предл.]` по тексту отказа — без инструкций и команд для изменений, без имитации выполнения, без имён ручек и без «можно добавить» [UC-25], причина понятна.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: `orch-agent-choice`, `local-no-template`, `orch-not-in-scope`. Узлы — `orchestrator/delegated/09`, `local/refusal/02`, `orchestrator/report/09`.
