# main/e2e/template-mismatch/01 — данных за окно нет

## Сценарий

Пункт плана «Template mismatch → Time mismatch». Шаблон есть, но запрошенный период — до установки сборщиков. Отказ «нет данных за окно» — явно, не нулём.

Запрос: «Какая была нагрузка на сервер 1С в сентябре?»

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Стенд добавлен в систему после 2026-09-30 — данных за сентябрь нет.

## Вход

Запрос.

## Ожидаемое поведение

- Делегирование srv-1c; агент — `executed`, ручка `host.metrics`, окно — сентябрь; возврат пустой.
- Ответ по образцу контракта: «За сентябрь данных о нагрузке srv-1c нет»; не «0 %», без оценок по октябрю. Называть доступное окно не требуется [UC-13].
- Ошибки: нули; данные октября; `no_template` («не поддерживается»).

## Эталон

- `delegated` → srv-1c; `executed`, `host.metrics`, окно — сентябрь 2026.

## Метрики

- Rule-based: `orch-agent-choice`, `local-template-choice`, `local-template-args`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-report` — числа и факты в ответе пользователю совпадают с возвратом шаблона в журнале прогона; причины не выдуманы; период или момент назван; внутренние имена не упомянуты.

## Основания

[K §2.2] «Нет данных за окно», [UC-13], [UC-17].

## Данные

Живой стенд M, запрос, эталонные классы, адресат и шаблон, рубрика judge. Фактические числа берутся из журнала прогона (возврат шаблона), не из этого описания.
