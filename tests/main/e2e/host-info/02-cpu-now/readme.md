# main/e2e/host-info/02 — что грузит сервер прямо сейчас

## Сценарий

Пункт плана «Host info → CPU monitor Now». Вопрос о моменте: агент выполняет разовую команду просмотра ресурсов, а не читает историю. На стенде засеяна известная нагрузка — виновник известен заранее.

1. Засев: за минуту до запроса на srv-1c запущена нагрузка на CPU на 5 минут (известный процесс, например stress-ng на 4 ядра).
2. Запрос: «Что сейчас грузит сервер 1С?»

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев нагрузки — шаг 1 сценария; после теста процесс завершается сам.

## Вход

Запрос шага 2.

## Ожидаемое поведение

- Уточняющих вопросов нет; делегирование srv-1c; агент — `executed`, разовая команда «ресурсы сейчас».
- Отчёт: процесс-виновник из засева назван с его долей CPU и памяти; общая загрузка; момент снятия назван.
- Сравнение с обычной нагрузкой (есть в примере контракта) — желательно, но не обязательно: механизм двух чтений за один запрос не описан.
- Состояние стенда не изменено системой (процесс засева не трогается).
- Ошибки: чтение истории за сутки вместо «сейчас»; виновник не назван или назван не тот; «нагрузка нормальная»; предложение завершить процесс с командой.

## Эталон

- `delegated` → srv-1c; `executed`, разовая команда «ресурсы сейчас».
- Виновник в отчёте = процесс засева (по возврату в журнале).

## Метрики

- Rule-based: `orch-agent-choice`, `local-template-choice`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-report` — числа и факты в ответе пользователю совпадают с возвратом шаблона в журнале прогона; причины не выдуманы; период или момент назван; внутренние имена не упомянуты.

## Основания

[K §2.2] «Разовая команда чтения „сейчас“»; [K §2.1 Выход 3] — момент данных; [UC-06].
