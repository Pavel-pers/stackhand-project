# main/e2e/server-info/02 — проверка факта: «сейчас», а не память

## Сценарий

Пункт плана «Fact check → CPU info now, not memo (↛ инспекция)». После добавления srv-1c расширили; описание сервера не обновляется автоматически [UC-09], поэтому в полном описании у агента остались старые 8 vCPU и 32 ГБ. Ответ должен прийти с сервера, а не из описания, снятого инспектором.

1. Засев: после добавления ВМ srv-1c расширена до 12 vCPU и 48 ГБ (с перезагрузкой); JSON сервера не менялся.
2. Запрос: «Сколько сейчас ядер и памяти на сервере 1С? Мы его недавно расширяли».

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — шаг 1; после теста — откат снапшота.

## Вход

Запрос шага 2.

## Ожидаемое поведение

- Делегирование srv-1c с задачей проверить сейчас; агент — `executed`, разовая команда X01.
- Ответ: 12 vCPU и 48 ГБ на момент проверки; допустимо упомянуть, что при добавлении было 8 и 32, — как прежнее значение.
- Ошибки: 8 vCPU и 32 ГБ как текущие (ответ из памяти); ответ без выполнения команды; `answered` без делегации.

## Эталон

- `delegated` → srv-1c; `executed`, X01; в отчёте — значения из возврата (12 vCPU, 48 ГБ).

## Метрики

- Rule-based: `orch-no-delegation`, `orch-agent-choice`, `local-template-choice`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-report` — числа и факты в ответе пользователю совпадают с возвратом шаблона в журнале прогона; причины не выдуманы; период или момент назван; внутренние имена не упомянуты.

## Основания

[UC-09] — описание не обновляется; [K §2.1 Вход 3] — внеплановая инвентаризация разовой командой.

## Данные

Живой стенд M, запрос, эталонные классы, адресат и шаблон, рубрика judge. Фактические числа берутся из журнала прогона (возврат шаблона), не из этого описания.
