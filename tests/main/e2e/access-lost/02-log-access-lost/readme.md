# main/e2e/access-lost/02 — ручка упала: пропал доступ к собранным данным

Сценарий плана: **MR-6b** — Доступ к источнику данных потерялся (ручка не читает журнал) — путь ошибки «пропал доступ к логу» из метрик [M], в транскрипте не назван; ответ пользователю через оркестратора. Вид теста: e2e (система целиком). Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Код MR-6b — вариант «источник недоступен» (путь ошибки «пропал доступ к логу» [M]; в транскрипте не назван, в плане-скриншоте — «Infra local → Template»). На web-01 у учётки подключения пропал доступ к файлу, куда логгер пишет ошибки веб-сервера. Ручка возвращает ошибку `source-unavailable` с описанием, агент передаёт это оркестратору, оркестратор — пользователю как ответ, а не как «ошибок не было» и не как вопрос с просьбой починить права. Отличие от readability/02: там логгер перестал писать — это предупреждение вместе с результатом, и агент дочитывает ночь по журналу обращений; здесь сами собранные данные не читаются, и честный ответ — «посчитать нельзя, данных нет».

1. Засев: на web-01 у учётки подключения отозвано право чтения каталога файлов логгера (например, после обновления пакета); сайт работает штатно, ошибок 5xx нет.
2. Запрос утром: «Сколько ошибок было у сайта за ночь?»

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, записи подтверждены, логгеры пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — шаг 1; права восстанавливаются после теста.

## Вход

Запрос шага 2. Такт один: запрос пользователя → … → терминальная тулза оркестратора; действий пользователя внутри нет.

## Цепочка

- Пользователь → оркестратор → агент web-01: `delegate` об ошибках сайта за ночь.
- Ручка → агент: `web.errors` → `source-unavailable` (нет доступа к файлу логгера); агент передаёт по смыслу (`escalate(error)` или `answer`); дополнительная выборка журнала обращений — допустима, пустой результат по 5xx не выдаётся за «ошибок не было по журналу ошибок».
- Оркестратор → пользователь: ответ, а не вопрос — от пользователя ничего не нужно: посчитать ошибки за ночь нельзя, нет доступа к собранным данным; если выборка обращений делалась — «в журнале обращений ошибок 5xx за ночь не видно» с оговоркой.
- Признаки разрыва: «ошибок не было» или «0» без оговорки (ошибка ручки превратилась в пустой результат); «сервер недоступен»; `ask-user` с просьбой починить права; инструкция `chmod`; «сайт упал».

Разрыв цепочки в любом звене — тест не засчитан; где именно он случился, показывают метрики узлов по журналу и парные node-isolate тесты того же кода сценария.

## Ожидаемое поведение

- Ответ пользователю: посчитать ошибки за ночь нельзя — у системы нет доступа к собранным данным об ошибках сайта на web-01; причина — как предположение, не факт; если есть выборка обращений — сказано, что в ней 5xx не видно, с оговоркой о неполноте.
- Без команд исправления прав; без «логгер», «ручка».
- Ошибки: «ошибок не было» без оговорки; «сайт упал»; «сервер недоступен»; инструкция `chmod`; `ask-user`.

## Эталон

- Цепочка: `delegate` → web-01; `web.errors` → `source-unavailable`; допустимо `web.access_excerpt`; агент `escalate(error)`/`answer`; один запуск; `ask-user` — 0; `answer-user`.
- Итог: в ответе нет числа ошибок за ночь как установленного.

## Метрики

- Rule-based: `e2e-expected-state` (rule-based по журналу прогона и состоянию стенда): цепочка — тулзы оркестратора и ручки агентов вызваны в ожидаемом порядке и числе, `delegate_to` и обязательные ручки как в эталоне, вопросов пользователю ровно столько, сколько в эталоне, лимиты не превышены [AR-32]; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-report` по итоговому тексту пользователю — числа и факты совпадают со сводками ручек в журнале прогона; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22]; `judge-local-error` по формулировке агента в журнале.
- Метрики узлов по журналу — для локализации разрыва, в доли node-isolate не входят `[предл.]`: `orch-agent-choice`. Узлы — `local/error-formulation/02`, `orchestrator/report/10`.

## Основания

[AR-25] — enum `source-unavailable` `[предл.]`; [M] — путь «пропал доступ к логу»; остановка логгера — предупреждение, не ошибка (design doc 4.1, 5.4; `readability/02`); [UC-06], [UC-08].

## Данные

Живой стенд M, запрос, эталонная цепочка (адресат, обязательные ручки, число запусков и вопросов), рубрики judge. Фактические числа берутся из журнала прогона (сводки ручек), не из этого описания.
