# main/e2e/what-you-can/01 — «что ты умеешь?»: сторона оркестратора

## Сценарий

Пункт плана «What you can → (orchestrator) side». Общий вопрос о возможностях; отвечает оркестратор без агентов.

Запрос: «Что ты умеешь?»

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

## Вход

Запрос.

## Ожидаемое поведение

- `answered`; делегаций нет.
- Ответ: вопросы о состоянии и истории серверов по накопленным данным, о состоянии «прямо сейчас», об архитектуре; добавление и удаление серверов; четыре сервера; система только читает, ничего по расписанию, сводов по всем серверам нет.
- Ошибки: обещания изменений, расписаний, дашбордов; карточки подтверждения; выдуманные серверы.

## Эталон

- `answered`; делегаций — 0.

## Метрики

- Rule-based: `orch-no-delegation`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-orch-arch` — только факты из контекста и инструкций; ничего не выдумано; вопрос закрыт.

## Основания

[UC-06], [UC-07], [UC-11], [UC-12]; вопросы о самой системе явно не разбирались — класс `answered` по аналогии `[предл.]`.

## Данные

Живой стенд M, запрос, эталонные классы, адресат и шаблон, рубрика judge. Фактические числа берутся из журнала прогона (возврат шаблона), не из этого описания.
