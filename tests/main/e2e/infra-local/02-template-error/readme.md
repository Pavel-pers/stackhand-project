# main/e2e/infra-local/02 — шаблон упал: пропал доступ к журналу

## Сценарий

Пункт плана «Infra local → Template». Ночью после ротации журнала ошибок nginx на web-01 система потеряла к нему доступ. Шаблон возвращает ошибку с комментарием, агент её формулирует, оркестратор передаёт пользователю — без «ошибок не было».

1. Засев: ротация журнала ошибок nginx на web-01 в 00:00 с правами, недоступными для учётки сбора данных; до ротации на сайте сгенерированы ошибки 404/502; запуск теста — утром.
2. Запрос: «Сколько ошибок было у сайта за ночь?» (при запуске не утром — «за последние N часов», где N — время с ротации).

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — шаг 1; права восстанавливаются после теста.

## Вход

Запрос шага 2.

## Ожидаемое поведение

- Делегирование web-01; шаблон чтения ошибок веб-сервера возвращает ошибку с комментарием (нет доступа к журналу с момента ротации); агент формулирует её по смыслу.
- Ответ пользователю: за ночь посчитать нельзя — с полуночи система не может читать журнал ошибок веб-сервера; данные есть до момента ротации; без чисел за ночь.
- Без команд исправления прав; без «сборщик», «источник», «ручка».
- Ошибки: «ошибок не было»; «0»; «сайт упал»; инструкция `chmod`.

## Эталон

- `delegated` → web-01; ошибка шаблона по пути «пропал доступ к логу».
- Класс итогового сообщения оркестратора в v0.2 не определён — rule-based по классу на этом шаге нет.
