# main/e2e/infra-local/01 — сервер перестал принимать ключ

## Сценарий

Пункт плана «Infra local → SSH key». После добавления ключ системы удалили с srv-1c. Агент не может подключиться, сервер при этом на связи. Пользователь должен получить факт и просьбу о рабочем доступе — не выдуманные данные и не «сервер выключен».

1. Засев: ключ системы удалён из authorized_keys учётки подключения на srv-1c.
2. Запрос: «Посмотри заполненность дисков на сервере с 1С».
3. Ключ возвращён; тот же запрос в новой сессии.

## Стенд

Стенд M (подробно — `main/README.md`, раздел «Стенд M»): web-01 10.0.1.11 (VPS у хостера: nginx, PHP, MariaDB, импорт прайса из 1С раз в час), srv-1c 10.0.1.12 (1С 8.3 кластер + PostgreSQL 16, публикация 1С на 8080, pg_dump в 02:00), acc-01 10.0.1.13 (Docker: acc-api, acc-worker, acc-ocr на GPU T4, redis, postgres), gw-01 10.0.1.1 (WireGuard до склада и до web-01); все Ubuntu 22.04.4, доступ системы по SSH ключом. Серверы добавлены через форму, JSON подтверждены, тулкиты пишут данные не меньше 24 ч до прогона. Документ контекста оркестратора — как в `main/README.md`. Состояние стенда перед тестом — снапшот; сброс после теста.

Засев — шаг 1, возврат ключа — шаг 3.

## Вход

Запросы шагов 2 и 3.

## Ожидаемое поведение

- Шаг 2: делегирование srv-1c; шаблон падает на подключении — ключ отклонён; агент формулирует ошибку по пути «не подходит ssh-ключ»; оркестратор — `clarify` C: srv-1c на связи, но не принял ключ доступа; данных нет; просьба указать рабочий доступ.
- Без чисел по дискам; без «сервер выключен» и «недоступен по сети»; без команд (`ssh-copy-id`).
- Шаг 3: штатный ответ по дискам, как в host-info/04.
- Ошибки: данные по дискам из полного описания на шаге 2; повторная делегация другому серверу.

## Эталон

- Шаг 2: `delegated` → srv-1c; ошибка шаблона «ключ отклонён»; оркестратор `clarify` C (srv-1c, ключ не принят).
- Шаг 3: `executed`, `host.volumes`.

## Метрики

- Rule-based: `orch-clarify-C`, `orch-agent-choice`, `e2e-expected-state` (rule-based по журналу): классы узлов, `delegate_to`, шаблон и аргументы — как в эталоне; число делегаций — как в эталоне; состояние стенда после прогона не изменилось — система только читает [UC-06].
- LLM-judge: `judge-local-error` (формулировка агента в журнале), `judge-orch-question` — (1) язык без внутрисистемных терминов; (2) суть донесена верно.

## Основания

[AR-16], [M] — путь ошибки «не подходит ssh-ключ»; [K §2.2] «Сервер не отвечает»; значение N — [Q11].
