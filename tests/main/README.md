## Выдержка манифестов — пример для srv-1c

Каждый node-isolate тест локального агента приводит выдержку для своего сервера целиком; ниже — пример для srv-1c.

Выдержка из манифестов тулкитов установленных тегов — то, что агент получает в контекст: по источникам типовые вопросы и ключевые поля, по шаблонам — условия применимости [T §2.6, §4]. Выдержка составлена для теста: точные идентификаторы, `questions` и `key_fields` — по манифестам [Q04]; форма ручек — [Q02]; каталог разовых команд — [Q08]. Данные источников — с 2026-10-08 14:20 (установка тулкитов); ретенция: сырые метрики 7 дней, часовые агрегаты 13 месяцев, события 30 дней [T §2.5]. Все действия — только чтение, подтверждений нет [UC-06], [UC-07].

Ручки чтения логов (источники тулкитов):

| Источник | Вид | Типовые вопросы |
|---|---|---|
| host.metrics | metric, 60 с → часовые агрегаты | загрузка CPU и памяти, когда пики, хватает ли ресурсов |
| host.volumes | metric | заполненность томов, рост, когда закончится место |
| host.dirsizes | snapshot | какие каталоги занимают место |
| host.processes | metric, 60 с | какие процессы грузили сервер |
| host.services | snapshot | какие службы упали или перезапускались |
| host.auth | tail | кто заходил на сервер, неудачные входы |
| host.sched | snapshot | задания планировщика: расписание, последние запуски, коды завершения |
| host.backup_files | snapshot | свежесть файлов бэкапа по путям из паспорта |
| 1c.sessions, 1c.cluster | snapshot | кто сидит в базах, состояние кластера 1С |
| 1c.eventlog | tail | события журнала регистрации 1С |
| db.blocking | tail | блокировки в базе PostgreSQL |
| db.backups | snapshot | бэкапы СУБД |
| web (публикация 1С) | tail, probe | ошибки и доступность публикации; идентификаторы — по манифесту web |

Разовые команды чтения (R0):

| размер пути | размер произвольного каталога |
| выборка журнала | сырой журнал по фильтру и периоду |
