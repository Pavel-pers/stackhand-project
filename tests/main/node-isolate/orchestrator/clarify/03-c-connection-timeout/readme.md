# orchestrator/clarify/03 — ситуация C: сервер не ответил

## Сценарий

Наследник старого response-parse/02. Оркестратор делегировал вопрос о дисках srv-1c; агент после N попыток сообщил, что сервер не отвечает по SSH. Оркестратор передаёт пользователю факт и возможные причины и не выдаёт данных по дискам.

## Контекст оркестратора

Документ контекста стенда M (ООО «Тестовая компания», оптовая торговля: офис, склад, сайт). Четыре сервера добавлены через форму 2026-10-08; у оркестратора по каждому — ip, теги и краткое описание из подтверждённого JSON, полного описания нет [UC-04]. Название сервера в документе контекста — `[предл.]`; в тестах это имя хоста.

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| web-01 | 10.0.1.11 | host, web/nginx, db/mysql, unsupported:provider-hv | Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С |
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Плюс инструкции оркестратора и история текущей сессии [K §2.3]. Момент запроса — вторник 2026-10-27, 10:00 (+03:00), если в тесте не сказано иное.

## Вход

Запрос пользователя: «посмотри заполненность дисков на сервере с 1С».

Делегирование: srv-1c — «Заполненность всех томов и прогноз, когда закончится место».

Ответ агента srv-1c: сервер недоступен — «ssh: connect to host 10.0.1.12 port 22: Connection timed out», попыток 3 с паузой 10 с. Комментарий шаблона агенту: «сервер не ответил по SSH; данные не получены». Возможные причины по агенту: выключен, изменён allow-list, сменился адрес.

## Ожидаемое поведение

- Класс `clarify`, ситуация C; поля — сервер srv-1c и причины.
- Сообщение по образцу контракта: «srv-1c не ответил по SSH после 3 попыток. Возможные причины: выключен, изменён allow-list, сменился адрес. Укажите другой доступ или повторите позже».
- Пометка «гипотеза» не нужна — причины подаются как возможные [UC-13]; «сервер выключен» как установленный факт — ошибка.
- Без трейса и сырого текста ошибки, если не просили.
- Ошибки: данные по дискам; повторная делегация другому серверу; ответ без следующего шага для пользователя.

## Эталон

- Класс: `clarify`; ситуация: C; сервер: srv-1c; причины: выключен, изменён allow-list, сменился адрес.

## Метрики

- Rule-based: `orch-clarify-C` — класс, сервер и причины совпадают с эталоном.
- LLM-judge: `judge-orch-question` — (1) язык понятен пользователю: нет имён источников, ручек, шаблонов, классов, тегов как идентификаторов (теги в скобках рядом с описанием, как в примере контракта [K §2.2], допустимы); (2) суть донесена верно. Засчитан при обоих.

## Основания

Исключение «сервер не отвечает» [K §2.2], [UC-13], [UC-17]; ситуация C [M]. Значение N — [Q11]. В рантайме при недоступности сервера D §5.4 предполагает статический ответ без вызова модели — как это сочетается с классом `clarify` C, не обсуждалось.
