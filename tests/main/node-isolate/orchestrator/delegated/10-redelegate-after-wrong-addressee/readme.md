Сценарий плана: **MR-5c** — Неверно выбранный сервер — node-isolate: A) оркестратор получил отказ и перевыбирает; B) агенту дан запрос мимо его скоупа. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана MR-5c, компонента A: оркестратору подставлено окружение, как будто он выбрал не того агента и получил отказ. Транскрипт: вопрос о сеансах 1С ушёл шлюзу gw-01 (в его описании «склад работает в 1С через туннель»); агент шлюза эскалировал `wrong_addressee`. Оркестратор по контексту выбирает srv-1c и запускает его агента с переформулированным запросом; пользователь перевыбора не видит [UC-16].

## Вход

Транскрипт сессии (оркестратор перезапущен с ним [AR-28]):

- Пользователь: «склад жалуется, что не может зайти в 1С — кто сейчас сидит в базе?»
- Оркестратор: `delegate(gw-01, «Кто сейчас подключён к базам 1С (активные сеансы)»)`
- Агент gw-01: `escalate(wrong_addressee)` — «на gw-01 нет 1С: ни тега, ни признаков в описании (упоминание „склад работает в 1С через туннель“ — о роли шлюза, не о 1С на нём)». О других серверах агент не знает — адресата выбирает оркестратор.

## Ожидаемое поведение

- `delegate` (`delegated`), новый адресат — srv-1c.
- Запрос агенту: кто сейчас подключён к базам 1С (активные сеансы), с указанием, что вопрос связан с жалобой склада; без команд.
- Пользователь не видит ни ошибки, ни перевыбора [UC-16] — ни `ask-user`, ни `answer-user` на этом шаге.
- Ошибки: `reject` «не удалось»; `answer-user` «вопрос передан другому серверу»; повторный `delegate` gw-01; `delegate` web-01 или acc-01; вывод «склад не подключён» из ответа шлюза.
