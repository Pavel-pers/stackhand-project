## Вход

Запрос пользователя: «какие снапшоты и бэкапы делает хостер для web-01?». Агент в тесте не участвует — проверяется только оркестратор; транскрипт сессии пуст, счётчики тулз — 0.

## Ожидаемое поведение

- `reject` (`not_in_scope`), делегирования нет.
- Сказано по образцу контракта («Вижу кластер Proxmox, но не обслуживаю его»): web-01 — виртуальная машина у хостинг-провайдера, платформу провайдера система не обслуживает, поэтому о снапшотах и бэкапах хостера данных нет.
- Имя `unsupported:provider-hv` не названо [UC-16].
- Ошибки: выдуманный список снапшотов; `delegate` web-01 «посмотри снапшоты»; «бэкапов нет» как факт.

## Эталон

- Тулза: `reject` (`not_in_scope`); `delegate` не вызван.

## Метрики

- Rule-based: `orch-not-in-scope` — тулза `reject` (класс `not_in_scope`) там, где ожидается; делегаций нет.
- Доп. рубрика `judge-orch-refusal` `[предл.]` — вне долей v0.2 (текст отказа judge-метрикой не покрыт): нет инструкций и команд для изменений [UC-06]; нет имитации выполнения; имена ручек не названы [UC-22]; нет предложения «можно добавить в перечень» [UC-25]; причина отказа понятна.

## Основания

[T §3.4, §6] — `unsupported:<имя>`, «вижу, но не обслуживаю»; [UC-16].
