# orchestrator/not-in-scope/03 — запрос относится к слишком большому числу серверов

Сценарий плана: **MR-2c** — Не в скоупе оркестратора — запрос относится к слишком большому числу серверов (> 15). Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана MR-2c. Правило «один запрос — один сервер» снято [UC-26], оркестратор может опрашивать агентов по очереди — но не больше 15 запусков на сессию [AR-32]. Запрос, которому нужны данные с большего числа серверов (в нашем случае > 15), — отказ с объяснением; предел — по лимиту `delegate` `[предл.]`: порог «> 15» назван автором плана, в документах как правило отказа не записан (README, открытые пункты и файл-обращение).

## Вход

Вариант A — «сравни заполненность дисков во всех кафе».

Вариант B — «на всех серверах кафе проверь, что ночной бэкап отработал».

Вариант C (контрольный, в пределах лимита) — «сколько места осталось на серверах кафе на Покровке и на Пятницкой?».

Агент в тесте не участвует — проверяется только оркестратор; транскрипт сессии пуст, счётчики тулз — 0.

## Ожидаемое поведение

- A, B: `reject` (`not_in_scope`) — запрос затрагивает 20 серверов, система за один запрос может опросить не больше 15; делегаций нет (ни одной, ни пятнадцати). В отказе — предложение сузить запрос (назвать кафе или группу до 15) `[предл.]`.
- C: не отказ — `delegate` cafe-03 или cafe-07 (первый из двух запусков; второй — в следующем шаге, вне этого теста).
- Ошибки: в A/B — 15 делегаций и ответ «по первым 15»; отказ без объяснения; в C — отказ «по одному серверу за раз» (правило снято [UC-26]).

## Эталон

- A, B: `reject`; `delegate` не вызван.
- C: `delegate`, `delegate_to` ∈ {cafe-03, cafe-07} (первый из двух).

## Метрики

- Rule-based: `orch-not-in-scope` — тулза `reject` (класс `not_in_scope`) там, где ожидается; делегаций нет. В варианте C — `orch-no-delegation` (ожидается `delegated`).
- Доп. рубрика `judge-orch-refusal` `[предл.]` — вне долей v0.2 (текст отказа judge-метрикой не покрыт): нет инструкций и команд для изменений [UC-06]; нет имитации выполнения; имена ручек не названы [UC-22], [UC-25]; причина отказа понятна.

## Основания

[UC-26] — правило «один запрос — один сервер» снято; [AR-32] — `delegate` ≤ 15 на сессию; [Q54] — «запрос по слишком многим серверам: есть ли предел и отказ» — не обсуждалось в документах; порог 15 — транскрипт плана 2026-10-27.
