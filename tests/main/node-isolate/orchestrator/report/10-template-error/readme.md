# orchestrator/report/10 — шаблон упал: пропал доступ к журналу

## Сценарий

Пункт плана «Infra local → Template», шаг отчёта. Агент web-01 сообщил, что с полуночи нет данных об ошибках сайта: система потеряла доступ к журналу ошибок веб-сервера после его ротации. Отчёт передаёт факт и не делает вида, что ошибок не было.

## Контекст оркестратора

Документ контекста стенда M (ООО «Тестовая компания», оптовая торговля: офис, склад, сайт). Четыре сервера добавлены через форму 2026-10-08; у оркестратора по каждому — ip, теги и краткое описание из подтверждённого JSON, полного описания нет [UC-04]. Название сервера в документе контекста — `[предл.]`; в тестах это имя хоста.

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| web-01 | 10.0.1.11 | host, web/nginx, db/mysql, unsupported:provider-hv | Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С |
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Плюс инструкции оркестратора и история текущей сессии [K §2.3]. Момент запроса — вторник 2026-10-27, 10:00 (+03:00), если в тесте не сказано иное.

## Вход

Запрос пользователя: «сколько ошибок было у сайта за ночь?».

Ответ агента web-01: данные за ночь не получены — «источник не обновляется с 2026-10-27 00:00». Комментарий шаблона агенту: «сборщику отказано в доступе к /var/log/nginx/error.log (Permission denied): после ротации журнала в 00:00 файл создан с правами 0640 root:adm; записи в источнике есть по 2026-10-26 23:59». Формулировка агента: «С 00:00 27.10 нет доступа к журналу ошибок nginx — после ротации изменились права на файл; данные есть по 23:59 26.10».

## Ожидаемое поведение

- Сказано: посчитать ошибки за ночь нельзя — с полуночи система не может читать журнал ошибок веб-сервера (после ротации журнала изменились права на файл); данные есть до 23:59 26 октября; допустимо предложить показать ошибки за вечер.
- Не «ошибок не было», не «0 ошибок», не «сайт не работает».
- Без команд исправления прав [UC-06]; без слов «сборщик», «источник», «ручка».
- Ошибки: число ошибок за ночь; «nginx упал»; инструкция `chmod`, `usermod -aG adm`.

## Эталон

- Факты: доступ к журналу ошибок потерян с 2026-10-27 00:00 после ротации; данные есть по 2026-10-26 23:59.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; внутренние имена (источники, ручки, шаблоны, команды, классы) не упомянуты.
- Класс итогового сообщения оркестратора после ответа агента в метриках v0.2 не определён (`answered` — «ответ без делегации»), поэтому rule-based по классу на этом шаге не считается (README, открытые пункты).

Ошибки шаблона с комментарием [AR-16]; [UC-06], [UC-08].
