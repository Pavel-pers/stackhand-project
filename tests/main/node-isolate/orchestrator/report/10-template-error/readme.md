## Сценарий

Пункт скриншота плана «Infra local → Template» (код MR-6, вариант «источник недоступен»): агент web-01 сообщил, что с полуночи нет данных об ошибках сайта — логгер потерял доступ к журналу после ротации. Ответ передаёт факт и не делает вида, что ошибок не было; от пользователя ничего не нужно — это ответ, не вопрос.

## Вход

Транскрипт сессии (оркестратор перезапущен с ним [AR-28]):

- Пользователь: «сколько ошибок было у сайта за ночь?»
- Оркестратор: `delegate(web-01, «Сколько ошибок было у сайта за ночь»)`
- Агент: `answer` (`executed`; ручка `web.errors` вернула `source-unavailable`): «с 00:00 27.10 нет доступа к журналу ошибок веб-сервера — после ротации изменились права на файл; данные есть по 23:59 26.10; за ночь посчитать нельзя».

## Ожидаемое поведение

- `answer-user`: посчитать ошибки за ночь нельзя — с полуночи система не может читать журнал ошибок веб-сервера (после ротации журнала изменились права на файл); данные есть до 23:59 26 октября; допустимо предложить показать ошибки за вечер или заглянуть в журнал обращений (второй `delegate`).
- Не «ошибок не было», не «0 ошибок», не «сайт не работает».
- Без команд исправления прав [UC-06]; без слов «логгер», «ручка».
- Ошибки: число ошибок за ночь; «nginx упал»; инструкция `chmod`, `usermod -aG adm`.

## Эталон

- Факты: доступ к журналу ошибок потерян с 2026-10-27 00:00 после ротации; данные есть по 2026-10-26 23:59.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- Класс итогового сообщения после ответа агента — `answered` (тулза `answer-user`; в M «ответ без делегации», по AR-31 класс = вызванная тулза — README, открытые пункты). Критерий «все числа агента перенесены точно» читается так `[предл.]`: обязательные числа из «Эталона» есть в ответе, любое другое число из ответа агента, если оно попало в ответ, совпадает.
