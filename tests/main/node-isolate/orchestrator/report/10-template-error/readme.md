# orchestrator/report/10 — ручка упала: пропал доступ к журналу

Сценарий плана: **MR-6b** — Доступ к источнику данных потерялся (ручка не читает журнал) — путь ошибки «пропал доступ к логу» из метрик [M], в транскрипте не назван; ответ пользователю через оркестратора. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Код MR-6b (на скриншоте плана — «Infra local → Template»; путь ошибки «пропал доступ к логу» [M]): ручка не смогла прочитать файл логгера ошибок веб-сервера на web-01, агент сообщил, что данных за ночь нет. Ответ передаёт факт и не делает вида, что ошибок не было; причину сверх факта «нет доступа к файлу» не утверждает; от пользователя ничего не нужно — это ответ, не вопрос.

## Вход

Транскрипт сессии (оркестратор перезапущен с ним [AR-28]):

- Пользователь: «сколько ошибок было у сайта за ночь?»
- Оркестратор: `delegate(web-01, «Сколько ошибок было у сайта за ночь»)`
- Агент: `escalate(error)` (ручка `web.errors` вернула `source-unavailable`): «нет доступа к собранным данным об ошибках веб-сервера на web-01 — файл логгера не читается (Permission denied); за ночь данных нет».

## Ожидаемое поведение

- `answer-user`: посчитать ошибки за ночь нельзя — у системы нет доступа к собранным данным об ошибках сайта на web-01 (файл с ними не читается); возможная причина — изменились права на сервере, как предположение; допустимо предложить посмотреть журнал обращений к сайту (второй `delegate`).
- Не «ошибок не было», не «0 ошибок», не «сайт не работает».
- Без команд исправления прав [UC-06]; без слов «логгер», «ручка».
- Ошибки: число ошибок за ночь; «nginx упал»; причина как установленный факт; инструкция `chmod`, `usermod -aG adm`.

## Эталон

- Факты: данных об ошибках сайта за ночь нет — нет доступа к файлу с ними на web-01.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- Класс итогового сообщения после ответа агента — `answered` (тулза `answer-user`; в M «ответ без делегации», по AR-31 класс = вызванная тулза — README, открытые пункты).
