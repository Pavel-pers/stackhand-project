# orchestrator/report/16 — ответ по двум серверам из двух запусков

Сценарий плана: **X-MULTI** — Несколько серверов в одном запросе — последовательные запуски агентов [UC-26], [AR-27]. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Вне плана (X-MULTI): второй шаг запроса по двум серверам — после ответа первого агента оркестратор запускает второго, а после его ответа собирает один ответ пользователю [UC-26], [AR-27]. Тест на двух тактах транскрипта: вариант A — после первого ответа (ожидается второй `delegate`); вариант B — после обоих (ожидается `answer-user` со сравнением).

- Пользователь: «сравни свободное место на srv-1c и на сервере сайта»
- Оркестратор: `delegate(srv-1c, «Свободное место по томам и прогноз»)`
- Агент srv-1c: Ответ агента srv-1c (терминальная `answer`, класс `executed`; вызвана `host.volumes_usage`, данные с 2026-10-08 по 2026-10-27 09:59, 19 суток):

Вариант B — то же плюс:

- Оркестратор: `delegate(web-01, «Свободное место по томам и прогноз»)`
- Агент web-01: Ответ агента web-01 (`answer`, `executed`; вызвана `host.volumes_usage`, 19 суток): том / — 40G, занято 17G, свободно 23G (43 %), рост 0,1 ГБ/сут, заполнение не раньше чем через 200 дней. Источник — накопленные данные о томах.

## Ожидаемое поведение

- A: `delegate(web-01, …)` — второй запуск, без вопроса пользователю и без ответа по одному серверу.
- B: `answer-user` — сравнение: на srv-1c самый заполненный том /var/lib/postgresql — 81 %, свободно 90G, место закончится около 2026-12-30; на web-01 диск заполнен на 43 %, свободно 23G, запас больше 200 дней; вывод — внимания требует srv-1c. Период и источник названы.
- Ошибки: в A — `answer-user` только по srv-1c или `reject` «по одному серверу»; в B — числа перепутаны между серверами; выдуманный третий сервер; третий `delegate` без нужды.

## Эталон

- A: `delegate`, `delegate_to` web-01.
- B: `answer-user`; числа: srv-1c 81 %, 90G, ≈ 2026-12-30; web-01 43 %, 23G.

## Метрики

- Rule-based: A — `orch-agent-choice`; B — `orch-no-delegation` (`answered`).
- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- Класс итогового сообщения после ответа агента — `answered` (тулза `answer-user`; в M «ответ без делегации», по AR-31 класс = вызванная тулза — README, открытые пункты). Критерий «все числа агента перенесены точно» читается так `[предл.]`: обязательные числа из «Эталона» есть в ответе, любое другое число из ответа агента, если оно попало в ответ, совпадает.
