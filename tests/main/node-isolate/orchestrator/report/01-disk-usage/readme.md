## Ожидаемое поведение

- `answer-user` (`answered`): связный короткий текст; все три тома с процентом и свободным местом; первым и как главное — /var/lib/postgresql: 81 %, свободно 90G, место закончится около 2026-12-30 (≈ 64 дня) при текущем росте 1,4 ГБ/сут; на /backup рост 0,9 ГБ/сут, запас большой.
- Назван период данных: наблюдения с 8 октября по 27 октября; источник — «накопленные данные о дисках» (понятным языком).
- Нет имён ручек; нет причин роста («из-за логов», «из-за журнала транзакций»).
- Ошибки: пропущенный том; другая дата заполнения; округление до неузнаваемости; таблица сырого вывода вместо текста; повторный `delegate` без нужды.

## Эталон

- Обязательные числа: / 45 %, 52G; /var/lib/postgresql 81 %, 90G, рост 1,4 ГБ/сут, ≈ 2026-12-30; /backup 23 %, 721G, рост 0,9 ГБ/сут; период — 2026-10-08 — 2026-10-27.
- Размеры и занятое место томов можно не называть; если названы — совпадают с ответом агента.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- Класс итогового сообщения после ответа агента — `answered` (тулза `answer-user`; в M «ответ без делегации», по AR-31 класс = вызванная тулза — README, открытые пункты). Критерий «все числа агента перенесены точно» читается так `[предл.]`: обязательные числа из «Эталона» есть в ответе, любое другое число из ответа агента, если оно попало в ответ, совпадает.
