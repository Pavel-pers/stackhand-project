## Вход

Транскрипт сессии (оркестратор перезапущен с ним [AR-28]):

- Пользователь: «сколько ошибок было у сайта за ночь?»
- Оркестратор: `delegate(web-01, «Сколько ошибок было у сайта за ночь»)`
- Агент: Ответ агента web-01 (`answer`, `executed`; вызваны `web.errors(window = ночь)` — `source-unavailable` с 00:00 — и `web.access_excerpt(filter = " 5", window = ночь, max_lines = 200)`): по журналу обращений за ночь ошибок с кодами 5xx — не меньше 200 (выборка ограничена 200 строками из 1 437): 502 на страницах каталога (/catalog/*) — большинство, с 22:03 до 08:57 почти непрерывно; 504 — 31 на импорте прайса (/api/price/import, /buh/hs/price); 500 — 5 на /cart/ около 02:11. Журнал ошибок веб-сервера с 00:00 недоступен — после ротации нет прав на файл, поэтому точное число и причины 502 по нему не видны. Источники — журнал обращений к сайту (выборка), журнал ошибок веб-сервера (до 00:00).

## Ожидаемое поведение

- Ответ: за ночь сайт отдавал ошибки почти непрерывно с 22:03 до 08:57 — в основном «502» на страницах каталога (большинство из выборки в 200 строк; всего строк с ошибками 1 437), 31 «504» на импорте прайса, 5 «500» в корзине около 02:11; точное число не названо как точное — выборка ограничена; журнал ошибок веб-сервера с полуночи недоступен (права после ротации), поэтому причины 502 по нему не видны.
- Главное выделено и прокомментировано (каталог недоступен пользователям; импорт прайса не проходит); источники названы понятным языком (журнал обращений к сайту, журнал ошибок веб-сервера).
- Без строк лога, IP-адресов и user-agent'ов в ответе; без команд.
- Ошибки: вставка сырых строк; «ошибок не было»; точное число «1 437 ошибок» как установленное (это строки с фильтром « 5», агент назвал их оценкой); инструкция `chmod`.

## Эталон

- Обязательные факты: 502 на /catalog — большинство; 504 — 31 на импорте прайса; 500 — 5; первая 22:03, последняя 08:57; журнал ошибок недоступен с 00:00.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- LLM-judge: `judge-readability` `[предл.]` (пункт плана MR-1d) — ответ читается без подготовки: не сырой вывод тулз (таблица на сотни строк, JSON, список записей), главное выделено и прокомментировано — что это значит и на что обратить внимание; длинные перечни свёрнуты в итоги с примерами; объём соразмерен вопросу.
- Класс итогового сообщения после ответа агента — `answered` (тулза `answer-user`; в M «ответ без делегации», по AR-31 класс = вызванная тулза — README, открытые пункты). Критерий «все числа агента перенесены точно» читается так `[предл.]`: обязательные числа из «Эталона» есть в ответе, любое другое число из ответа агента, если оно попало в ответ, совпадает.
