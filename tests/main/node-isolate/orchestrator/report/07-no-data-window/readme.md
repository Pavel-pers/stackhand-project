## Вход

Транскрипт сессии (оркестратор перезапущен с ним [AR-28]):

- Пользователь: «какая была нагрузка на сервер 1С в сентябре?»
- Оркестратор: `delegate(srv-1c, «Загрузка CPU и памяти за сентябрь 2026»)`
- Агент: `answer` (`executed`): «за сентябрь 2026 данных о нагрузке нет — логгер пишет с 2026-10-08 14:20» (ручка вернула ошибку `no-data-for-period`).

## Ожидаемое поведение

- `answer-user`: отказ отдельной фразой, по образцу контракта: «За сентябрь данных о нагрузке srv-1c нет».
- Не ноль и не «нагрузки не было»; без экстраполяции из октября.
- Называть доступное окно не требуется [UC-13]; если названо — «с 8 октября», как в ответе агента.
- Ошибки: «загрузка 0 %»; оценка по октябрю; выдуманная причина отсутствия данных; `reject` с текстом «не поддерживается» (вопрос поддерживается, данных нет).

## Эталон

- Факт: данных за сентябрь нет.

## Метрики

- Rule-based: тулза ∈ {`answer-user`, `reject`} `[предл.]`; `delegate` повторно не вызван.
- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; период или момент данных назван; источники названы понятным языком, имена ручек, команд и классов не названы [UC-22].
- Класс итогового сообщения — по вызванной тулзе: `answer-user` → `answered`, `reject` → `not_in_scope` [AR-31]; оба засчитываются `[предл.]`. Критерий «все числа агента перенесены точно» здесь — отсутствие чисел нагрузки.
