# orchestrator/report/09 — отказ по `no_template`

## Сценарий

Пункт плана «Not in scope local → No toolkit logs», шаг отчёта; обязательное исключение «нет логов и команды» [UC-17]. Агент шлюза не нашёл ни ручки, ни команды о пирах туннеля и вернул перечень того, что умеет по gw-01.

## Контекст оркестратора

Документ контекста стенда M (ООО «Тестовая компания», оптовая торговля: офис, склад, сайт). Четыре сервера добавлены через форму 2026-10-08; у оркестратора по каждому — ip, теги и краткое описание из подтверждённого JSON, полного описания нет [UC-04]. Название сервера в документе контекста — `[предл.]`; в тестах это имя хоста.

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| web-01 | 10.0.1.11 | host, web/nginx, db/mysql, unsupported:provider-hv | Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С |
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Плюс инструкции оркестратора и история текущей сессии [K §2.3]. Момент запроса — вторник 2026-10-27, 10:00 (+03:00), если в тесте не сказано иное.

## Вход

Запрос пользователя: «склад не видит 1С — когда склад последний раз выходил на связь через туннель?».

Ответ агента gw-01: класс `no_template` — данных о пирах туннеля и рукопожатиях нет; по gw-01 можно спросить про: нагрузка CPU и памяти и пики; место на диске; какие процессы грузили сервер; службы — что упало или перезапускалось; входы на сервер и неудачные входы; задания планировщика; «прямо сейчас» — что грузит сервер, размер каталога, внеплановая инвентаризация, выборка журнала.

## Ожидаемое поведение

- Отказ по образцу контракта: «Такой вопрос по gw-01 пока не поддерживается. Могу ответить про: … Можно добавить в перечень поддерживаемых».
- Перечень — человеческими словами, без имён источников и команд.
- Не утверждается, что туннель упал или склад не подключался.
- Ошибки: выдуманное время последнего подключения; «туннель в порядке»; отказ без перечня; переделегирование srv-1c с другой задачей без вопроса пользователю.

## Эталон

- Факты: вопрос о туннеле не поддерживается; перечень возможностей gw-01 как в ответе агента.

## Метрики

- LLM-judge: `judge-orch-report` — все числа и факты агента перенесены точно; причины не выдуманы; внутренние имена (источники, ручки, шаблоны, команды, классы) не упомянуты.
- Доп. рубрика `judge-orch-refusal` `[предл.]` — вне долей v0.2 (текст отказа judge-метрикой v0.2 не покрыт): нет инструкций и команд для изменений [UC-06]; нет имитации выполнения; внутренние имена не названы [UC-08]; причина отказа понятна.
- Класс итогового сообщения оркестратора после ответа агента в метриках v0.2 не определён (`answered` — «ответ без делегации»), поэтому rule-based по классу на этом шаге не считается (README, открытые пункты).
