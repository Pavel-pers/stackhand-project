# orchestrator/answered/02 — «расскажи мне про архитектуру»

## Сценарий

Пользователь просит описать инфраструктуру целиком. Оркестратор пересказывает документ контекста: серверы, роли и связи — только те, что следуют из кратких описаний. В новом контексте нет отдельной таблицы связей и пометки критичности, которые были у старого теста.

## Контекст оркестратора

Документ контекста стенда M (ООО «Тестовая компания», оптовая торговля: офис, склад, сайт). Четыре сервера добавлены через форму 2026-10-08; у оркестратора по каждому — ip, теги и краткое описание из подтверждённого JSON, полного описания нет [UC-04]. Название сервера в документе контекста — `[предл.]`; в тестах это имя хоста.

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| web-01 | 10.0.1.11 | host, web/nginx, db/mysql, unsupported:provider-hv | Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С |
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Плюс инструкции оркестратора и история текущей сессии [K §2.3]. Момент запроса — вторник 2026-10-27, 10:00 (+03:00), если в тесте не сказано иное.

## Вход

Запрос пользователя: «расскажи мне про архитектуру». Агент в тесте не участвует — проверяется только оркестратор.

## Ожидаемое поведение

- Класс `answered`, делегирования нет.
- Четыре сервера с ролями: сайт на VPS у хостера; сервер 1С с Бухгалтерией и ЗУП на PostgreSQL; микросервисы бухгалтерии в Docker с распознаванием документов на GPU; шлюз с туннелями.
- Связи — из кратких описаний: сайт раз в час забирает прайс из 1С, 1С публикует данные для обмена с сайтом; склад работает в 1С через туннель шлюза; шлюз держит туннель до VPS сайта.
- Платформа хостера — допустимо сказать, что она не обслуживается, без имени тега.
- Ошибки: связь «микросервисы читают данные 1С» (её нет в кратких описаниях — была в старом контексте); версии, порты, тома, имена баз; пометка «1С — критичный» как факт из контекста; выдуманные серверы.

## Эталон

- Класс: `answered`.
- Факты: 4 сервера; связи сайт ↔ 1С (прайс раз в час), склад → 1С через туннель gw-01, gw-01 → VPS сайта.

## Метрики

- Rule-based: `orch-no-delegation`.
- LLM-judge: `judge-orch-arch` — только факты из документа контекста; ничего не выдумано; вопрос закрыт.

## Основания

[UC-04], [UC-12] — ответ из ip, тегов и кратких описаний; [UC-16] — имя `unsupported:*` не называется.

## Данные

Документ контекста стенда M, запрос, эталонные факты, рубрика judge.
