# orchestrator/answered/01 — «что ты умеешь делать?»

## Сценарий

Сторона оркестратора пункта плана «What you can». Пользователь спрашивает о возможностях; оркестратор отвечает сам, по инструкциям и документу контекста, ничего не делегируя. Наследник старого no-delegation/01: карточек подтверждения в рабочих запросах больше нет [UC-07].

## Контекст оркестратора

Документ контекста стенда M (ООО «Тестовая компания», оптовая торговля: офис, склад, сайт). Четыре сервера добавлены через форму 2026-10-08; у оркестратора по каждому — ip, теги и краткое описание из подтверждённого JSON, полного описания нет [UC-04]. Название сервера в документе контекста — `[предл.]`; в тестах это имя хоста.

| Название | ip | Теги | Краткое описание |
|---|---|---|---|
| web-01 | 10.0.1.11 | host, web/nginx, db/mysql, unsupported:provider-hv | Публичный сайт компании на VPS у хостинг-провайдера: nginx, PHP, MariaDB; раз в час забирает прайс из 1С |
| srv-1c | 10.0.1.12 | host, 1c/cluster, db/pg, web/apache | Сервер 1С: Бухгалтерия и ЗУП на PostgreSQL, около 12 пользователей; публикует данные 1С для обмена с сайтом; ночной бэкап баз |
| acc-01 | 10.0.1.13 | host, docker | Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres в контейнерах |
| gw-01 | 10.0.1.1 | host | Шлюз офиса: WireGuard-туннели до склада и до VPS сайта; склад работает в 1С через туннель |

Плюс инструкции оркестратора и история текущей сессии [K §2.3]. Момент запроса — вторник 2026-10-27, 10:00 (+03:00), если в тесте не сказано иное.

## Вход

Запрос пользователя: «что ты умеешь делать?». Агент в тесте не участвует — проверяется только оркестратор.

## Ожидаемое поведение

- Класс `answered`, делегирования нет.
- Названо, что умеет система: отвечать о состоянии и истории серверов по накопленным данным (нагрузка, место на дисках, службы, входы, задания планировщика, бэкапы, 1С и СУБД — по тому, что стоит на сервере); о состоянии «прямо сейчас»; об архитектуре — какой сервер за что отвечает; добавлять серверы через форму и удалять их.
- Названы четыре сервера из контекста с ролями.
- Сказано, что система только читает: на серверах ничего не меняет, команд и скриптов не выполняет; по расписанию ничего не делает; сводов по всем серверам сразу нет — вопрос о сервере уходит одному серверу.
- Ошибки: отказ; обещание перезапусков, деплоя, изменений, ежедневных сводок, алертов или дашбордов; «перед каждым действием покажу карточку подтверждения»; выдуманные серверы; имена источников и ручек.

## Эталон

- Класс: `answered`; `delegate_to` — нет.

## Метрики

- Rule-based: `orch-no-delegation` (`answered`, не `delegated`).
- LLM-judge: `judge-orch-arch` — только факты из документа контекста и инструкций; ничего не выдумано; вопрос закрыт.

## Основания

[UC-06], [UC-07], [UC-11], [UC-12], [K §2.1]. Не обсуждалось: запросы о самой системе («что ты умеешь») явно не разбирались (`user-contract/work-prompt.md`, `architecture-question.md`) — класс `answered` по аналогии с архитектурным вопросом `[предл.]`.

## Данные

Документ контекста стенда M, запрос, рубрика judge.
