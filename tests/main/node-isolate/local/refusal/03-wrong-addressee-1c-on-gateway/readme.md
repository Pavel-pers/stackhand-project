# local/refusal/03 — не по адресу: сеансы 1С на шлюзе

Сценарий плана: **MR-5c** — Неверно выбранный сервер — node-isolate: A) оркестратор получил отказ и перевыбирает; B) агенту дан запрос мимо его скоупа. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана MR-5c, компонента B: оркестратор дал запрос однозначно мимо скоупа агента. `wrong_addressee` — тема не покрыта ни тегами, ни описанием сервера (пример метрик: «просят про 1С, а в тегах только backup и в описании про 1С ничего»). У gw-01 тег только host; в описании 1С упомянута только как то, с чем работает склад через туннель.

Каталог — предложение тестов до [Q08]: имена и параметры условные, при появлении манифестов заменяются ими; эталон `local-handle-choice` сравнивает имя ручки, `local-handle-args` — обязательные параметры в допуске (допуски — [Q18]). Данные логгеров — с 2026-10-08 14:20 (установка); ретенция: сырые метрики 7 дней, часовые агрегаты 13 месяцев, события 30 дней [T §2.5]. Все ручки только читают, подтверждений нет [UC-06], [UC-07]. Лимит — 20 вызовов ручек A и B на запуск, терминальная `answer`/`escalate` не считается [AR-32]; агент видит остаток лимита; вызов сверх лимита отклоняется с комментарием, 10 таких подряд — система закрывает сессию [AR-43].

Тип A — сводки по имеющимся логам:

| Ручка | Параметры | Что возвращает |
|---|---|---|
| `host.load_peaks` | resource (cpu / mem / gpu / disk_io), threshold_pct, window | отрезки времени с нагрузкой выше порога, средняя нагрузка, нагрузка по остальным ресурсам, самые потребляющие процессы |
| `host.load_profile` | resource, window, step (hour / day) | нагрузка по часам суток или по дням: средняя, p95, максимум; самые спокойные и самые нагруженные окна |
| `host.volumes_usage` | window | по томам: размер, занято, свободно, %, рост в сутки, прогноз заполнения |
| `host.dir_sizes` | — | крупнейшие каталоги по последнему снимку |
| `host.process_top` | resource, window | процессы, которые больше всего грузили сервер за окно |
| `host.service_events` | window | службы: падения, перезапуски, смены состояния за окно |
| `host.auth_events` | window, result (all / success / failed) | входы на сервер: успешные с пользователем, адресом и способом; неудачные — счётчиком по адресам и именам |
| `host.sched_jobs` | window, job (необязательно) | задания планировщика: расписание, запуски за окно, коды завершения, длительность, хвост вывода |
| `host.backup_files` | path (необязательно; по умолчанию — пути бэкапов из записи о сервере) | свежесть файлов бэкапа: последние файлы, время и размер |

Тип B — one-shot на момент «сейчас»:

| Ручка | Параметры | Что возвращает |
|---|---|---|
| `host.now_resources` | — | загрузка CPU и памяти и топ процессов на момент вызова |
| `host.now_inventory` | section (all / hardware / os / packages) | инвентаризация на момент вызова: ОС, CPU, память, GPU, диски, пакеты |
| `host.path_size` | path | размер каталога и крупнейшие файлы в нём на момент вызова |
| `host.log_excerpt` | path, filter, window, max_lines | выборка строк журнала по фильтру и периоду — сырой текст, не больше max_lines строк |

Терминальная ручка: `answer(text)` — ответ оркестратору; `escalate(kind: no_template | wrong_addressee | error | ambiguous, text)` — эскалация [AR-31]; виды `error` и `ambiguous` (под запрос подходят несколько ручек, без ответа пользователя не выбрать) — предложение тестов, схема — [Q37].

Ошибки ручек — enum с описанием причин и следующих действий [AR-25] (перечень — предложение тестов до [Q20]):

| Код | Когда | Что ручка подсказывает агенту |
|---|---|---|
| `ssh-refused` | подключение к серверу не удалось после 2 попыток с паузой 5 с внутри ручки [AR-42] (ключ отклонён, порт закрыт, таймаут) — в описании ошибки текст SSH и число попыток | сообщить пользователю через эскалацию оркестратору |
| `no-data-for-period` | в логах нет записей за запрошенное окно — в описании самая ранняя запись | сказать, что данных за окно нет; не подменять окно |
| `invalid-param` | значение параметра не подходит — в описании параметр, допустимые значения, примеры | повторить вызов с исправленным параметром |
| `source-unavailable` `[предл.]` | ручка не может прочитать файл логгера на хосте (нет доступа по SSH к файлу, файл удалён) — путь ошибки «пропал доступ к логу» [M] | сообщить оркестратору, что данных за окно нет; не выдавать ноль за результат |
| `timeout` `[предл.]` | ручка не уложилась в отведённое время (по умолчанию 30 с [AR-42]) | повторить с меньшим окном или сообщить оркестратору |

Предупреждение — не ошибка: если логгер перестал писать (например, не может читать журнал службы после ротации), ручка возвращает сводку по последнюю запись и предупреждение «источник не обновлялся с …» вместе с результатом (design doc 4.1, 5.4).

Ручек о пирах и рукопожатиях WireGuard нет: тулкита для WireGuard нет [T §5], [Q29]; `host.log_excerpt` рукопожатий не содержит — WireGuard не пишет их в системный журнал.

Момент получения запроса — 2026-10-27 10:00 (+03:00).

## Вход

Запрос от оркестратора (prompt тулзы `delegate`): «Кто сейчас подключён к базам 1С (активные сеансы)». Исходный запрос пользователя: «склад жалуется, что не может зайти в 1С — кто сейчас сидит в базе?».

## Ожидаемое поведение

- `escalate(wrong_addressee)`, ручки не вызваны.
- Причина: на gw-01 нет 1С — ни тега, ни признаков в описании (упоминание «склад работает в 1С через туннель» описывает роль шлюза, не 1С на нём).
- На другой сервер агент не указывает: чужих контекстов у него нет, адресата меняет оркестратор [AR-27].
- Ошибки: `no_template`; входы по SSH из `host.auth_events` как «кто подключён»; `answer` «сеансов нет».

## Эталон

- Эскалация: `wrong_addressee`.

## Метрики

- Rule-based: `local-wrong-addressee` — эскалация `wrong_addressee` там, где тема запроса не покрыта ни тегами, ни описанием сервера, и только там.
