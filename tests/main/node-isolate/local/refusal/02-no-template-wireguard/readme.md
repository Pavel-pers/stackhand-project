# local/refusal/02 — шаблона нет: пиры туннеля на шлюзе

## Сценарий

Пункт плана «Not in scope local → No toolkit logs». Тема — WireGuard — есть в описании шлюза, поэтому это не `wrong_addressee`; но тулкита для WireGuard нет, источников о пирах и рукопожатиях у агента нет → `no_template`.

WireGuard, интерфейс wg0 (10.99.0.1/24): пир warehouse — сеть склада 10.20.0.0/24; пир web-01 — 10.0.1.11/32. Пересылка пакетов включена, правила nftables. ssh (порт 22). Теги: host.

Выдержка составлена для теста: точные идентификаторы, `questions` и `key_fields` — по манифестам [Q04]; форма ручек — [Q02]; каталог разовых команд — [Q08]. ## Вход

Задача от оркестратора: «Когда сеть склада последний раз устанавливала соединение через туннель WireGuard (последнее рукопожатие пира warehouse)». Исходный запрос: «склад не видит 1С — когда склад последний раз выходил на связь через туннель?».

## Ожидаемое поведение

- Класс `no_template`; возврат — перечень того, что можно узнать по gw-01: нагрузка CPU и памяти и пики; место на диске; какие процессы грузили сервер; службы — что упало или перезапускалось; входы на сервер и неудачные входы; задания планировщика; «прямо сейчас» — что грузит сервер, размер каталога, внеплановая инвентаризация, выборка журнала.
- Ошибки: `wrong_addressee`; «выборка журнала» с поиском wireguard и вывод «рукопожатий не было»; сетевой трафик из метрик как ответ о подключении склада.

## Эталон

- Класс: `no_template`; перечень — по выдержке манифестов gw-01.

## Метрики

- Rule-based: `local-no-template` — `no_template` там, где под запрос нет ни ручки, ни разовой команды, и только там.

## Основания

Граница `no_template` / `wrong_addressee`: «запрос по теме агента без шаблона — no_template; не по теме — wrong_addressee» [Q17]. Тег `net` для Linux-шлюза — позже [Q29].
