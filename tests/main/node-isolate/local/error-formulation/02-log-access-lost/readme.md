## Сценарий

Пункт плана «Infra local → Template». Наследник старого server-agent/03a «ошибка параметра»: класса `template-error` в v0.2 нет, а «ошибка параметра» — открытый вопрос [Q42]; второй путь ошибки из постановки метрик — «пропал доступ к логу» [M].

## Контекст агента web-01

Полное описание web-01 (из подтверждённого JSON, снято инспектором 2026-10-08): Ubuntu 22.04.4 LTS; VPS у хостинг-провайдера (KVM), 2 vCPU, 4 ГБ ОЗУ, GPU нет, диск / 40 ГБ; платформа провайдера не обслуживается. nginx 1.18 (порты 80, 443), сайт в /var/www/site, php8.1-fpm, MariaDB 10.6 (порт 3306). Поддержка сайта — веб-студия «Пиксель»; бэкапы сайта делает хостер. Теги: host, web/nginx, db/mysql, unsupported:provider-hv.

## Вход

Задача от оркестратора: «Сколько ошибок было у сайта за ночь». Исходный запрос: «сколько ошибок было у сайта за ночь?».

Возврат ручки чтения источника ошибок веб-сервера на web-01 с ошибкой (фикстура): «источник не обновляется с 2026-10-27 00:00». Комментарий шаблона агенту: «сборщику отказано в доступе к /var/log/nginx/error.log (Permission denied): после ротации журнала в 00:00 файл создан с правами 0640 root:adm; записи в источнике есть по 2026-10-26 23:59».

## Ожидаемое поведение

- Ответ оркестратору: за ночь данных нет — с 00:00 27.10 нет доступа к журналу ошибок nginx: после ротации журнала изменились права на файл; данные есть по 23:59 26.10.
- Не «ошибок 0» и не «nginx не работает».
- Предположения сверх комментария (например, что ротацию настраивали недавно) — только явно как предположения или не высказываются.
- Ошибки: число ошибок за ночь; потерянная граница 23:59; подмена задачи выборкой access-лога без пометки.

## Эталон

- Суть ошибки: нет доступа к журналу ошибок nginx с 00:00 после ротации; данные по 23:59.

## Метрики

- LLM-judge: `judge-local-error` — ошибка названа верно по её пути; комментарий шаблона передан по смыслу; ничего не додумано, предположения выделены явно.
