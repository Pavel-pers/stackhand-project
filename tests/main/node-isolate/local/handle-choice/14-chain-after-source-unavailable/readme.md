# local/handle-choice/14 — цепочка: после ошибки источника агент ищет другой путь

Сценарий плана: **MR-1d** — Читаемость ответа пользователю — не сырые данные тулз, а показательные с комментариями; данные разрозненные, неструктурируемые, большого объёма. Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

Пункт плана MR-1d (неструктурируемые данные) и цикл [AR-26]: первая ручка `web.errors` вернула `source-unavailable` (журнал ошибок недоступен с полуночи). Агент не останавливается на «данных нет»: ошибки 5xx видны в журнале обращений — он берёт выборку `web.access_excerpt` с фильтром по кодам и отвечает с оговоркой о неполноте.

## Вход

Запрос от оркестратора (prompt тулзы `delegate`): «Сколько ошибок было у сайта за ночь». Исходный запрос пользователя: «сколько ошибок было у сайта за ночь?».

Первый вызов агента в тесте зафиксирован: `web.errors(window = ночь)` → `source-unavailable` `[предл.]` — «логгер ошибок веб-сервера не читает /var/log/nginx/error.log с 2026-10-27 00:00: после ротации журнала у учётки сбора нет прав на новый файл (Permission denied). Данные есть по 2026-10-26 23:59. Следующее действие: сообщить оркестратору, что данных нет с 00:00; не выдавать ноль за результат». Проверяется следующий шаг цикла. Состав запроса агенту постановкой не задан (`agent-loop-work-orchestration.md`, «Артефакты»); в тестах — prompt тулзы `delegate` плюс исходный запрос пользователя `[предл.]`.

## Ожидаемое поведение

- Следующая ручка — `web.access_excerpt(filter = коды 5xx, window = ночь, max_lines ≤ 200)` (или `host.log_excerpt(path = /var/log/nginx/access.log, …)`); затем `answer` с оговоркой: журнал ошибок недоступен с 00:00, оценка по журналу обращений.
- Допустимо вместо выборки сразу `answer` «данных по журналу ошибок с 00:00 нет» — засчитывается как слабый, но не ошибочный ответ `[предл.]` (эталон цепочки — [Q55]); ошибкой считается ноль и повтор упавшей ручки.
- Ошибки: `answer` «ошибок 0»; повторный `web.errors` с тем же окном; `web.probes` как замена (доступность — не ошибки); эскалация `error` (ошибка не `ssh-refused`, следующий шаг есть).

## Эталон

- Ручка второго шага: `web.access_excerpt` (засчитывается `host.log_excerpt` по access.log); параметры: filter — коды 5xx; window — ночь (допуск как в handle-choice/10); max_lines ≤ 200.
- Повторный `web.errors` с тем же окном — не засчитывается.

## Метрики

- Rule-based: `local-handle-choice` — имя ручки совпадает с эталоном; при цепочке из нескольких ручек за запуск — все обязательные ручки эталона вызваны, лишних (не из допустимых) нет `[предл.]` [Q55]; `local-handle-args` — обязательные параметры совпадают с эталоном точно или в допуске (допуски — предложение тестов до [Q18]).
