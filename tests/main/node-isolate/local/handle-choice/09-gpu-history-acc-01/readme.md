# local/handle-choice/09 — загрузка GPU за сутки на хосте с видеокартой

Сценарий плана: **MR-1a** — Получение информации — динамика параметра (монитор CPU за последний день). Вид теста: node-isolate. Соответствие e2e ↔ node-isolate — `SCENARIOS.md`.

## Сценарий

GPU-часть пункта MR-1a. На acc-01 есть видеокарта T4, и (допущение тестов) логгер нагрузки пишет её метрики. Агент выбирает сводку по накопленным метрикам GPU за окно.

## Контекст агента acc-01

Контекст агента acc-01 (запуск тулзой `delegate`, память новая [AR-27]).

`full-desc`: Микросервисы бухгалтерии в Docker: сверка с контрагентами и распознавание первичных документов на GPU; redis и postgres работают в контейнерах, отдельной СУБД на хосте нет. Ubuntu 22.04.4 LTS, 8 vCPU, 32 ГБ ОЗУ, GPU NVIDIA T4 16 ГБ. Осмотрен инспектором 2026-10-08.

`tags-full-desc` (`[предл.]` у агента — [Q56]):

- host — Ubuntu 22.04.4 LTS; 8 vCPU, 32 ГБ ОЗУ; GPU NVIDIA T4 16 ГБ (драйвер 535); диск / 200 ГБ. Службы: docker, containerd, ssh, cron.
- docker — Docker 24: контейнеры acc-api (порт 8080), acc-worker, acc-ocr (распознавание первичных документов, использует GPU), redis, postgres (данные в /srv/acc/pgdata). Отдельной СУБД на хосте нет.

Перечень ручек агента — то, что агент видит на шаге «просмотр ручек» [AR-26]: ручки типов A (сводка по имеющимся логам) и B (one-shot, на момент «сейчас») с параметрами [AR-24]. Каталог — предложение тестов до [Q08]: имена и параметры условные, при появлении манифестов заменяются ими; эталон `local-handle-choice` сравнивает имя ручки, `local-handle-args` — обязательные параметры в допуске (допуски — [Q18]). Данные логгеров — с 2026-10-08 14:20 (установка); ретенция: сырые метрики 7 дней, часовые агрегаты 13 месяцев, события 30 дней [T §2.5]. Все ручки только читают, подтверждений нет [UC-06], [UC-07]. Лимит — 20 вызовов ручек A и B на запуск, терминальная `answer`/`escalate` не считается [AR-32]; агент видит остаток лимита.

Тип A — сводки по имеющимся логам:

| Ручка | Параметры | Что возвращает |
|---|---|---|
| `host.load_peaks` | resource (cpu / mem / gpu / disk_io), threshold_pct, window | отрезки времени с нагрузкой выше порога, средняя нагрузка, нагрузка по остальным ресурсам, самые потребляющие процессы |
| `host.load_profile` | resource, window, step (hour / day) | нагрузка по часам суток или по дням: средняя, p95, максимум; самые спокойные и самые нагруженные окна |
| `host.volumes_usage` | window | по томам: размер, занято, свободно, %, рост в сутки, прогноз заполнения |
| `host.dir_sizes` | — | крупнейшие каталоги по последнему снимку |
| `host.process_top` | resource, window | процессы, которые больше всего грузили сервер за окно |
| `host.service_events` | window | службы: падения, перезапуски, смены состояния за окно |
| `host.auth_events` | window, result (all / success / failed) | входы на сервер: успешные с пользователем, адресом и способом; неудачные — счётчиком по адресам и именам |
| `host.sched_jobs` | window, job (необязательно) | задания планировщика: расписание, запуски за окно, коды завершения, длительность, хвост вывода |
| `host.backup_files` | path (необязательно; по умолчанию — пути бэкапов из записи о сервере) | свежесть файлов бэкапа: последние файлы, время и размер |
| `docker.container_events` | window | перезапуски и смены состояния контейнеров за окно |
| `docker.container_resources` | window | ресурсы по контейнерам за окно |

Тип B — one-shot на момент «сейчас»:

| Ручка | Параметры | Что возвращает |
|---|---|---|
| `host.now_resources` | — | загрузка CPU и памяти и топ процессов на момент вызова |
| `host.now_inventory` | section (all / hardware / os / packages) | инвентаризация на момент вызова: ОС, CPU, память, GPU, диски, пакеты |
| `host.path_size` | path | размер каталога и крупнейшие файлы в нём на момент вызова |
| `host.log_excerpt` | path, filter, window, max_lines | выборка строк журнала по фильтру и периоду — сырой текст, не больше max_lines строк |
| `docker.now_containers` | — | состояние контейнеров на момент вызова |
| `docker.log_excerpt` | container, filter, window, max_lines | выборка лога контейнера — сырой текст |

Терминальная ручка: `answer(text)` — ответ оркестратору; `escalate(kind: no_template | wrong_addressee | error | ambiguous, text)` — эскалация [AR-31]; виды `error` и `ambiguous` (под запрос подходят несколько ручек, без ответа пользователя не выбрать) — предложение тестов, схема — [Q37].

Ошибки ручек — enum с описанием причин и следующих действий [AR-25] (перечень — предложение тестов до [Q20]):

| Код | Когда | Что ручка подсказывает агенту |
|---|---|---|
| `ssh-refused` | подключение к серверу не удалось (ключ отклонён, порт закрыт, таймаут) — в описании ошибки текст SSH и число попыток | сообщить пользователю через эскалацию оркестратору |
| `no-data-for-period` | в логах нет записей за запрошенное окно — в описании самая ранняя запись | сказать, что данных за окно нет; не подменять окно |
| `invalid-param` | значение параметра не подходит — в описании параметр, допустимые значения, примеры | повторить вызов с исправленным параметром |
| `source-unavailable` `[предл.]` | логгер не может читать источник (нет доступа к файлу журнала после ротации, служба не отвечает) — в описании с какого момента | сообщить оркестратору, что данных нет с этого момента; не выдавать ноль за результат |
| `timeout` `[предл.]` | ручка не уложилась в отведённое время | повторить с меньшим окном или сообщить оркестратору |

На acc-01 логгер нагрузки пишет и метрики GPU (resource = gpu) — допущение тестов: состав метрик host в документах не расписан, GPU не упоминается (README, открытые пункты).

## Вход

Запрос от оркестратора (prompt тулзы `delegate`): «Загрузка GPU и память видеокарты за последние 24 часа». Исходный запрос пользователя: «как была загружена видеокарта на сервере распознавания документов за сутки?». Состав запроса агенту постановкой не задан (`agent-loop-work-orchestration.md`, «Артефакты»); в тестах — prompt тулзы `delegate` плюс исходный запрос пользователя `[предл.]`.

## Ожидаемое поведение

- Ручка `host.load_profile`, resource = gpu, window 24 ч, step = hour (или `host.load_peaks`, resource = gpu).
- Ошибки: `host.now_resources`; `host.now_inventory` (наличие GPU не спрашивали); `docker.container_resources` как единственная ручка; эскалация.

## Эталон

- Ручка: `host.load_profile` или `host.load_peaks`; параметры: resource = gpu; window [2026-10-26 10:00; 2026-10-27 10:00], допуск ±15 мин.

## Метрики

- Rule-based: `local-handle-choice` — имя ручки совпадает с эталоном; при цепочке из нескольких ручек за запуск — все обязательные ручки эталона вызваны, лишних (не из допустимых) нет `[предл.]` [Q55]; `local-handle-args` — обязательные параметры совпадают с эталоном точно или в допуске (допуски — предложение тестов до [Q18]).
