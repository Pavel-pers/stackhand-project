Тип A — сводки по имеющимся логам:

| Ручка | Параметры | Что возвращает |
|---|---|---|
| `host.load_peaks` | resource (cpu / mem / gpu / disk_io), threshold_pct, window | отрезки времени с нагрузкой выше порога, средняя нагрузка, нагрузка по остальным ресурсам, самые потребляющие процессы |
| `host.load_profile` | resource, window, step (hour / day) | нагрузка по часам суток или по дням: средняя, p95, максимум; самые спокойные и самые нагруженные окна |
| `host.volumes_usage` | window | по томам: размер, занято, свободно, %, рост в сутки, прогноз заполнения |
| `host.dir_sizes` | — | крупнейшие каталоги по последнему снимку |
| `host.process_top` | resource, window | процессы, которые больше всего грузили сервер за окно |
| `host.service_events` | window | службы: падения, перезапуски, смены состояния за окно |
| `host.auth_events` | window, result (all / success / failed) | входы на сервер: успешные с пользователем, адресом и способом; неудачные — счётчиком по адресам и именам |
| `host.sched_jobs` | window, job (необязательно) | задания планировщика: расписание, запуски за окно, коды завершения, длительность, хвост вывода |
| `host.backup_files` | path (необязательно; по умолчанию — пути бэкапов из записи о сервере) | свежесть файлов бэкапа: последние файлы, время и размер |
| `1c.sessions_history` | window | число сеансов по часам и пользователи за окно (по снимкам сеансов) |
| `1c.eventlog` | window, user (необязательно), event (необязательно) | сводка журнала регистрации: события по типам и пользователям, ошибки, пики |
| `db.blocking` | window | блокировки в СУБД: кто держал, кто ждал, сколько |
| `db.backups` | window | бэкапы СУБД по её журналам — что содержит для pg_dump из планировщика, не определено `[предл.]` |
| `web.errors` | window, status (необязательно) | ошибки веб-сервера за окно: число по кодам, самые частые URL, первые и последние |
| `web.probes` | window | доступность сайта по синтетическим проверкам: доля успешных, время ответа, провалы |

Терминальная ручка: `answer(text)` — ответ оркестратору; `escalate(kind: no_template | wrong_addressee | error | ambiguous, text)` — эскалация [AR-31]; виды `error` и `ambiguous` (под запрос подходят несколько ручек, без ответа пользователя не выбрать) — предложение тестов, схема — [Q37].

Ошибки ручек — enum с описанием причин и следующих действий [AR-25] (перечень — предложение тестов до [Q20]):

| Код | Когда | Что ручка подсказывает агенту |
|---|---|---|
| `ssh-refused` | подключение к серверу не удалось после 2 попыток с паузой 5 с внутри ручки [AR-42] (ключ отклонён, порт закрыт, таймаут) — в описании ошибки текст SSH и число попыток | сообщить пользователю через эскалацию оркестратору |
| `no-data-for-period` | в логах нет записей за запрошенное окно — в описании самая ранняя запись | сказать, что данных за окно нет; не подменять окно |
| `invalid-param` | значение параметра не подходит — в описании параметр, допустимые значения, примеры | повторить вызов с исправленным параметром |

Предупреждение — не ошибка: если логгер перестал писать (например, не может читать журнал службы после ротации), ручка возвращает сводку по последнюю запись и предупреждение «источник не обновлялся с …» вместе с результатом (design doc 4.1, 5.4).

## Вход

Вариант A — Запрос от оркестратора (prompt тулзы `delegate`): «Загрузка CPU за последние 24 часа: среднее, пики и когда они были». Исходный запрос пользователя: «какая была загрузка процессора на сервере 1С за последние сутки?».

Вариант B — Запрос от оркестратора (prompt тулзы `delegate`): «Загрузка CPU за последний час». Исходный запрос пользователя: «какая загрузка CPU на srv-1c за последний час?». Состав запроса агенту постановкой не задан (`agent-loop-work-orchestration.md`, «Артефакты»); в тестах — prompt тулзы `delegate` плюс исходный запрос пользователя `[предл.]`.

## Ожидаемое поведение

- Ручка `host.load_profile` (или `host.load_peaks` — пики выше порога); resource = cpu; A — window 2026-10-26 10:00 — 2026-10-27 10:00, step = hour; B — window 09:00–10:00.
- Ошибки: `host.now_resources` (момент, не период); `host.process_top` как единственная ручка; window «7 суток».

## Эталон

- Ручка: `host.load_profile` (засчитывается и `host.load_peaks` с threshold_pct 50–80 `[предл.]`).
- Параметры: resource = cpu; A — window [2026-10-26 10:00; 2026-10-27 10:00], допуск ±15 мин; B — window [09:00; 10:00], допуск ±5 мин.

## Метрики

- Rule-based: `local-handle-choice` — имя ручки совпадает с эталоном; при цепочке из нескольких ручек за запуск — все обязательные ручки эталона вызваны, лишних (не из допустимых) нет `[предл.]` [Q55]; `local-handle-args` — обязательные параметры совпадают с эталоном точно или в допуске (допуски — предложение тестов до [Q18]).
