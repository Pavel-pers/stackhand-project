# local/template-choice/01 — заполненность томов и прогноз

## Сценарий

Наследник старого server-agent/04. Агент должен выбрать чтение накопленных данных о томах, а не разовую команду: «диски с прогнозом» в tag-system — это чтение источника томов, разовый шаблон — только для произвольного пути [T §9.1 X04]. Карточки подтверждения больше нет [UC-07].

## Контекст агента srv-1c

Полное описание srv-1c (из подтверждённого JSON, снято инспектором 2026-10-08): Ubuntu 22.04.4 LTS; 8 vCPU, 32 ГБ ОЗУ, GPU нет. Тома: / (98 ГБ), /var/lib/postgresql (492 ГБ), /backup (980 ГБ). 1С:Предприятие 8.3.24.1548 в режиме кластера: агент 1540, менеджер 1541, рабочие процессы 1560–1591, RAS 1545; ИБ Buh (Бухгалтерия предприятия 3.0) и ZUP (ЗУП 3.1) в PostgreSQL. PostgreSQL 16 (postgresql@16-main, порт 5432). apache2 — публикация 1С для обмена с сайтом (порт 8080). Планировщик: `0 2 * * * /usr/local/bin/backup_1c.sh` — pg_dump баз в /backup/pg. Подрядчик по 1С — франчайзи «1С-Партнёр». Теги: host, 1c/cluster, db/pg, web/apache.

Выдержка из манифестов тулкитов установленных тегов — то, что агент получает в контекст: по источникам типовые вопросы и ключевые поля, по шаблонам — условия применимости [T §2.6, §4]. Выдержка составлена для теста: точные идентификаторы, `questions` и `key_fields` — по манифестам [Q04]; форма ручек — [Q02]; каталог разовых команд — [Q08]. ## Вход

Задача от оркестратора: «Проверь заполненность всех томов на srv-1c и когда закончится место». Исходный запрос пользователя: «посмотри заполненность дисков на сервере с 1С».

## Ожидаемое поведение

- Класс `executed`, ручка `host.volumes`.
- Аргументы: все тома (не перечислены вручную), окно для роста — весь доступный период наблюдений.
- Ошибки: разовая команда «размер пути» или «ресурсы сейчас»; выдуманные тома в аргументах; отказ; карточка подтверждения.

## Эталон

- Класс: `executed`; шаблон: ручка `host.volumes`.
- Аргументы: тома — все; окно — с начала данных (2026-10-08 14:20) по момент задачи; допуск — окно не короче 14 суток.

## Метрики

- Rule-based: `local-template-choice` — выбранный шаблон совпадает с эталоном (до решения [Q02] и [Q08] сравнивается источник для ручки и вид разовой команды); `local-template-args` — обязательные аргументы совпадают с эталоном в допуске (допуски — предложение тестов до [Q18]).
