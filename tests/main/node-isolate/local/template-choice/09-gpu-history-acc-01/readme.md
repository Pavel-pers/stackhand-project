# local/template-choice/09 — загрузка GPU за сутки на хосте с видеокартой

## Сценарий

GPU-часть пункта плана «Host info → CPU/GPU monitor last day, 1h — History». На acc-01 есть видеокарта T4, и (допущение тестов) `host.metrics` пишет её метрики. Агент выбирает чтение накопленных метрик GPU за окно.

## Контекст агента acc-01

Полное описание acc-01 (из подтверждённого JSON, снято инспектором 2026-10-08): Ubuntu 22.04.4 LTS; 8 vCPU, 32 ГБ ОЗУ, GPU NVIDIA T4 16 ГБ; диск / 200 ГБ. Docker 24: контейнеры acc-api (порт 8080), acc-worker, acc-ocr (распознавание первичных документов, использует GPU), redis, postgres (данные в /srv/acc/pgdata). Отдельной СУБД на хосте нет: postgres только в контейнере, тег db пользователь снял при добавлении. Теги: host, docker.

Выдержка из манифестов тулкитов установленных тегов — то, что агент получает в контекст: по источникам типовые вопросы и ключевые поля, по шаблонам — условия применимости [T §2.6, §4]. Выдержка составлена для теста: точные идентификаторы, `questions` и `key_fields` — по манифестам [Q04]; форма ручек — [Q02]; каталог разовых команд — [Q08]. Данные источников — с 2026-10-08 14:20 (установка тулкитов); ретенция: сырые метрики 7 дней, часовые агрегаты 13 месяцев, события 30 дней [T §2.5]. Все действия — только чтение, подтверждений нет [UC-06], [UC-07].

Ручки чтения логов (источники тулкитов):

| Источник | Вид | Типовые вопросы |
|---|---|---|
| host.metrics | metric, 60 с → часовые агрегаты | загрузка CPU и памяти, когда пики, хватает ли ресурсов |
| host.volumes | metric | заполненность томов, рост, когда закончится место |
| host.dirsizes | snapshot | какие каталоги занимают место |
| host.processes | metric, 60 с | какие процессы грузили сервер |
| host.services | snapshot | какие службы упали или перезапускались |
| host.auth | tail | кто заходил на сервер, неудачные входы |
| host.sched | snapshot | задания планировщика: расписание, последние запуски, коды завершения |
| host.backup_files | snapshot | свежесть файлов бэкапа по путям из паспорта |
| docker | snapshot, metric | состояние контейнеров, перезапуски, ресурсы контейнеров; идентификаторы — по манифесту docker |

Разовые команды чтения (R0):

| Команда | Что возвращает |
|---|---|
| X01 — внеплановая инвентаризация | ОС, CPU, память, GPU, диски, пакеты — на момент запуска |
| ресурсы сейчас | загрузка CPU и памяти, топ процессов — на момент запуска |
| размер пути | размер произвольного каталога |
| выборка журнала | сырой журнал по фильтру и периоду |
| L02 — сырой лог контейнера | лог контейнера с фильтром |

На acc-01 host.metrics пишет и метрики GPU (загрузка, память видеокарты) — допущение тестов: состав host.metrics в документах не расписан, GPU не упоминается (см. README, открытые пункты).

Момент получения задачи — 2026-10-27 10:00 (+03:00).

## Вход

Задача от оркестратора: «Загрузка GPU и память видеокарты на acc-01 за последние 24 часа». Исходный запрос: «как была загружена видеокарта на сервере распознавания документов за сутки?».

## Ожидаемое поведение

- Класс `executed`, ручка `host.metrics`, метрики GPU, окно 24 ч.
- Ошибки: «ресурсы сейчас»; X01 (наличие GPU не спрашивали); источники docker вместо метрик хоста; отказ.

## Эталон

- Шаблон: ручка `host.metrics`; аргументы: метрики gpu (загрузка, память), окно [2026-10-26 10:00; 2026-10-27 10:00], допуск ±15 мин.

## Метрики

- Rule-based: `local-template-choice` — выбранный шаблон совпадает с эталоном (до решения [Q02] и [Q08] сравнивается источник для ручки и вид разовой команды); `local-template-args` — обязательные аргументы совпадают с эталоном в допуске (допуски — предложение тестов до [Q18]).

## Основания

Тест считается, когда решат, что метрики GPU собираются (в документах GPU не упоминается — README, открытые пункты). До решения — `статус: ждёт решения`.
